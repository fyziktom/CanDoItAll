## Execution rules

For each selection record direct production builds, owning test project/solution, configuration,
exact filter, list-tests command, expected/actual discovery and runtime expansion, result counters,
source/binary fingerprints and original private TRX/log path. No-build requires current matching
binaries. Zero cases, gated-off external methods and source-only stub successes are not product proof.
Read current `docs/testing.md` for the actual commands; this handoff does not freeze SDK/tool syntax.

Existing owners include `ProviderRequestHistoryPanelTests`, `ProviderHistorySearchStateTests`,
`ProviderHistorySeamTests`, native History query/cursor/access/content source families,
`TooltipLifecycleBehaviorTests` and current Tooltip component consumers. Use actual PP2 final/native
History fixtures for multi-instance paths. Do not guess discovery counts from the number of methods.

Test before blur/Enter and real async event completion. Use dispatcher-contained Find+ClickAsync,
proper bUnit disposal and actual controller acquisition markers. A heading or disabled button is not
proof that a target loaded or operation completed. Capture deliberate failure first for S0.

Use controlled completion sources for late success/failure/cancel, A→B→A and close/reopen cases.
Do not use blanket sleeps, altered production timeouts or weaker authorization as synchronization.

G25 requires a documented final invalidation decision, not automatically an unfiltered Stable at
every stage. If a broad checkpoint runs, retain every failed assembly and exact qualified follow-up.
G18–G23 are actual three-instance/native consumer work, not a mock of IProviderRequestHistory alone.
Full unchanged 19-case protocol repetition is conditional as described in the runbook; a change to
shared transport/authority cannot be excused as 'UI only'.

Write results outside this immutable package using the [evidence template](templates/evidence.json).
All groups begin NOT_RUN. The stricter optional evidence checker rejects incomplete groups when
`--require-complete` is requested, but still only validates recorded structure, not execution truth.
