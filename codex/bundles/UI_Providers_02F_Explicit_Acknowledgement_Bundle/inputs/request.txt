WORKSTREAM 1 — PROVIDERS-02F
======================================================================

Goal:

Make receiver acknowledgement an enforced semantic contract rather than a
convention, without replaying provider/shared-provider mutations and without
introducing a generic event bus or durable outbox.

----------------------------------------------------------------------
1.1 Enforce explicit reconciliation acknowledgement
----------------------------------------------------------------------

Required behavior:

- Returning successfully from the delivery callback is not sufficient by
  itself.

- SharedProviderRecovery may classify a delivery as Acknowledged only when
  SharedProviderChangeDelivery.IsAcknowledged is true after receiver
  processing.

- A callback that returns without calling ReconcileAsync leaves the delivery
  Pending.

- A callback that throws before acknowledgement leaves the delivery Pending.

- A callback that completes ReconcileAsync and then throws leaves the
  delivery envelope receiver-acknowledged but sender-pending. A later correct
  owner may complete sender bookkeeping without running reconciliation again.

- If ReconcileAsync completed but the sender component became stale or was
  torn down, the acknowledged receiver state must survive in the circuit.
  A later valid owner finishes delivery cleanup without rerunning the
  receiver effect.

- A wrong target/source or stale generation cannot acknowledge or complete
  another attempt.

- No delivery retry may repeat Publish, Unpublish, imported-settings update,
  retirement, source write, source test, or source synchronization.

Update the current test that expects `_ => Task.CompletedTask` to acknowledge.
That callback must now produce Pending.

Add direct tests equivalent to:

- Callback_return_without_receiver_ack_keeps_delivery_pending
- Callback_exception_before_ack_keeps_delivery_pending
- Reconcile_ack_then_callback_exception_does_not_repeat_reconciliation
- Reconcile_ack_survives_sender_teardown
- Correct_owner_can_finalize_already_acknowledged_delivery
- Wrong_owner_cannot_finalize_acknowledged_delivery
- Successful_ack_releases_attempt_and_delivery_once
- Delivery_retry_never_replays_backend_mutation

----------------------------------------------------------------------
1.2 Make receiver reconciliation single-flight
----------------------------------------------------------------------

Harden SharedProviderChangeDelivery.ReconcileAsync so that:

- the reconciliation delegate runs at most once successfully per envelope;
- concurrent calls do not run the delegate in parallel;
- a second call after successful acknowledgement returns without rerunning;
- a failed reconciliation remains retryable;
- an in-progress reconciliation has defined behavior;
- no thread-blocking lock is held across await;
- the type does not become a generic application event framework.

Use an asynchronous single-flight mechanism or a small explicit state
machine. Avoid SemaphoreSlim proliferation unless it is the simplest bounded
solution.

Add concurrency-focused tests.

----------------------------------------------------------------------
1.3 Audit every delivery producer and receiver
----------------------------------------------------------------------

Advisory Unconfirmed/UnknownScope callbacks do not represent a known commit.
