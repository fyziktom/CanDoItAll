# Real application and native-owner journeys

Run after the relevant implementation has stabilized and on the recorded final
source pair. Avoid duplicating all unchanged WB1 setup. Use new isolated resources,
or a specifically owned retained fixture whose identities you inspect before reuse.
Never reset historical manual data or the ordinary app on port 5032.

## Native project report

Create an owned project and a descendant through existing Projects UI. Use WB1 task
entry points for nontrivial schedule, effort, pricing and execution states. Include
known zero, unknown/unpriced and a non-USD planned amount with meaningful decimals;
keep actual completion and future-plan semantics. Record exact native project/task/
assignment identities. Preserve a separate unchanged sibling project/task.

Open Manager Summary. Prove no payload query before Load. Load current-project and
confirmed descendant scopes, including one bounded large-scope fixture if practical
through existing native test owners. Record accepted options/window and compare all
figures with actual native facts/calculator output. Edit options without Load and
show that the accepted chart and Activity details retain their original provenance.
Run one appropriate Agent, SimpleChat and Workflow path and a supported bounded root
Process fixture; use owner-level integration for any path requiring unavailable
external tooling rather than inventing a green browser result. Keep child/parent
attribution and historical partial coverage visible.

Activity must have enough native records to span a page. Exercise both offset and
Process continuation protocols, filter totals independently from page rows, backward
navigation and a fixed as-of cutoff that excludes a later generated record. Do not
seed report DTOs directly and call that persistence evidence. Do not load raw
conversation transcripts just to calculate metadata totals.

## Selection and support controls

Open actual Structure with two different native targets. Exercise Object Index
search and right-click, single/multi menu, Signals marker add/remove, priority and
progress, health/validation and Selection border/status/action controls. Read the
canonical objects/links and assert exact changed targets and unchanged neighbors.
Use captured delayed callbacks to prove a stale menu cannot affect a successor
selection or a recreated project lifetime. A denied path must reach the actual
owner/authority boundary in tests, not merely find a disabled button.

Open WB1 task editing through the new selection presentation and save one small
field without disturbing schedule, precision, assignment, cost basis or hidden
metadata. Open existing attachment/mermaid/native details through their real owners.
The metadata card may render in a sandbox, but bytes, local-open permission and
current content authorization require native proof. Preserve existing confirmations.

## Agent and provider continuity

Use a supported ordinary Agent over the same owned Project Structure. Read a canary
not supplied in the prompt, approve an exact harmless file write/attachment and reject
a distinct proposal. Verify tool names *and arguments*, original project/node/path,
approval/run/receipt IDs, canonical bytes and download hash. Keep the original file
and unrelated sibling bytes unchanged after rejection. External model responses may
be deterministic; no new paid calls are authorized.

Where the existing fixture is available, use the owned source and two clients for
relevant shared-provider consumption. Source-defined display names must stay separate
from opaque request routing IDs; no personal-provider fallback may hide a failed
shared route. The new report shows native consumer identity and pricing, not a
new rewritten model name. Recheck History metadata versus content authorization.
Only the touched consumer paths need a fresh run when protocol inputs are unchanged;
record the scope, not a fictitious full protocol campaign.

## Runtime/restart continuity

Keep a completed finite Scheduler plan enabled and use the existing repaired native
restart path; a future neighbor must not duplicate. Do not pause an exhausted plan
to make a restart pass. Relevant accepted/incomplete Workflow output and current
History proof remain in the impact map. WB2 does not redesign Scheduler or Workflow.

## Fixture and evidence discipline

Use isolated PostgreSQL of the repository-required major version, dedicated port,
volumes and process/container labels. Native credentials are short-lived fixture
credentials only; inspect expiration before a paid-free deterministic run. Renew
explicitly rather than silently replaying an unknown operation. Preserve response
plans until the original native attempt has a known disposition. Keep original
failures and observations even if a later attempt passes.

Collect test/image/DLL/served-asset hashes at the relevant time, not retrospectively
as pre-run evidence. A follow-up metadata-only image has separate affected proof;
state that instead of relabeling earlier browser runs. Clean up only owned processes
and policy-authorized fixture resources after capturing results; do not kill unrelated
apps, user signing agents or remove retained evidence.
