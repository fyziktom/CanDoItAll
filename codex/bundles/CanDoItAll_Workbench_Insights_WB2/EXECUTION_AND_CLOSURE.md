# Execution and closure

## Stages and decision gates

S0 repairs the bounded original Components owner and validates it. W1 finishes
Manager Summary with all charts, diagnostics and the full Activity dialog. W2
finishes all four Selection/Support surfaces plus the actual advanced child and
production wiring. W3 proves independent publishing, native effects, regression and
developer-loop behavior. These are stages of one task, not permission to stop after
a single subpanel. Keep coherent signed checkpoints.

Small reproduced integration defects belong in this run, including native adapter
origin capture needed by the selected surfaces. Preserve behavior and add failing-
first tests. If the actual issue requires a new cross-owner authority, database
schema, persistent replay protocol or broad business redesign, map it with exact
call graph, values, attempt order, effect phase and affected consumers. Stop unsafe
writes and report the blocker, while continuing independent safe work where valid.
Do not manufacture a speculative fix or call a map a resolved defect.

## Deliverables in the repository

Update existing maintained architecture/module documentation and add the slice's
specific evidence record where current conventions place it. Include actual
renderer/caller/descendant/assets census and remaining main-canvas/runtime/file
scope. Do not modify sealed historical bundle docs or replace native forms with
unexplained compatibility placeholders. Keep old public compatibility types where
needed and validate forwards/wire identity/document generation when changed.

Record entry/final source pair and dirty state, precise deltas, dependency graphs,
actual build/test commands and counts, source/published/native proof, failed attempts,
qualifications and repeated watch conditions. Large private logs, traces, TRX,
screenshots, credentials and fixture database artifacts remain outside tracked
source and sealed bundles. Safe tracked summaries point to the original artifacts.

Use [the evidence template](templates/evidence.json) as a simple ledger or supply an
equivalent adapter from the existing repository format. Fill an external copy;
leave the sealed template NOT_RUN. The validator checks structure only, never
whether a command actually ran or an artifact is genuine.

`python tools/validate_handoff.py --evidence <external-evidence.json> --require-complete`
requires every group to have passing referenced proof, required source/signature
metadata and no blocking finding. Qualified/local-only dependency delivery must be
stated explicitly. If a group cannot pass, report partial completion truthfully;
do not change the template, validator or group scope to turn it green.

## Closure fields

- `insights_ui_boundary_complete`: every scoped real renderer and its assets has
  crossed the boundary and is used by production and the faithful sandbox.
- `gantt_cleanup_fixed`: failed-first cancellation/fault cleanup is repaired and
  paired build/browser continuity has passed.
- `reporting_and_selection_native_proof`: original report arithmetic/window/cursors
  and real action effects/refusals are proved, not only scenario mocks.
- `native_consumer_campaign_passed`: required affected application paths have
  current source-pair evidence with old failures kept separately.
- `ready_for_next_workbench_slice`: the selected WB2 boundary and required proof
  are closed without known blocking defects. It is not release readiness and not
  completion of all Workbench/Processes.

Record remote versus local Components delivery independently. The current dc573e2b
fix is already published, but a new S0 commit may need operator publication later.
Verify the actual dependency resolution/assemblies/assets instead of changing CI
pins blindly. No push or release is delegated here.
