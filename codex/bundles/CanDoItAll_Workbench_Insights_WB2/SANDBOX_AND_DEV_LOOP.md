# Independent host, assets and measured developer loop

The sandbox renders the same Manager Summary, Activity and Selection/Support
surfaces used in production. Register no module implementation, database, native
runtime, vault, Process application or generic fake service provider. A realistic
fixture implements only the actual seam and makes simulated operations explicit.

Required scenarios include initial not-loaded, loading/progress, accepted empty,
realistic/large bounded reports, unknown/estimated/non-USD values, failed/stale read,
changed draft options, pending scope confirmation, four activity kinds and more
than one page, separate windows, no/single/multi selection, missing/disabled target,
read-only/denied action, exact partial/unknown outcome and queued A-B-A results.
Use the actual Charts, CanvasFloatingWindow, TreeView, dialogs and native-looking
feature markup. Do not replace significant children with labels or screenshots.

Source Fast/Parity and separately published Fast/Parity must serve their own
correct asset graph: fonts/theme, chart scripts, Canvas window runtime, scoped CSS,
icons and any feature-owned JavaScript. Public/static resources stay with their
true owners. Test generated scopes against actual DOM, not just HTTP 200 responses.
Do not distribute fonts as standalone handoff files.

All newly created visual contexts use **1920x1080, scale 1**. Test visibility,
full menus, vertical scroll, focus, keyboard actions, stacked independent dialogs
and close during loading/errors. No small/medium/mobile tuning, breakpoint sweep
or new responsive redesign. Existing legitimate tests remain intact.

Before movement, record current native/sandbox build roots, SDK, source/dependency
pair, evaluated graphs and watch file sets. Afterwards measure the same owned Razor,
C#, CSS and any owned JS file across three consecutive edits and restorations.
Capture process PID, watch output, browser reload/navigation versus in-place update,
edit-to-visible observation and cold/warm conditions. If the leaf has no owned JS,
state that rather than manufacturing one solely for a metric.

Restore probe files byte-for-byte. Separate build/startup readiness from edit latency.
Do not compare unlike baseline hosts and call the ratio a product speedup. WB1's
reported same-PID samples used automatic navigation for several kinds; preserve that
qualification instead of inheriting a claim of completely seamless hot reload.

The new leaf should not require rebuilding Workbench/MAF runtime for a renderer-only
edit. Prove this with evaluated and observed builds; csproj count alone is not proof.
Keep published-asset and real-native-operation validation as separate layers.
