# Validation matrix

The groups below are proof topics, not a prescribed number of tests or classes.
They start as NOT_RUN in [the evidence template](templates/evidence.json). Reuse
actual existing tests and add only missing behaviors. Each execution must record
its command, selected filter, expected/actual discovery, executed/pass/fail/skip,
source and pre-run assembly identity, environment and private artifact references.
A source inspection, helper self-test or disabled live gate is not a native pass.

## Choosing tests without wasting the run

Read current `docs/testing.md` and actual CI registrations. Build each changed
production project before its owning tests. Use CodeAnalytics when available;
otherwise follow explicit call sites and current source/discovery. Confirm the
count for every new/changed filter; zero or an unexpected count is not proof.
Do not copy historical counts into new filters.

Existing relevant anchors include the native Manager Summary state/query/calculator
and scope tests, current Project Structure action/admission tests, WB1 pricing and
task families, and the actual Components Gantt lifecycle family. Discover their
current names and owning projects; this brief does not fabricate exact methods.
New lightweight tests belong in the correct Components/Stable/CI lanes, never as
product projects. Preserve all negative boundary and public-identity tests.

A broad run is not required at every step. After the delta settles, explicitly assess
current composition, shared-contract, owner and CI/build invalidation triggers and
choose one defensible final checkpoint. A shared Gantt fix requires its current
consumer evidence. If a later code change invalidates earlier proof, rerun its owning
selection and assess wider impact; do not relabel earlier binaries as the final source.

For any deliberately reused native protocol result, identify the exact unchanged
inputs and why reuse is valid. Do not claim all nineteen shared-provider vectors
ran if only relevant native UI/report consumers were exercised. Reuse does not
cover changed UI or altered authorization paths.

Static closure includes the real portability scan, intentional reviewed deltas and
final enforcement without write-baseline. Source/delta secret scans, complete
worktree scans and historical synthetic controls have distinct scopes. Preserve
historical failed artifacts and scanner rules; do not call a scoped scan a clean
full checkout.
