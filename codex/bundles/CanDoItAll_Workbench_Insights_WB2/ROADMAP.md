# Updated roadmap after WB1

| Family | Disposition |
|---|---|
| Agents, provider administration selected slices, History, capability/team editor and Workflow authoring | Preserve completed AC1/WF1 boundaries and explicit native hosts. No wholesale restart. |
| Workspace, Projects portfolio/editor/files | Preserve completed UI families and real authorization/persistence. |
| Workbench Calendar, Gantt and both task forms | WB1 completed; one bounded Gantt lifecycle follow-up is staged at the start of WB2. |
| Workbench Manager Summary, Activity and Selection/Support windows | **This WB2 bundle**, approximately 4/5 integration complexity, no elapsed-time promise. |
| Main Structure canvas, node inspectors/authoring and toolbox/graph gestures | Next major coherent family; audit current call sites after WB2 rather than duplicating moved support windows. |
| Remaining Workbench assignment/process/workflow launch integration, runtime/file/preview families | Separate cross-owner slices. Preserve native admission, file content authority and recovery. |
| Processes product UI | Last large family after Workbench boundaries are stable. |
| Final Web/compatibility audit | Reachability/asset/dependency review, not deleting every residual Razor or adding missing features by inference. |

Longer Codex runs are used to complete coherent functional families and their real
proof, not to combine every owner or to repeat broad Stable after each small stage.
A remaining native route, registry, context publisher, lifetime adapter or command
owner is legitimate. A complete renderer hidden behind an injected service bag is not.

Do not claim the main Structure canvas or whole Workbench complete after WB2. Its
selection/support children will be isolated, but graph authoring and runtime/files
remain separate work. No new provider test-chat or maintenance screen should be
invented just because a backend operation exists.
