For code tests record direct production build, refreshed owning assembly, exact filter, expected
and actual discovery and executions, with an explanation of any data-driven expansion. For a
review/measurement gate, record the actual command or inspection and its evidence; do not
invent test counts. G30 can pass only as an honest regression decision/disposition, not by
relabeling a failing broad attempt. Keep mixed attempts with their true status. Required
product behavior may not be replaced by a review note, gate-off test, fake echo or old screenshot.

Use controlled native barriers for writes, not only delays in a fake UI port. Native PostgreSQL
and real shared controls are required at their appropriate layer. Empty discovery, skipped
prerequisites and unavailable tests are not a pass. Final --require-complete rejects any required
non-PASS group; it still cannot certify that referenced private commands genuinely executed.
