# Execution, regression scope and completion

## Stage cadence

S0 continuity/quote regression -> W1 Calendar and data seams -> W2 complete Gantt -> W3 both
task families -> W4 independent/native integration closure. These are meaningful checkpoints,
not rigid class names or per-step microcommits. Finish every selected family in this run.
No work on the unrelated Structure canvas or Processes begins after an early stage succeeds.

Map affected tests with actual CodeAnalytics when available; otherwise current source/caller
search and evaluated project graphs are acceptable with the limitation stated. Discovery uses
current branch code, not default-branch search excerpts. Candidate owning families include
ProjectCalendarPageTests, ProjectStructureGanttPanelTests, ProjectStructureGanttMutationServiceTests,
ProjectStructureTaskResourceCostEstimatorTests and native TaskApplication/assignment/resource
classes. Verify their actual names, traits and case expansions instead of hardcoding counts
from this document. New pure leaf tests and real-host tests complement, never replace, them.

Directly build changed production projects before their narrow current tests. Refresh the
owning test assemblies before --no-build. Confirm exact filter discovery count. Keep original
failures, source hashes and distinct follow-up runs. A filtered result is not an entire suite.

## Stable decision

After the settled source/contract/reference diff, record the current repository trigger for
one frozen Stable checkpoint or the reason none is triggered. New shared Workbench contracts,
ownership results or composition/test/CI registration are likely relevant; decide from actual
changes, not elapsed time or a module label. Never run broad per form. The gate here is an
honest decision and proper disposition of any executed run, not a demand to call a mixed run
PASS. Product-relevant failures must be repaired with current proof or remain blockers.
Non-product prerequisite and preserved synthetic-control failures keep their precise scope.
Any later source delta requires specific invalidation analysis and fresh affected proof.

## Evidence and security hygiene

An attempt records exact command/filter, expected+actual discovery, executions, pass/fail/skip,
configuration, source/dependency fingerprints and artifact references. Actual browser actions
need native identity/bytes evidence, not only screenshots. Preserve original errors and
independent failing runs; never relabel by adding a later passing attempt. Build/image labels
must describe their true source. Store full transcripts, credentials and private fixtures
outside tracked files. Source-only and full-worktree scans are not interchangeable.

Run current portability-static after protected edits, repair genuine findings, review baseline
moves, inspect the diff and finish enforcement without baseline write. Also validate maintained
docs, changed secret-risk lines and owned shared asset gates. Never waive mandatory static
closure because tests passed, or remove security controls to make a scan green.

## Defect handling

Repair small reproduced owned defects immediately and preserve their regression tests. A new
large authority/schema/durable-transaction redesign needs a concrete map: original/current
call graph, exact failure sequence, affected records, reproduced result and safe next slices.
Stop its hazardous path, continue independent safe work and report a blocker honestly. Mapping
is not fixing. Do not invent a critical AC1 issue to force another closure-only iteration.

## Final completion fields

Keep architecture, sandbox fidelity, native functional correctness, current regression scope,
dependency delivery and measured development performance separate. `planning_ui_boundary_complete`
means Calendar, entire Gantt, both task form families and children are genuinely isolated and
used by production. It does not mean all Workbench is finished. `ready_for_next_workbench_slice`
requires no unresolved blocking product findings in this slice, current required native/independent
proof and explicit dispositions. `release_ready` is not authorized by this assignment.

The maintained WB1 record includes remaining PM/read panels, Structure canvas/inspectors,
assignment/runtime/files and Processes work. Update only current docs/census, never old sealed
bundles. Use verified signed checkpoints, leave exact local delivery limitations visible,
stop owned resources and retain the data needed to review the result.
