# Native owners and lifetime boundaries

The native source references in S15, S18 and S25–S27 are the starting map. Refresh the complete
call graph with current CodeAnalytics when available, otherwise explicitly report source search
and evaluated references as the fallback. Never claim an unavailable MCP tool was executed.

## Authority that stays native

Project identity is not its lifetime. Retain the original Projects-owned admission and the
current permitted actor to the actual native transaction. Ordinary Agent source authority,
Process claims and local UI authority are separate modes; do not synthesize or merge them.
ProjectStructure invocation snapshots are bounded read context, not permission to mutate.
Canonical host database and selected UI profile have different roles; do not rebind scoped
factories merely to make the new sandbox or multi-profile test convenient.

Workbench owns task objects, links, ordering and task-related assignment records. CRM owns
Party, affiliation, roles, rates and validation; Projects owns its project lifetime and
bridges. Calendar and Gantt show projections, not a duplicate writable task table. Use existing
query/transaction participation paths, preserving native lock order and compensation behavior.

Do not publish raw `ProjectObjectRecord`, EF model, whole authority-bearing request, or
`IServiceProvider` through the renderer seam. A stable UI origin can be mapped to native
captured context by the host. Do not serialize actor grants or source admission into navigation,
local storage or reusable sandbox fixture payloads.

## Independent decisions

Availability of project header, calendar events, Gantt assignments/order, resource options,
quote and active task editor are separate. A successful ancillary read cannot mark a missing
editor acquired. An unavailable reference is not an empty successful list. Already loaded
same-scope data may be explicitly stale; another scope's data must be removed.

After every relevant wait, check the original request and opening before publishing. Before
new native dispatch, check ownership again; after dispatch, retire display without falsifying
what the owner committed. Keep original operation facts independent of view navigation.
Read retry is not write retry. Reopening a new lifetime should not inherit an obsolete busy
flag or unknown operation, nor automatically replay the old operation.

View state is a persisted effect even when the domain view is read-only. It needs original
project/context and ordering, but not a new generic transactional engine. Do not mistake its
success for task data persistence. Restore only accepted state for the correct canonical scope.

## Change budget

Pure renderer extraction and targeted lifetime fixes are authorized. A necessary narrowly
scoped owner/result correction can accompany them with native fault tests and compatibility
coverage. Pause the affected hazardous path and map a newly demonstrated schema, authority or
cross-owner durable-protocol redesign; do not implement speculative broad changes. Continue
independent safe parts and report that a map is not a repaired product blocker.
