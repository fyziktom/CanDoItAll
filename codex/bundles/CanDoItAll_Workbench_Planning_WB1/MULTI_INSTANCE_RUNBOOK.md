# Owned multi-instance continuity

Reuse the current shared-provider E2E runner/Compose capability after reading its actual
preflight and ownership contract. Prefer a new unique WB1 source + two clients with independent
DBs, volumes, project labels and loopback ports. Never blindly Reset an old/manual stack.
A previously stopped private fixture can be reused only after exact ownership/input/credential
checks and a clear reason to preserve its receipts. PostgreSQL18 must have sufficient durable
capacity; do not repeat the known small tmpfs exhaustion problem. Reap child processes in SDK
containers with the documented init setup.

This is not another blanket provider protocol refactor. Select bounded relevant checks:
source default and nondefault model display metadata and opaque routing, exact source identity,
no fallback to a personal provider, a real client Agent task/file journey, Workflow consumer,
History content denial and two-client isolation. Retain old 19-vector proof only for explicitly
unchanged inputs; rerun the vector if the actual protocol/runtime/dependency diff invalidates it.
A passing test-chat API alone does not prove the planning UI's Agent/Workflow consumer journey.

Run affected consumers on the final rebuilt application image or prove the exact unchanged
production inputs of an already built candidate; preserve original image labels. Record the
main/Components/FileTools source pair, input fingerprint, image IDs and asset comparison.
Credential expiry is a prerequisite failure; don't replay an uncertain original turn. Resolve
its state and renew only task-owned credentials via native owners, then use a distinct action.
Do not discard response plans needed by pending approvals/unknown original outcomes at teardown.

Preserve the completed finite enabled plan and admitted history across app restarts. Check
unchanged canonical receipts and a future neighbor exactly once. A retained runtime projection
warning is not a UI pass/fail by itself: classify it by affected owner and exact evidence.

Retain private logs, TRX, media, failed attempts and meaningful data. Stop only verified owned
processes/containers at closure; never delete historical data merely for a clean scan. Export
only redacted result metadata. No physical microphones, paid inference, real mail/payment or
new deployment side effects. Current user authorization covers harmless ephemeral test accounts,
credentials and publications only inside the owned local fixture.
