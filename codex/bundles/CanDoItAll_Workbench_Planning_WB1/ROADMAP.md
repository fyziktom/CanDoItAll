# After AC1: remaining roadmap

This is a scoped planning order, not an elapsed-time estimate or permission to implement all
families in WB1. Current source inventory S28–S30 shows a very large Structure canvas and
substantial native task/scheduling families. The selected planning slice is intentionally
larger than a single dialog but smaller than all of Workbench.

| Order | Family | Current intent | Relative complexity |
|---|---|---|---|
| Complete | Active Agents, provider PP1–PP3, capability/team CA1, Workflow WF1 and AC1 adjuncts | Preserve extracted UI and legitimate native hosts; maintain regression, do not redo them | Completed selected rendering; not universal release certification |
| Now WB1 | Workbench Calendar, entire Gantt and both task editor families | Independent planning UI and sandbox, native exact owner/effect validation | 4/5, one multi-stage substantial bundle |
| Next Workbench read slice | Manager summary/activity, object index/health/signals and remaining bounded read windows | Current caller/authority census, then whole useful read families | 3–4/5 |
| Next Workbench authoring | Main Structure canvas, node/selection/toolbox and supported general authoring | Lossless native graph, exact target context, real shared canvas and independent host | 5/5 |
| Later Workbench integrations | Process/Workflow assignments, file/browser/assets, runtime/terminal/media and remaining editor dialogs | Separate actual owner protocols and projections; classify hosts rather than blindly moving all Razor | 5/5, split by genuine native ownership |
| Last major family | Processes | Catalog/definition, launch/approval, live monitoring, file/evidence and recovery | 5/5, multiple coherent slices |
| Final shared/Web audit | Home/runtime capability pages and reachable shared remnants | Current callers and assets only; retain dormant public compatibility intentionally | 2–3/5 |

If WB1 discovers a truly indivisible dependency, document the smallest safe extension before
implementation; do not absorb the huge Structure page via a broad service bag. No release or
merge is implied. Rendered files remaining in a module do not automatically mean incomplete
work, and a new .UI project does not automatically mean completion.
