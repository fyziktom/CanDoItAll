## New native proof obligations

Use rich source documents and real production composition. Separate scopes/connections and
actual restart/cross-process tests must not reuse a service dictionary. Required topics:

- Every supported action in all five families is durable and observable from another scope;
  catalog/filter/count/status and semantic canvas/import behavior agree.
- Full hidden-field/resource preservation, no-op template identity/hash compatibility,
  schema/serialization round trip, relationship integrity and typed invalid-input refusal.
- Concurrent first insert in global/project scope, two writers on one revision across
  different editor families, unique receipt race, same operation/different payload, no
  partial head/publication/receipt state on precommit failure.
- Real postcommit response failure, retained known acceptance, operation-status recovery
  from another scope/host and exactly one native mutation. No unknown-result blind replay.
- Clean/dirty authoritative newer observation, delayed old read, sibling revision coherence,
  current denied scope and all inherited opening-retirement/raw-input scenarios.
- Draft versus immutable publication, exact preview/launch/prepared retry after republish,
  deliberately resolved empty drivers, pinned child/resource meaning and legacy run recovery.
- Project admission race under the real transaction gate, profile switch, same public ID
  with another lifetime, transfer residue/model coverage and no sensitive state bleed.
- Fresh canonical migration, upgrade populated predecessor schema, no pending model changes,
  SQL review, same-data idempotent reapply and real owned OS-process restart.

Construct before-fix evidence with owned fixtures and then commit positive tests for repaired
behavior. An ignored diagnosis program expecting data loss cannot become the long-term green
oracle. Keep sandbox simulations explicitly separate from real native semantics.

## Performance and dependency checks

Capture a small reproducible baseline before changes, then repeat under the same source/
sibling/configuration/fixture conditions. Record dataset shape, sample count and environment.
Measure native catalog/query SQL count and elapsed observations, selected definition load,
authoring commit/read-back, and preview/compile preparation. Avoid N+1 per role/step, full
JSON deserialization of the catalog, unbounded aggregate history scans, synchronous DB waits,
per-render storage queries and per-pointer-frame commits. Metadata indexes and page limits
must serve real query paths; a test on three rows is not scale evidence.

Re-evaluate light UI/sandbox/production project closures and assets after contract changes.
No Application/Persistence/module/EF dependency may leak into Processes.UI or its sandbox
through a new public type/transitive reference. Compare Fast/Parity source and published
startup. Record measured samples, not an unsubstantiated speedup percentage. A former non-durable dictionary write is not an equivalent durable-commit baseline; attribute the added guarantee and report its measured cost separately. Do not create a
benchmark framework or brittle arbitrary millisecond assertions; fix clear regressions and
state remaining performance uncertainty.

composition and launch resolution. It therefore triggers one final broad Stable campaign
at an integrated frozen checkpoint under current repository policy. It is not required after
each implementation stage and does not replace Playwright/live-process/host-specific lanes.
Run the precise current Stable command/traits and preserve honest failures/skips/quarantine.
If a later code change invalidates part of the campaign, rerun the affected proof and reassess
broad invalidation. Do not label a required unavailable gate NOT_APPLICABLE.

Run mandatory portability-static self-tests/scan/secret checks, review each ADDED/STALE finding,
repair true defects, refresh only intentional reviewed baseline changes, and enforce finally
without --write-baseline. Check new/untracked files by the supported scan/staging path.
Do not autoaccept a whole new baseline or skip a rule because generated migration text is
large. Run canonical pending-model/schema/transfer validation and current docs/link checks.
