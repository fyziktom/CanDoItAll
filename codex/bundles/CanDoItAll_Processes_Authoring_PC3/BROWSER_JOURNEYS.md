# Production browser journeys and effect oracles

Use current Playwright helpers, a task-owned production Web host/configuration, isolated
PostgreSQL 18, ephemeral loopback ports and supported large-desktop viewport (the reviewed
campaign used 1920 x 1080, scale 1). Preserve source/published Fast and Parity sandbox modes.
A deterministic free local upstream is permitted; it is not live-model proof. No paid calls.

Final durable journeys use normal production IProcessWorkspaceProjectionClient lifetimes.
Do not substitute a retained role/step owner or inject desired projections. A transparent
fault/timing decorator may observe the native method and delay a result, but cannot replace
its storage, transaction or read path. State the exact seam and independent oracle.

## J1 — real save and reopen across all sections

non-first step (with distinct DecisionRoleKey). Keep later text typed during an awaited Save.
Switch tabs, refresh, close/reopen and open a second browser context. Native reads from fresh

An unmodified step/hidden rich semantic fixture remains unchanged. Capture editor readiness,
not just a page heading before input. Preserve raw invalid numeric drafts across lazy tabs.

## J2 — role identity, canvas and materialized imports

Add a role with a dialog open, then select another role before a delayed result. Prove the
correct eligible selection behavior. Delete an unreferenced selected role and the last

Use the actual canvas: move nodes, add supported structures, recompose, clone visual
references and keep two canvas instances independent. Confirm final geometry after refresh,
not pointer-frame command counts. Import a role/artifact/process into captured targets, then

and stable remapping natively, not only ImportedComponents count. Reopen in another session.

## J3 — two editors and an authoritative newer revision

Open A and B at r1. A commits r2. B clean refreshes and sees r2; B dirty refreshes instead
retains raw local fields and offers conflict/reconcile. A's receipt remains visible even
when a later valid r3 arrives. Include a role edit in A and stale step/canvas write in B;
one shared revision must prevent lost updates. Demonstrate an intentional conflict recovery
through the UI and a subsequent valid write, with exact native operation counts.

## J4 — real unknown/secondary failure recovery

Inject a fault after the native COMMIT but before returning the result, then consult/retry
the same durable operation identity from a fresh scope/session. Exactly one aggregate
change/import/publication exists. For known accepted plus failed read-back, keep the receipt
and show a warning; Refresh must not replay the write. For precommit validation/authority
refusal, preserve the draft and allow a corrected explicit intent. No private exception
text appears in DOM, console or screenshots. Unknown must have a working status/recovery
path, not an indefinitely disabled page.

## J5 — publication, OS-process restart and exact launch

the relevant browser path where it is user-visible. Archive blocks new acceptance as defined;
accepted runs remain recoverable and unmodified.

## Evidence and failure handling

Use bounded TaskCompletionSource/native signals for ordering; do not rely on arbitrary long
sleeps. Await public actions and stable editor/data state. Assert page errors and relevant
asset/network failures, inspect screenshots, retain trace plus independent effect queries and
record browser/native source/config/PID provenance. A changed screenshot is not automatically
a regression or a pass; inspect it. Record failed attempts and final reruns. Raw traces may
contain data: keep them private and sanitize committed summaries. Unavailable browser/DB
proof is BLOCKED, not a successful sandbox substitute.
