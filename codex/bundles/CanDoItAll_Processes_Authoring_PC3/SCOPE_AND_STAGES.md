# Scope and autonomous stages

## Authorized scope

Implement a durable definition authoring owner across the existing native Processes layers,
its canonical PostgreSQL schema/migration, the five editor-family adapters and catalog,
immutable publication and exact definition resolution into existing preview/launch/child-
process/prepared recovery paths. Adapt light seam contracts only as necessary. Add real
native/browser/migration/concurrency tests and current maintained documentation.

Preserve all existing enabled actions; first enumerate current command enums, visible
buttons, API and tool consumers. Do not add speculative new Create/Clone/import-format
features merely because a historical design mentions them. In particular, the reviewed
basic definition service implements SaveDraft, Publish, Archive and Delete. Canvas has
separate semantic/reference actions; those are real existing obligations.

Out of scope: another UI extraction, new HTTP-only architecture, a universal event bus,
new workflow engine, model/package upgrades, unrelated JWT/SSR/auth redesign, editing or
migrating retained user databases, automatic deployment/push, paid inference, and demo-
specific tooling. Existing runtime/policy checks cannot be weakened as a shortcut.

The stages below define completion order, not a class or commit quota. Ordinary implementation
choices belong to Codex. Refine the short design at S1 using current source and then continue
without requesting new approval for every already assigned stage. External prerequisites
may block their own proof, but never justify fabricated green results or an unrelated task.

## S0 — current state, signing and failing-first baseline

Read SHARED_BUNDLE_POLICY.md and use the installed shared baseline without a download or
version upgrade. Record NO_CHANGE by default; only an actual cross-cutting defect permits
a minimal Codex-owned in-repository correction with reviewed impact and signed evidence.
Keep task-specific rules and status updates local to this assignment's output reports.

Request local PGP unlock before substantial implementation. Inspect current worktree/index,
actual dependencies, branch drift and existing rules. Keep ordinary application resources
untouched. Establish isolated configuration and PostgreSQL 18 fixture according to current
testing.md. Discover CodeAnalytics tools/index or record real unavailability and fallback.

Commit generic tests that will protect the repaired contract together with the implementation
at a coherent green checkpoint; retain the before-fix failures privately. Do not freeze the
known data-loss outcome as a permanent passing expected result. Document actual supported
actions and touched callers. Capture comparison query/build/graph observations before changes.

## S1 — one owner contract and an additive schema

Choose the smallest complete semantic snapshot and scoped aggregate/revision/operation
contracts. Reuse native models and current transaction primitives. Add database-enforced
scope uniqueness, expected-revision compare-and-swap, immutable publications and receipt
identity. Append canonical migration and update model/transfer registration. Produce a
short ADR and cross-file map, not a stand-alone design deliverable. Run fresh/upgrade and
concurrent-first-write tests before committing the durable storage slice.

## S2 — all five families and truthful catalog

Replace instance dictionaries as production authority in definition, role, step, canvas and
import services. They may become mappers/coordinators; keep pure projections pure where useful.
Route the native client through the same owner with captured profile/project lifetime and
current native policy. Persist meaningful structure/layout, not zoom/selection/edit buffers.
Materialize real imports, preserve references and hidden semantic fields, and use one revision.
Implement honest metadata/counts/status/selection/scope precedence and idempotent FeedDefaults.
No temporary fallback may claim Accepted while losing changes in a new scope.

## S3 — observation, drafts and recovery

Replace token-mismatch pinning with an authoritative observation contract. Handle accepted,
rejected, accepted-with-warning and unknown outcomes without replaying a command blindly.
Reconcile aggregate/sibling revisions and dirty/raw state deliberately. Preserve PC2 fences,
role identity, actual-step binding, row normalization, canvas coalescing and import origin.
Add recoverable operation status using native receipts; do not make an unknown gate permanent.
Run controlled timing and two-editor tests with the actual owner as well as light tests.

## S4 — publication and executable resolution

Publish the complete validated content as an immutable revision. Resolve the same content
for catalog launch action, variable preparation, compiler, executor/assignments, prepared
review/acceptance, child-process selection and later recovery. Preserve published/accepted
snapshots when drafts change. Maintain current governance/readiness and stable legacy IDs.
Test republish/archive/delete distinctions and driver-activation resolved-empty behavior.
Do not alter the pure captured subprocess contract decoder merely because a resolver exists.

## S5 — native integration, lifecycle and migration closure

Prove production lifetimes over separate scopes/contexts/hosts and a real process restart.
Test PostgreSQL atomicity, duplicate/unknown outcomes, optimistic conflict, profiles and
project retirement/recreation under coordinated mutation guards. Update transfer residue/
model coverage without introducing silent or unsupported transfer. Validate upgraded populated
runtime data and prepared admissions still recover. Document realistic deployment/rollback
limits; no ordinary data is touched by this assignment.

## S6 — real browser and retained feature parity

Run new durable journeys and the affected existing native/sandbox journeys. Final durable
proof must not use the old retained-role/step fixture workaround. Use real owner persistence,
normal lifetimes and timing-only faults, with independent DB/native observations. Verify all
current editable controls and rendering/assets still work, including nested canvas/dialogs,
imports, files, workflows, Workbench, chat, attachments and voice restrictions.

## S7 — frozen verification and delivery

At the frozen integrated source candidate, run the final targeted union, one broad Stable
gate required by this scope, separately selected browser/runtime lanes and mandatory
portability/model/transfer/documentation checks. Record query/development-loop observations,
actual dependency closure and residuals in the PC3 report. Do not refresh shared history or
maps merely to mark this task complete; apply SHARED_BUNDLE_POLICY.md to any genuine change. Re-run evidence invalidated by later fixes.
Commit sanitized maintained reports with the tested code/tree/config/sibling pair and exact
commands/counts. A later report-only commit may refer to the tested source commit; do not
require a circular self-hash. Verify all new signed checkpoints and leave no untracked
required product fix. No push/merge is implied.

Completion requires the implemented vertical contract, not merely an ADR, tables, dictionary
replacement or a screenshot. Missing infrastructure or a fundamental newly discovered
out-of-scope dependency must be concrete, reproducible and honestly qualified; finish safe
independent work rather than silently narrowing the mandatory native or browser proof.
