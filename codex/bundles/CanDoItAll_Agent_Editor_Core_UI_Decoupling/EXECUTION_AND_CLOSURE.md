# Execution, evidence and closure

## Work order

1. **E0** — resolve current source pair, instructions, actual consumers and evaluated graph. Make a
   short implementation plan and map all selected/deferred controls before changes.
2. **S0** — reproduce/repair P2-R1; preserve prior P1 fixes; correct maintained P2 census and any
   actually confirmed title encoding defect. Focused proof first, not another whole Workspace audit.
3. **A1** — extract the real core shell/four sections and their independent scenario host. Keep six
   original deferred sections/integrations in production. Wire all current consumers and assets.
4. **Validation/closure** — test current binaries, actual owners and browser consumers; publish
   sandbox, measure loop, enforce portability, update docs/census and record honest outcomes.

Current repository instructions outrank historical snapshot details. Respect test/cleanup safety and
signing. No remote writes, branch creation/reset, merge, push, deployment or publication is authorized
by this read-and-handoff task. Existing user work, keys, ordinary host and older artifacts stay intact.
Do not evade a denied operation with another mechanism. Use temp/owned resources and an explicit
safe cleanup plan; retain diagnostic resources when needed without promising asynchronous work.

## Bounded repair versus escalation

Fix small proven UI-origin/event/field/asset/fixture defects directly with regression coverage.
Known inherited selector uncertainty is not a request to invent a fix without a reproducer.
If a new issue requires schema, new authority, durable replay or several owner protocols, record the
precise source paths, call graph, timeline, persisted effects, proof and limited repair alternatives.
Stop unsafe affected writes, continue unrelated safe work, and keep the affected gate blocked. Do
not substitute a mapping document for the known bounded S0 repair.

## Evidence and test cost discipline

Keep exact commands, discovered/executed counts, theory expansion if any, source/bin/asset identities,
TRX hashes, failed attempts and environment in a working run directory. Do not overwrite historical
attempts or sum reruns as unique coverage. A small follow-up passing on a mixed batch does not turn
the original batch all-green. Use safe metadata summaries; raw provider fixtures, credentials,
private source excerpts and screenshots with confidential content stay outside shareable artifacts.
Do not generate giant shareable discovery dumps containing negative-control credential strings.
The scanner must remain unchanged; safely separate private raw and normalized derivatives.

Read the actual current Stable invalidation rules. Named triggers, not elapsed time or phase count,
determine broad execution. Avoid parallel builds overwriting running host/checkpoint outputs; own
separate configurations and serialize conflicting actions. Final no-build test proof requires the
current compiled owning assembly, not an older successful build. Package tooling below is unrelated
to product proof and must not be reported as native C# coverage.

## Completion report

Report independently: S0 finding status; A1 selected rendering boundaries; complete list of retained
six sections/host integrations; real production entry points tested; graph/assets/sandbox proof;
confirmed native configuration and runtime consumer effects; current tests and blocked/excluded
lanes; dev-loop observations; owned-resource disposition; actual final source pair and any unpublished
sibling changes. Do not claim whole AgentFramework or application release readiness.

Working evidence may use PASS/FAIL/BLOCKED/NOT_RUN with a reason and exact artifacts. The sealed
`templates/evidence.json` remains all NOT_RUN as an input; copy it before recording outcomes. There
is no automatic runtime certification by `tools/validate_package.py`. Keep historical shared files,
review commits and original reports immutable. Update maintained modules.md, editor local README,
new boundary record and test selection docs to reflect the actual A1 state.

The next assignment after this one is decided by review. Do not start access/capabilities A2,
provider administration, Workflow authoring, Workbench or Processes in the same run.
