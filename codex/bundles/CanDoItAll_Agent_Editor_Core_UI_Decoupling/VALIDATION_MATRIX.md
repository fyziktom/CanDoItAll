## Technique and validity

Build the changed production projects directly, then the owning test assembly. Use the same filter,
configuration and source for discovery/execution. Await the actual event-dispatch task; find+dispatch
inside the renderer where background render can invalidate element IDs. For held requests, capture
the task, observe the admitted stage, release the barrier, then await completion. Do not block an
owner read in WaitForAssertion. Observe bUnit renderer disposal exceptions, not just Dispose return.

Test branch histories must distinguish test failure, setup failure, expected negative controls and
passed proof. Repeating a failing case on a fresh host can establish a follow-up result, not a causal
fix by itself. Verify actual model requests, grants, IDs, native rows and bytes for consumers. A
server HTTP success, tool toast, enabled control or visible URL alone is insufficient evidence.

## Broad-gate decision

A1 is not automatic permission to spend several hours on repeated unfiltered runs. Use current
`docs/testing.md` triggers. If shared model/enum contracts, owner behavior, general validation,
canonical persistence/authority or common fixture policy change, explicitly evaluate whether a new
frozen broader gate is required. If it is required, run it once after code stabilizes, then reassess
invalidation after subsequent changes. Otherwise state which focused owner/consumer proof bounds
the unchanged shared graph. Historical P1 Stable and P2 selective tests are not fresh A1 evidence.

Every protected-file change still requires reviewed portability-static deltas and final enforcement
without baseline-writing. Do not loosen a scanner or remove a behavioral test for a green result.
No paid/live proof is mandatory or authorized here; record it as outside this assignment, not Passed.
