## 1. Execution boundaries

- Use isolated PostgreSQL databases, temporary canonical-file workspaces, fake clocks and deterministic local upstreams. Preserve the user's running instance, real providers, credentials and database profiles. Existing integration fixture availability must be checked before running; a skipped/unavailable PostgreSQL test is not database proof.
- Do not automatically run `SharedProviderTwoInstanceUiAcceptanceTests`, `SharedProviderRealCatalogUiTests`, the whole Playwright project or a live 5210 acceptance flow. Some existing UI flows can issue tokens or invoke real providers. Reuse safe helpers only after inspecting their setup and teardown. New history browser tests must use an isolated host and deterministic upstream without real API keys.
- Tests may create synthetic token identities and sentinel secret strings inside fixtures. Never include real keys, request bodies, connection strings or signed URLs in transcripts, SQL plans, screenshots or manifests. Assert sentinel absence without printing the sentinel payload.
- Build the affected project graph once for a frozen source/test/dependency/configuration state. Reuse binaries only while that state remains identical. No solution-wide test run is an automatic phase gate.
- Check the actual diff before each phase. Refresh CodeAnalytics impact analysis from changed production/test files, with runnable test projects included. The preparation snapshot `snap-20260828134930-4eb1620a` covers only ten scoped production projects and cannot certify all runtime, UI or test impacts.
