# QA And Architecture Handoff

For preparation review, inspect documents/source references only and do not implement.
For execution review, first verify the user authorized that work and identify the exact
phase and current source revision.

Start from the literal request, normalized requirements, normative05/09/10 contracts,
dependency map and proof strategy. Review actual changed code/producer paths and tests,
not only status prose. Report precise actionable findings with file/line and impact.

Challenge these shallow passes: provider/model as identity; unknown cost as free; aggregate
price copied to every retry; canonical transcript copied into a log; generic runtime wrapper
missing MAF/stream/batch; second-context outbox; file journal missing late first creation;
expiry defeating retained canonical evidence; transient profile generation as storage key;
eager history/totals/facets; client-only authorization; Search submitting provider Save;
Workspace-to-AgentFramework dependency; offset/full-source paging; stale cursor/results;
fake empty errors; unobserved SDK retries; expired/unauthorized detail in DOM or logs.

Check discovery selects real class names (not guessed filenames), includes required new
authority/transaction/producer tests, and has no unexplained skips/zero matches. Positive
and negative cases must target actual behavior. Governed proof must identify real source
producer, durable artifact, consumer, failure/replay lifecycle and hashes/transcripts.
Seeding is valid for scale, not the sole proof of functional capture.

Verify runtime/class-size/project/public-signature/DI constraints and old-body removal.
Review desktop1920x1080 normal and open-overlay evidence with first viewport, focus,
clipping and scroll ownership findings. Browser/database/tool unavailability is a missing
execution proof, not a silent pass; do not work around access controls.

A prepared bundle can pass without product implementation. Product closure cannot. Keep
those verdicts separate, propagate invalidation to affected dependents, and do not request
unrelated full-suite runs or paid provider calls without a concrete necessity/authorization.
