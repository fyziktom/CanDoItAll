SB06-INVARIANT-001

- `repo://src/CanDoItAll.AgentFramework.Tooling/CanDoItAll.AgentFramework.Tooling.csproj` references only AgentFramework Models plus Microsoft.Extensions.AI.Abstractions; it has no product module or MAF project reference.
- `repo://src/CanDoItAll.AgentFramework.Tooling/IAgentRuntimeToolProvider.cs` exposes only provider order, descriptor, tool creation, and optional metadata hooks using Tooling/Core model contracts and `Microsoft.Extensions.AI` abstractions.
- `repo://src/CanDoItAll.AgentFramework.Maf/Runtime/Capabilities/MafAgentRuntime.Capabilities.RuntimeToolProviders.cs` owns only provider-neutral composition policy: ordering, descriptor fallback, duplicate provider/tool validation, metadata inference, approval wrapping, purpose mapping, and diagnostics.
- `repo://src/CanDoItAll.AgentFramework.Maf/Runtime/Capabilities/MafAgentRuntime.Capabilities.cs` contains no process/project/image-specific runtime tool attach methods after SB04/SB05.
- `repo://src/CanDoItAll.AgentFramework.Maf/CanDoItAll.AgentFramework.Maf.csproj` directly references only the allowed module boundaries `CanDoItAll.Modules.Security` and `CanDoItAll.Modules.Workspace`; direct Processes, Projects, and Workbench references are absent.
- `repo://tests/CanDoItAll.Tests.Unit/AgentRuntimeToolProviderArchitectureTests.cs` enforces Tooling isolation, MAF allowed module references, first-party provider projects referencing Tooling, and provider-neutral MAF source names.

## Decision Log

- Remain in MAF: model/client creation, workflow compilation/runtime orchestration, workspace tools, security-sensitive credential handoff, local MCP/A2A/capability composition. These are runtime orchestration concerns and not first-party product tool providers.
- Remain as direct MAF module references: `CanDoItAll.Modules.Security` for runtime security/credential boundaries and `CanDoItAll.Modules.Workspace` for workspace command/provider runtime integration. These stay allowed until a later security/workspace boundary extraction explicitly owns that split.
- Moved out of MAF: Processes tools, project-structure tools, and image-generation tools. Product tool creation now lives in owning modules and is attached by `IAgentRuntimeToolProvider`.
- Deferred to SB07: `ProcessAgentRuntimeToolProvider` remains large; the next subbundle owns its internal split so SB06 does not mix checkpoint validation with provider refactoring.
