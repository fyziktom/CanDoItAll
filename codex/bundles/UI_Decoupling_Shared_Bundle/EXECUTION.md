# Long-running execution without scope drift

## Start once, refresh on change

Record the current branch, HEAD/tree, worktree changes, relevant sibling revisions and build modes. Treat a reviewed SHA as provenance. Read current instructions and the child's complete scope; consult older bundles only for a specific dependency or regression. Do not load/re-execute the entire historical campaign at every stage.

Create one owned run directory outside sealed packages. Maintain a small `progress.md` containing current stage, feature rows completed/pending, changed interfaces, exact last builds/tests, active owned processes, unresolved decisions and the next executable step. Keep detailed raw evidence separate and sanitized. After compaction/resumption, reread this ledger, inspect actual git state and refresh the impacted source instead of starting the extraction again.

The source register is a navigation aid, not a complete reachability proof. Reconcile new, renamed, removed and untracked source, current routes, deferred children, `RenderFragment` factories, partial classes, DI and generated assets. Classify remaining native files by responsibility, not line count. Record any genuinely missed family before implementation; do not silently reduce the child scope.

## Work unit

At a checkpoint complete a coherent feature/owner transition: a bounded failing-first correction, a contract plus its consumer, a renderer family with real children, or a native integration. Keep production working throughout. Use temporary adapters or compatibility forwarding when justified, but track removal or permanent ownership explicitly.

Do not stop after the first repair, project creation, constructor split or green sandbox. Continue through the child's full stages. Do not create an artificial hierarchy or a separate approval request for each planned stage. Parallelize only genuinely independent source ownership and non-conflicting test outputs. Shared contracts, generated assets, parent state and native operations need a single integrating owner.

Build changed production projects, refresh the relevant test assembly, confirm discovery, execute the changed topic and update the ledger. Do not run broad Stable because a stage number ended. Preserve an earlier valid result only with a documented no-invalidation argument; never relabel an older failure as passed without a rerun.

## Bounded autonomy

Resolve ordinary implementation choices and small in-scope regressions directly. When an external prerequisite is unavailable, complete independent safe work, provide reproducible failure/prerequisite details and keep that proof blocked. A required unavailable browser/database/native effect means the corresponding readiness dimension is not complete. Do not switch to a different unrelated module or fabricate a successful mock as compensation.

A fundamental owner/API/schema redesign outside scope must be recorded with the smallest causal dependency and consequence map. Preserve the working function until that prerequisite is resolved. This exception does not excuse stopping at a routine refactor decision or asking for permission already supplied by the child.

## Checkpoints and delivery

Respect existing repository signing and commit policy. Stage only owned files; inspect staged changes. Preserve GPG-agent/pinentry behavior without exporting secrets, requesting the passphrase in chat, changing global trust, or disabling signing. A signing block does not prevent independent coding/testing; report it accurately and do not call an unsigned checkpoint signed. No push/merge/release is authorized by these packages.

Record the actual app/sibling/configuration pair for tested source and published output. A claimed sibling fix that is not present locally/remotely in the consumed pair is not delivered evidence. Rebuild affected outputs after a source/property change. Do not share ordinary application ports, retained databases, output folders or running processes with fixtures.

Finish with separate status for:

- Structural extraction and complete render closure.
- Native functional parity, security/authority and outcome semantics.
- Real browser and source/published asset proof.
- Measured development/performance behavior.
- Required frozen/broad integration gate and any remaining failures.
- Release/demo readiness, only when explicitly in scope and actually established.

A remaining host is not necessarily unfinished UI. A remaining in-scope native renderer hidden behind a slot is unfinished. A completed source refactor without required native/browser proof is a qualified checkpoint, not final task completion.

## Required signing checkpoints in PC2

[Signing and commits](SIGNING_AND_COMMITS.md) refines the earlier generic checkpoint rule. Request the local PGP unlock at entry. Establish the designated committer environment before substantial implementation. Commit after coherent tested changes throughout PC2; do not defer the entire series to one final `processes phase2` commit. If signing expires, retain work and request re-unlock without switching to unsigned commits or proceeding with an unbounded pending batch.

A tracked, sanitized final verification record must identify the tested source checkpoint, relevant siblings/configuration, exact filters and counts, results, missing proof, and commit/signature references. Detailed raw `.artifacts` data can remain ignored; its existence alone is not independently reviewable proof for a pushed branch. See [evidence template](templates/evidence.json).
