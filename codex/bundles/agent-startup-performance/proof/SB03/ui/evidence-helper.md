Repeat `--run-id` for at most 12 distinct runs. JSON is emitted to stdout only; the operator can redirect it into this proof directory. No application calls, HTTP, database queries, locks, recovery, process control or writes to source data occur.

The two execution roots are the already established native 5032 and client 5214 organization scopes. The helper reads only the exact requested run's `run.json`, immediate `logs`, `metrics`, `usage`, `approvals`, `audit/receipts` collections and its exact chat session record. It does not enumerate other runs. Every present run/agent/session identity is checked; nullable legacy usage attribution is explicitly marked. The session summary covers the current whole session and does not assign messages to a particular run.

Output allows GUIDs and bounded structured approval/call/tool identifiers, known enum states, UTC timestamps, durations, revisions, token/tool/message counts, approval states and auto-approval flags. Log phases use a fixed allowlist. Tool receipt outcomes are reduced to known labels; freeform failure details are removed and unrecognized text becomes `UnclassifiedRedacted`, never an inferred success. No message content, log messages, tool arguments, request summaries, filesystem destinations, provider/model strings, pricing details, environment values, prompt/context material, serialized state, approval notes or raw usage fields are emitted. Artifact contents are deliberately not opened.

Each source file is limited to 8 MiB; the whole observation is limited to 32 MiB and 1,000 files. Collections and session messages also have a 1,000-entry limit. Limit violations fail explicitly rather than truncating. Duplicate JSON keys, missing required fields, unexpected enums, invalid counts and identity mismatches fail without dumping source values. The helper rejects paths containing symlinks or Windows reparse points, and checks path containment beneath the frozen execution root.

Pending commit journals cause a refusal; the helper never triggers recovery. Before returning any JSON, it rechecks collection membership and every source file's content hash, then checks for journals again. This detects ordinary concurrent changes but is not an atomic snapshot and does not claim protection against arbitrary noncooperating filesystem races. Capture after the UI operation is quiescent. A stable waiting/nonterminal run can be captured and is explicitly marked as requiring a later terminal observation.

Metrics and provider usage observations are separate, potentially overlapping evidence. Do not add their counts together. A successful tool receipt is supporting persisted evidence; real tool execution, returned data, approval interaction and visible result correctness must still be established through the associated Playwright MCP run.
