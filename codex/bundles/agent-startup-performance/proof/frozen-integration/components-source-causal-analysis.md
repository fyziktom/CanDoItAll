Each removes the real `IWorkflowTestRunner` registration and installs a fake (WorkflowsPageTests.cs:1197–1205 and1365–1371). Both tests wait only for its presence before clicking (WorkflowsPageTests.cs:1212 and1378). `WorkflowCanvasEditor.document` initially contains `CreateDraft([])` (razor.cs:86), whose graph contains only Start/End and no project-structure executor or work node (WorkflowCanvasModels.cs:126). There is no readiness assertion for the supplied definition in these two tests.

After that initialization await completes, `OnParametersSetAsync` obtains executor descriptors and applies the supplied definition (razor.cs:210–227). It explicitly sets testResult=null and isPreviewInputDialogOpen=false (230–231). Therefore an initial click before this parameter pass can run the initial two-node draft. For the project test, Analyze sees no project executor and never opens the requested input dialog (WorkflowPreviewInputSupport.cs:61; RunPreviewAsync at847). For the progress test, its fake can set HadProgressObserver=true and return Succeeded, but the initial parameter pass later clears testResult. The attempted progress selection also has no work node in the initial draft. This ordering explains both missing-element symptoms without needing a failed provider or persistence call. It is a possible concrete interleaving, not yet a measured trace of either failing execution.
