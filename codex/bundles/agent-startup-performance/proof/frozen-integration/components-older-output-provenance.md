## Limits and interpretation

This is a scoped provenance and load-input audit for two controlled workflow-preview tests. It does not establish bitwise equality of every application assembly, audit every transitive application source document, compare generated IL, or prove the historical state of a running application. It does not freeze OS scheduling or PostgreSQL timing. Those limits do not require an assembly swap: the intact earlier output already has matching test/harness/UI sources, identical dependency identity/configuration, present runtime assets and matching templates for the bounded comparison.

No test, discovery, build, restore, provider call or application interaction was performed here; inspected target assemblies were never loaded for execution. Only metadata and file bytes were read. A repeated failure in this old output would support a pre-optimization reproduction under that measured condition. A pass would leave causal attribution unresolved and must not be treated as proof that the startup optimization is at fault. The two original candidate failures remain recorded regardless of follow-up outcomes.
