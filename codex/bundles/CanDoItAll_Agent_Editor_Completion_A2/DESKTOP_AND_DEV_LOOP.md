# Supported desktop and development-loop proof

**Primary: 1920 × 1080, 100% zoom, actual Chromium.** Optional second large viewport: 1600 × 1000
only when needed to resolve a concrete behavior. No phone/tablet or small/medium breakpoint tuning,
new responsive screenshot matrix or cosmetic redesign. Existing reusable library tests are not
removed or weakened; report a genuinely relevant failure without turning it into a tuning program.

Inspect actual usable geometry, full tabs, focus, keyboard/Enter, scroll ownership, complete menus,
confirmation nesting, close/reopen and visible footer. A text node in DOM or URL change alone is
not proof of a usable editor or completed server navigation. Preserve existing acknowledgement
probes and clean-circuit observations; do not increase timeout or sleep around every operation.

Measure the same representative edits before and after on an owned host: one core/A2 Razor text,
one pure presentation C# change and scoped CSS. Do not invent feature-owned JavaScript merely to
fill a table. If new JS is truly necessary, include import/reload/disposal proof. Record SDK,
source tree, sibling resolution, cold/warm state, three samples where feasible and limitations.
Measure independent sandbox separately from Web. No concurrent broad tests/builds during timings.

Record actual evaluated projects/packages and `dotnet watch --list` (or equivalent installed-tool
output) before/after. Restore probe bytes and verify hashes. A small graph supports isolated UI
work; it is not an automatic speedup promise for the whole product. Do not alter normal host
watching settings, use another instance's output DLLs or kill an unrelated developer process.

Standalone publish must run outside the source folder with production environment, no database
configuration and no module backend registration. Verify stylesheets/fonts/scoped CSS and all ten
real sections. Native path/driver/provider effects remain labelled simulations in that host.
