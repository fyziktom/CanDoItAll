## S0 and mutation semantics

S0 must first demonstrate the unsaved-before-Verify case. A passing clean-editor test is insufficient.
Verify configuration read-back is not a submitted configuration acknowledgement; prove unchanged
native fields, actual proof/version and retained local context. Exercise a competing canonical edit
and a read-back failure followed by read-only retry. If native receipt or adapter result changes,
build and run all of its actual caller/HTTP/serialization consumers and re-evaluate broad Stable.

Assignment on an existing agent remains the currently documented whole-draft Save. New-agent
assignment remains staged. Wizard creation, assignment, proof publication and secondary refresh are
separate effects: preserve exact committed identities, no hidden diagnostic/create replay and no
misclassification based only on a generic exception. Failed or unknown action states never become
confirmed merely by reloading a neighboring list.

## Full form, children and native preservation

Test pre-blur Unicode/Enter, nested invalid input, same/different section, Clear, two simultaneous
editors, template and managed-agent cases, out-of-order reads/confirmations and a reused public ID.
Exercise all six sections through real inputs, not only direct state mutation. Require native
round-trip and negative authority controls; preserve opaque extensions and another agent unchanged.
Metadata failure is not empty success. Stored missing/restricted references remain inspectable and
removable when the true owner allows it; no automatic widening to all current/future resources.

The full sandbox uses real Memory binding rows, external-root entry/list, Storage picker,
capability list and small confirmations. Fixture native effects are explicitly simulated and
committed fixture state is read back. Production tests separately prove host mapping and owners.
Display the true default-versus-explicit-None and saved-unavailable-provider cases from A1.

## Wider closure

Run the complete affected editor/command/adapter families once after the stages settle, then named
production journeys on the same source pair. Document the Stable decision using current repository
triggers. Registration-only additions and moved feature markup do not automatically need repeated
all-product sweeps; a native verification result or broadly used lifetime/protocol change may do so.
Never call an old checkpoint current after subsequent meaningful source changes without targeted
invalidation analysis. A failed checkpoint plus passing retry is not a new all-green checkpoint.

Final gates include evaluated references and negative controls, independent published sandbox,
large-desktop geometry, restored watch probes, documentation, safe-artifact review and the mandatory
portability-static no-write enforcement. Do not relax rules or alter scanner policy to pass artifacts.
The package utility validates package integrity only. [CLOSURE.md](CLOSURE.md) defines the human
semantic gate; [APPLICATION_JOURNEYS.md](APPLICATION_JOURNEYS.md) defines actual user/runtime evidence.
