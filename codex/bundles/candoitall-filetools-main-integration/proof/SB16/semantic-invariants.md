# SB16 Semantic Invariants

Date: 2026-07-13.

| Invariant | Required behavior | Positive evidence | Adversarial evidence |
| --- | --- | --- | --- |
| `SB16_INV_DIRECT_AUTHORITY` | A known Project Structure file opens from one current authorized `FileReference` and content source without creating a FileBrowser session. | Coordinator/direct-dialog tests and real raster/PDF/Markdown flows open exact current content. | Zero-browser spies remain untouched; missing authority exposes no unsigned fallback. |
| `SB16_INV_EXPLICIT_COMPOSITION` | Only selected built-ins, Markdown, and the host Mermaid adapter are registered. | Package graph and policy tests resolve the claimed profiles and modes. | Unsupported/SVG/archive inputs remain inert; no renderer discovery or service locator exists. |
| `SB16_INV_BOUNDED_CONTENT` | The host enforces a 16 MiB maximum before and during content reads. | Normal text/Markdown/Mermaid/raster/PDF open through bounded FileInteraction. | A 16,777,217-byte declared text file fails before source materialization and creates no editor/view/active element. |
| `SB16_INV_CONTROLLED_STATE` | View/Edit mode, dirty, saving, conflict, error, and close guard remain explicit and host-controlled. | Component and browser flows show Preview, Unsaved, Saving/Saved, Conflict, revision, and discard guard states. | Dirty/conflicting work cannot silently close; edit is disabled for read-only and unsupported types. |
| `SB16_INV_AWAITED_SAVE` | Save is awaited and acknowledges a revision only after durable write succeeds. | Unit, component, integration, managed log, API byte match, and revision 4 browser proof. | Failure/cancellation/overwrite denial preserve local content and dirty state; revision is not advanced. |
| `SB16_INV_DRIVER_CONCURRENCY` | The storage revisioned driver compares each requested expected revision with current storage truth. | Sequential saves accept the prior persisted revision; two-session rebase succeeds against the conflict-reported current revision. | The stale first attempt conflicts and exposes both explicit retry choices; removing expected revision still requires Overwrite permission. |
| `SB16_INV_HOSTILE_MARKDOWN` | Markdown never activates scripts, remote images, or JavaScript links. | Safe rendered Markdown and edit/preview pass. | Hostile input produces zero script elements, zero images/requests, zero JavaScript links, and leaves the sentinel false. |
| `SB16_INV_STRICT_MERMAID` | Mermaid uses the shared wrapper in strict mode with HTML labels disabled at both root and flowchart policy locations. | Browser renders SVG text with five text elements; Components hardening test verifies both configuration locations. | Final DOM has zero `foreignObject`, zero script, and no raw host markup/source action. |
| `SB16_INV_INERT_UNTRUSTED_TYPES` | SVG and unknown files expose metadata only; PDF limitations are explicit and browser-controlled. | SVG/archive fallback and governed PDF browser checks. | Hostile SVG cannot create image/script or execute; archive creates no active element; neither is editable. |
| `SB16_INV_NO_ROUTE_BYPASS` | Project Structure canvas/dialog never exposes or requests a managed/unsigned attachment preview route. | Canvas graph projects empty `MediaPreviewUrl`; final clean network has no failed/preview request. | Source scan finds no legacy route, iframe, video, audio, or raw image branch in the migrated path. |
| `SB16_INV_LIFECYCLE` | Content loads, edit runtimes, blob URLs, and authorized sessions are replaced/disposed exactly once. | FileTools replacement/disposal suites and host dialog reopen/restart flows pass. | Detached editor callbacks cannot mutate a replacement; closed sessions release exact handles. |
| `SB16_INV_LAYERING` | Optional UI/render packages stay in the outer Workbench/Web composition and never leak into Infrastructure or Integration. | Checked package/project graph and zero-warning Web build. | Integration/Infrastructure scans find no Workbench, Components, Mermaid, Markdig, FileBrowser coordinator, or service locator dependency. |

These invariants apply to the final SB16 coordinator, policy, explicit composition, Mermaid adapter, direct dialog, authorized save target, canvas projection, selected package versions, and their direct automated/browser proof.
