# SB17 Semantic Invariants

| Invariant | Claim | Evidence | Shallow-pass rejection |
| --- | --- | --- | --- |
| `SB17_INV_OWNER` | Large Razor owners orchestrate rendering and state only; scope, authorization, browser construction, content, save, cache, and interaction lifetime have focused owners. | Owner inventory plus the new sealed `ProjectStructureKnownFileInteractionSlot`; direct replacement/cancellation tests. | A merely passing UI test would not detect page-owned resource lifetime or superseded-session leaks. |
| `SB17_INV_DEPENDENCY` | The six new project-reference edges point inward and introduce no project cycle or forbidden backward module edge. | Reverse-path check is false for every new edge; Projects has no Workbench/Resources source/reference; Infrastructure has no FileTools edge. | A successful build alone would not reject a compilable but backward dependency. |
| `SB17_INV_INTENT` | Collection actions construct FileBrowser; direct Project Structure known-file open constructs FileInteraction with zero browser dependency. | Direct-owner browser scan is zero; runtime DOM has one interaction root and zero browser roots; network has no unsigned preview request. | Returning the same visual through a hidden FileBrowser session would fail the source, DOM, and network assertions. |
| `SB17_INV_LIFECYCLE` | Close, replacement, supersession, disposal, and completion/cancellation races release owned interaction sessions exactly once and do not leak or throw. | Slot tests pass 16/16 after the final race repair; final-source browser open/close/reopen succeeds. | Happy-path open alone would not exercise cancellation or close-versus-completion ordering. |
| `SB17_INV_PROCESS_OWNER` | Process-run root semantics are owned by Processes.Application and consumed by Workbench/Processes through the typed policy. | Removed Workbench policy has no live source; both consumers call `ProcessRunArtifactRootPolicy`; focused tests pass. | Duplicated path parsing in Workbench would fail the source ownership scan. |
| `SB17_INV_SCALE` | Existing structural budgets remain enforced after expansion cleanup. | Real 100,000-entry filesystem test is included in the 123-test unit run; page one returns 50 after 51 inspections with bounded continuation state. Resources and browser source counts remain capped. | A 50-row UI without bounded provider work would fail the structural counter test. |
| `SB17_INV_PERFORMANCE` | Changed expansion owners contain no blocking async, `async void`, per-call HttpClient, substring allocation, chained replacement, parameter-array, or unsealed implementation signal. | Standard scan covers 30 files/3,571 lines; zero hits for those categories; remaining bounded hits are reviewed. | Pattern counts without hit review would misclassify the static serializer options factory and bounded materializations. |
| `SB17_INV_BROWSER` | Projects, Project Structure collection browsing, Resources browsing, and direct known-file interaction remain coherent at 1440x900 with clean console/network. | Four current screenshots, accepted SB14 flow, direct dialog 1150/1150 and interaction 1071/1071 client/scroll widths, errors 0, warnings 0, Blazor endpoints 200. | A screenshot alone would not prove persistence, request intent, or absence of hidden lateral overflow. |
| `SB17_INV_CLEANUP` | Controlled browser projects, leases, files, and managed runtimes leave no residue. | Both project deletes return 200, current leases return zero-byte bodies, project lists omit IDs, filesystem residue scans return zero, and both runtime sessions stop. | Closing the browser without deleting server state would fail the API and filesystem checks. |
