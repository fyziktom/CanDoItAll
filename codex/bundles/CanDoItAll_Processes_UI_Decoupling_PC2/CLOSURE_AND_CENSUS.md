# Evidence closure and the next architectural decision

## One tracked, source-addressed summary

Write a maintained report such as `docs/validation/processes-ui-pc2.md` plus a small machine-readable summary if appropriate. Use current repository documentation conventions. Raw traces/logs may remain in a task-owned ignored directory; do not commit secrets, private files, connection strings, prompts/customer data, or absolute personal paths.

Include application source checkpoint and relevant tree/delta, public signed commit fingerprints and verified checkpoint hashes, actual consumed sibling revisions/dirty state, SDK/configuration/source mode, exact build/test filters, expected/discovered/executed counts, skips/failures, browser source/published Fast/Parity modes, isolated database major version and sanitized fixture identity. An unavailable artifact location or digest is not independent verification of its contents.

Differentiate:

| Dimension | Meaning of completion |
| --- | --- |
| Structural renderer decoupling | Active actual render closure is reusable and has no forbidden evaluated native dependency; legitimate route/admission/effect hosts remain |
| PC2 editor/operation correctness | F1–F3 fixed or current-source refuted with evidence; H1–H3 resolved; required direct regressions executed |
| Native authoring durability | Cross-scope/restart/catalog/publish/launch authority established through actual native owners; cannot be PASS while dictionary gap remains |
| Other native parity | Existing launch/workflow/files/cancel/chat/context/voice behavior validated on affected source |
| Browser/assets | Real interactions and required source/published modes work, with errors/geometry/cleanup checked |
| Portability / broader gates | Current mandatory enforcement and any triggered frozen/broad gates have exact results |
| Development loop | Measurements only for actual comparable samples; no universal speed claim from old or single observations |
| Release/demo readiness | Not automatically granted by this engineering assignment |

Do not flatten those dimensions into one green badge. Use PASS, FAIL, BLOCKED, NOT_RUN or a justified NOT_APPLICABLE per actual obligation. A completed source repair can be distinguished from unavailable runtime proof; a preexisting native durability gap remains visible.

## Active renderer census

Start from current routes/navigation/assembly discovery and actual callers, not every `.razor` file. Trace renderer children, typed slots, deferred `RenderFragment` factories, open overlays, shared component registrations, JS/CSS/static assets and evaluated source/package-mode graph. Use CodeAnalytics and inspect its blind spots.

For each candidate, record:

- Exact path and active route/call/render path (or evidence of dormancy).
- Responsibility: renderer, native state/admission/effect host, neutral contract, composition, compatibility code or unknown.
- Evaluated direct/transitive dependencies and any forbidden runtime/persistence/provider/module edge.
- Production and sandbox consumers, actual deferred children, and relevant proof.
- Conclusion: correctly placed; in-scope residual fixed; newly found separately scoped residual; or unresolved classification with the next concrete investigation.

Do not call all native hosts defects or measure completion by line count, number of interfaces/partials, or an injection grep. Do not delete compatibility code or build another sandbox without proving active responsibility. If no remaining active heavy rendering edge exists, report structural completion instead of inventing another module extraction. Keep non-structural native authoring debt and gate failures separately named.

## Commit/evidence ordering

Commit coherent tested source stages with verified signatures. The final maintained report may reference the last tested source commit; a later documentation-only report commit does not require retesting every unchanged assembly, but verify and document the relevant diff. New source/configuration/asset/sibling changes invalidate affected results and must be tested on the final consumed candidate.

A report cannot contain its own final hash before it exists. Record final report commit/signature in the operator-facing result or a later external ledger; do not fabricate a hash or start an endless amend cycle.

## Final handoff

State exactly what was corrected, what completed extraction was preserved, which signed checkpoints were created, which proof actually ran, which existing proof remained valid and why, and the actual unresolved native owner/gate statuses. Include the implementation-ready native-authoring prerequisite when needed. No automatic push/merge/deploy is authorized.

The next assignment is determined by the real residual map or the explicitly mapped authoring owner prerequisite—not an obsolete pre-PC1 list. Keep one active shared companion and do not copy it recursively into new children.
