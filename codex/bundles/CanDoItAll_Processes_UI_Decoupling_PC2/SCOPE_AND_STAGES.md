# Assigned work and signed execution stages

The stages are outcomes, not a rigid class layout or a mandatory commit count. Continue through every stage after its checkpoint; no new approval is needed for an ordinary in-scope design choice. Finish independent safe work when an external prerequisite is blocked.

## P0 — Entry, signing, drift and evidence baseline

Request local PGP unlock immediately and establish the verified committer environment. Read current instructions, PC1's maintained boundary record, testing/CI and the exact current dependencies. Preserve dirty/staged operator work. Record application HEAD/tree, siblings, source mode, SDK, configuration, owned ports and isolated PostgreSQL endpoint/major version without credentials.

Use CodeAnalytics discovery/index freshness checks on current source and form the affected-test union. Inspect renamed partial classes and real render/event paths. Reconcile any changes since the review; do not force the checkout back to the reviewed commit. Recover accessible prior raw evidence locally, but distinguish it from current source proof. Record inaccessible evidence honestly.

Deliver an owned progress ledger, finding status register, baseline feature coverage and selected test plan. Do not create an empty signing probe commit or spend a first giant batch without a verified signing path.

## P1 — Stable mutation ownership across reads

Implement F1 using the smallest local native-host mechanism. Cover definition, role, step, canvas and template-import command families; separate read sequencing, active mutation slot and immutable operation origin. Preserve current route/authority semantics and fresh selected projections. Do not migrate transport or native services into Processes.UI.

Demonstrate pending command + same-opening read in both completion orders, multiple command entry points, rejection and unknown outcome, accepted-with-readback-failure, actual scope/profile/definition/opening retirement and disposal. Keep harmless typing/tabs available. High-frequency canvas intents must preserve/coalesce their latest intended geometry according to existing semantics rather than silently dropping actions through a blanket busy guard.

Build and run the owning regressions; create one or more signed verified logical checkpoints including tests. Do not stop here.

## P2 — Identity-complete draft and selection reconciliation

Implement F2 and F3; test H1/H2 and correct only demonstrated violations. Capture the edited step's hidden decision-role identity; adopt authoritative Add/Delete selections only for the eligible origin; clear deleted state, and preserve later user selection/typing. Preserve raw validation, per-row identities, template targets and accepted assigned IDs.

Use real renderer interactions plus focused native-host tests. Include two independent openings and tab unmount/recreation. Recheck workflows, operation policy/bindings and authorized role defaults; no destructive metadata fallback. Commit coherent tested fixes with signatures verified.

## P3 — Native authoring lifetime and bounded owner prerequisite

Execute AUTHORING_OWNER_PREREQUISITE.md. Establish the actual state across **separate client scopes**, not one reused service or an echo fake. Trace catalog/editor/role/step/template/canvas/definition publication/launch consumers, admission, profile generation and version handling.

When an already-established durable authoritative owner exists in the current checkout and the failure is a bounded adapter/lifetime bug, integrate that owner, preserve contracts and add real read-back tests. Do not add singleton mutable state, UI persistence or credentials to the renderer.

When the source still matches the reviewed dictionary/template model, deliver the specified implementation-ready native-authoring design, migration/data compatibility analysis, files/consumers/test map and a reproducible baseline. Do not silently start a new schema or redefine Publish/Launch within this UI assignment. Keep durable-authoring readiness unresolved. Complete P4–P5 even when this prerequisite remains separate.

Commit the sanitized prerequisite/design and any separately justified bounded repair with evidence. Documentation is a deliverable here, not a substitute for P1/P2 implementation.

## P4 — Native/browser/asset validation and nonregression

Run discovery-backed impacted tests and the required PC1 floor. Drive real browser input, role Add/Delete, non-first-step Save, tab/refresh during pending commands and two openings. Preserve the real native launch→workflow→chat→files→cancel journeys and existing Workbench/voice consumers when affected. Separate deterministic inference fixtures from external-provider proof.

Validate Fast/Parity source and published sandbox assets using current mode-specific build outputs; real children, dialogs, canvas, charts, Mermaid and files must work. Check actual behavior after deployment/publish, not just HTTP status. Leave ordinary app instances, ports, databases and resources untouched. Record owned fixture cleanup and errors.

Do not spend external inference money, request real user credentials in tests or access retained user data. Do not commit raw traces/screenshots with sensitive contents. Commit any test/asset fixes with verified signatures.

## P5 — Semantic census and pushed-source closure

Perform the active renderer/deferred host/asset and evaluated dependency census in CLOSURE_AND_CENSUS.md. Preserve legitimate native adapters; fix only proven in-scope residuals. Do not invent a new module task from a file-count scan.

Execute the current mandatory portability-static enforcement. Run the broader stable gate only for a current named invalidation trigger or frozen closure boundary, once on the coherent source after targeted fixes; keep unrelated environmental failures classified. Refresh invalidated proof after any relevant code/configuration change.

Commit the final sanitized source-addressed summary, source/owner decision and residual map. Confirm every assignment group, every signed checkpoint, actual uncommitted delta, dependency pair and readiness dimension. The final documentation commit may reference the last tested source checkpoint; verify that intervening changes really are documentation-only. No self-referential commit hash is required inside its own file.

## Completion boundaries

- P1/P2 correctness and their required validation are mandatory implementation, not optional planning.
- All PC1 feature families remain preservation obligations.
- P3 must produce an actionable native owner outcome, not a vague TODO or an unproved claim of durability.
- Structural completion, local editor correctness, actual native durability, browser/assets, portability and broad closure remain separate.
- A signing block pauses further dependent implementation at a coherent checkpoint; no unsigned workaround.
- PGP/pinentry interaction and genuine missing external prerequisites may require the operator. Stage transitions within this plan do not.
