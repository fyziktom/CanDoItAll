# What this bundle completes and what still remains

WB1 Planning, WB2 Insights and WB3 Structure are bounded completed rendering families.
WB3's published main requires its actual tested Components pair; remote availability is a
separate delivery qualification, not permission to recreate the earlier fixes.

WB4 completes content creation, file collections and direct interaction, generated-content
presentation, Progress Summary/exports and transcript actions. Do not declare the entire
Workbench complete merely because its main route is now a composer of several UI libraries.

| Family after WB4 | Remaining behavior and proposed next scope | Relative complexity |
|---|---|---|
| Participant/meeting/directory assignment | Full reusable participant sync, quick create, meeting defaults/pickers, exact assignment and metadata result handling. Existing CRM/HR owners remain. | 4/5, one coherent follow-up family |
| Protected secret references | Real chooser and create-and-use form, no automatic value read; exact secret save vs project link vs readback. | 3-4/5, can be staged with the above if dependencies stay independent |
| Runtime/terminal/web preview | Existing launch modes/capabilities, exact started handles, stop/close distinction and actual previews. | 4/5, bounded native effect family |
| Workflow/Process integration dialogs in Workbench | Definition/version choice, inputs, launch/review/assignment, progress and exact recovery. Not a new Workflow/Processes engine. | 4-5/5, dedicated native integration slice |
| Processes product module | Catalog/definition, launch/approval, live management, file/recovery surfaces. | 5/5, last large module, multiple validated slices |
| Final Web/shared closure | Actual remaining renderer census, dashboard/capability integration and distribution readiness. | Scope by real callers, not all Razor removal |

These are architectural estimates, not duration estimates or fixed project/commit counts.
After each real extraction update the current caller/child/asset map and classify legitimate
route/effect hosts separately. Do not manufacture a missing UI because a service/API exists.

Preserve every deferred entry from toolbar, node action, double-click, specialist composer
and nested dialog. A target-bound slot is valid; a fake sandbox placeholder is not evidence
that the corresponding native workflow passed. Keep native secret and file authorization,
party assignment semantics, runtime ownership and process admission. Do not reimplement them
inside Content.UI or have a deferred backend callback obtain the current page's new target.

S22 confirms that participant/meeting work is substantial: reads already capture context,
but quick-create, assignment replacement and metadata follow-up still have their own effects.
This review did not behaviorally certify those deferred paths. Keep them on the roadmap rather
than labeling them completed because they still open successfully.
