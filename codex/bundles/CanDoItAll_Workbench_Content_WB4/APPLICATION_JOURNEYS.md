# Application journeys: real owners behind actual controls

The scenario sandbox demonstrates the renderer, not the application's authorization or
persistence. Final proof combines both and uses only task-owned resources. A deterministic
provider reply is allowed; fabricated native receipts, hidden SQL writes to force a state,
disabled approvals or unrestricted grants are not.

## A. Operator text and original target

Create a project through existing Projects UI, use WB3 toolbox/context action to open the
actual text dialog, create supported text and upload a separate valid file. Verify actual
node identity, original parent/lifetime, storage record and bytes. Test invalid JSON/raw
inputs before any write, keyboard submit and normal cancel. Preserve exact unrelated rows.
Execute S0's native retired/recreated target cases and ensure the same ID does not reauthorize
an old dialog. Controlled barriers must reach the real writer; no sleep-only race tests.

## B. File collection and direct editable content

Open the project collection and a specific eligible node collection through actual toolbar
and Selection. Verify include-subprojects changes only its intended scope, source identities,
search budgets, partial indicators and actual list data. Search must not trigger Save or
content loading for every result. Open A, then B with a held/cancel-ignoring A result; B remains
correct after A's success/error/cleanup. Close/remount while opening a source, two windows,
old button and source-revision replacement are required counterexamples.

Use a native editable file target through direct attachment preview. Capture initial bytes
and revision, edit/save, verify the returned revision and bytes through an independent owner
read. A second editor with the old revision receives the real conflict and cannot overwrite.
Exercise pending-save close, dirty discard, failed save, read-only storage, invalid/expired
handle and unrelated file. Preview returned from collection browsing remains read-only.

Decode actual downloads and compare hashes. Releasing the original access must prevent its
reuse while another independent valid access remains usable. Test preferred-app/folder
commands through the real authorized native action on a suitable desktop host with a harmless
owned executable/root. No clipboard success, signed-link label or toast substitutes for bytes.

## C. Stored summaries and diagrams

Open Progress Summary on a subtree containing dated and undated rows. Change one explicit
status and independently read it back. Export XLSX and Mermaid through the actual buttons:
these create native file nodes. Decode the workbook and diagram from their governed content,
compare accepted rows/root/date basis, and prove exact new IDs plus unchanged neighbors.
Capture a canvas image for the original viewport, store it and verify decoded image content.
Test fault after creation but before refresh; Retry does not create another asset.
A legitimate legacy Mermaid specimen stays safe and distinct from stored .mmd content.

## D. Image placeholder to actual stored output

Use native image driver metadata captured before test customization, preserving original
bootstrap identities. Publish a supported saved profile and import into both owned clients.
Verify UI labels against the source catalog, including the configured default and a permitted
nondefault; actual requests retain opaque routing IDs. Use distinct deterministic image bytes
for the two selections and observe original upstream model/capture count, not only UI options.

Trigger a single generation explicitly. Observe placeholder identity, accepted queue handle,
worker execution and native media replacement; preview/download the final bytes. Reject bad
settings/purpose/disabled source before dispatch. Hold generation while retiring the original
project/node or switching the view; no replacement target receives output. Test failure after
placeholder, after external response and during native replacement. No automatic fallback,
resend, new operation ID or cleanup that hides an already committed placeholder is permitted.
Restart behavior reflects the existing in-memory queue honestly; it is not a durable-replay test.

## E. Transcript and explicit disclosure

Create a recording-related transcript scaffold without speech invocation. Attach a known
synthetic transcript through its supported native path, then open each existing analysis
action and explicitly select its provider. Cancel performs no provider call. Confirm captures
exact content/action/origin once; read canonical result fields/references and History metadata.
Hold provider completion across a new dialog and a concurrent transcript edit. Preserve the
native conflict and no-second-request evidence after persistence/readback failure. Generated
analysis does not silently create tasks; assertions count text outputs and graph nodes separately.

## F. Actual Agent over Project Structure

Use a UI-created project and a specifically configured saved Agent. Read a canary whose bytes
are unknown to the model prompt, create a bounded file with registered tools, approve only
its exact project/node/path/overwrite/content proposal, and attach/read it through native
Project Structure. Deny a separate proposal and verify no write. Compare canonical content,
node IDs, tool receipts, native preview and actual download hash. An assistant message saying
it created the file is not evidence. The new Content UI must show the same accepted object.

Keep original tool schemas and authorization. The proposed File/Project access is narrow;
neither fixture helpers nor model requests may receive all projects/all storage. A fixture
adapter can script external inference, not native tools or owner results. Record accepted
proposal/run/session identities before a UI assertion so continuation does not repeat effects.

## G. Neighbors and source/two-client fixture

Reuse the established shared-provider runner only on a newly owned, isolated source/two-client
fixture. No reset of retained work or the ordinary app at 5032. Record every image and canonical
DB/volume identity. Test native default/nondefault routing, image bytes, no personal fallback,
source retire/unavailable, expected denied content and History caller identity.

Run relevant saved Workflow accepted/incomplete output cases, and use Scheduler with an enabled
finite plan through restart plus one future neighbor. Open WB1 Gantt/task editor and WB2 Summary/
Activity/Signals, actual runtime Usage and History after the governed content journey. An index
may legitimately be partial; if native maintenance is required, invoke only the existing
explicit command in the owned scope and hash canonical evidence before/after. Do not seed
fake totals or remove the incomplete assertion.

Do not automatically replay all 19 protocol vectors before each phase. After final production
changes, run the affected consumer/image/authority vector set and document any unchanged
carried vectors by exact input identity. If shared provider/transport contracts change, rerun
the appropriate full protocol lane. Content changes never justify weakening the existing
source-name/opaque-ID parity oracle.

## Evidence handling

Record exact source pairs, pre-run DLL hashes, discovery, command, image inputs, accepted
native identities and private artifact references. Inspect desktop screenshots rather than
assuming DOM presence means visibility. Preserve every failed attempt. A later successful
continuation can establish remaining assertions but does not turn the earlier full test green.
Do not repeat accepted provider or file actions just to regenerate a cleaner screenshot.
New paid calls are forbidden. Private content/keys and full logs stay outside tracked files.
