# Execution and closure rules

This package is a boundary and behavioral specification, not a mandatory internal class
layout. Implement the smallest coherent solution consistent with current repo standards.
Use the full documents; the prompt is not permission to omit a difficult native path.

## Stage order

S0: inspect current source pair and retained evidence; arrange signing; reproduce and repair
WB4-T1 with actual native owners. Avoid rerunning all unchanged WB3 proof at entry.
W1: complete text creation/upload renderer and owner seam, independent and native tests.
W2: complete collection and direct known-file interaction including all shared children.
W3: complete image generation presentation/original queue target, Progress Summary exports,
transcript actions and Mermaid variants.
W4: final caller map, dependency boundary, publication/watch, native consumers and signed closure.

Do not stop after S0, a new project, one modal or a cosmetic browser pass. Every declared
in-scope family needs real production integration. If one path has a genuine protocol blocker,
keep it visibly incomplete, preserve its safe older implementation, and continue independent
safe work. Never claim complete WB4 after mapping a still-blocking wrong-target write.

## Scope of repair

Fix small reproduced UI/host lifecycle, projection, input, state-ordering and narrow native
identity/result defects with counterexample tests. Log root cause and whether it predates
WB4. A known defect discovered in an old deferred file path is not automatically caused by
WB3. Larger schema/authority/durable-protocol issues get exact call/commit diagrams, affected
consumers, realistic reproducer, safe containment and a proposed corrective bundle. Do not
start an unrelated general framework or weaken native checks to meet a completion label.

## Verification cost and trustworthy evidence

Read current docs/testing.md and CI before edits. Build changed production projects first,
then refreshed owning test assemblies, exact filters and expected/actual discovery counts.
Use broad topic filters only where that topic genuinely owns the change. No unfiltered suite
simply because a phase finished. --no-build is valid only with fresh verified assembly inputs.

The final native target/queue/file authority changes may justify one broad Stable checkpoint.
Decide with actual changed contracts, native owners and shared test/CI memberships after
implementation stabilizes. If not justified, document why focused proof covers the delta;
that is a test-scope decision, not a secretly omitted required lane. Browser, Docker, live
and special host tests remain distinct from Stable. No paid inference is authorized.

For each attempt retain pre-run source/compiled-input fingerprints, image inputs, command,
filter/discovery, counts, duration and private artifact paths. Store expected-vs-observed
native identities/bytes and independent oracle derivation. Do not relabel a failed run after
a later individual retry. Do not sum overlapping filters as unique cases. Never mutate a
historical test control, truncate a scan or loosen an assertion just to obtain green output.

Observe accepted writes before retrying a failed UI step. Extend path/encoding support only
in validation IO when warranted; preserve original bytes and distinguish supplementary scans.
A stale selector can justify a test fix only after native evidence proves what already happened.
No automatic maintenance/migration on normal user databases or source-provider fixtures.

Portability-static is mandatory under repo rules, including reviewed baseline deltas and final
enforcement without --write-baseline. Document source/delta secret review separately from any
whole-checkout scan. Current passing documentation/API/schema tests are required for moved
public values and owner contracts. Do not label all data or all logs clean by inference.

## Evidence schema and permitted qualifications

Use an external private copy of templates/evidence.json. G00-G35 are coverage groups, not a
mandated number of tests or files. PASS references actual passing attempts. A test PASS has
positive exact discovery/execution counts, no failure/skip and explanation for theory expansion.
The Python validator checks structural consistency only and cannot prove execution.

Only G28 (measured development-loop tooling limitation), G33 (broad-scope decision or original
mixed broad outcome with complete disposition) and G34 (whole-checkout historical scan
qualification) may close QUALIFIED, with explicit notes, referenced evidence, limitation and
reviewed rationale. Every functional/native security group must pass. G34 still requires
portability enforcement and current introduced-source security review to pass; a failing
required gate cannot be excused by its qualifier. Any untested original-target, save grant,
wrong content or unsafe replay path remains a blocking finding, not QUALIFIED completion.

Closure includes final source pair, coherent verified signed commits, all in-scope boundaries,
original text target proof, real content authority, native consumer proof, static gates and
security review. Record remote dependency availability separately; verified local-only delivery
permits bounded next-slice development but not a claim of reproducible remote/release readiness.
Set no all-suite/release-ready Boolean to true merely because this package's checker succeeds.

## Final handoff

State implemented renderers and retained native owners; exact remaining Workbench families;
all code fixes and their first failing counterexamples; actual builds/tests/source pair;
source/published assets; measured watch behavior and its limits; original failed attempts and
follow-ups; signed commits; and any unresolved blockers. Stop only owned hosts after preserving
fixtures/evidence. Never clean historical bundles or other developers' resources for a clean status.
