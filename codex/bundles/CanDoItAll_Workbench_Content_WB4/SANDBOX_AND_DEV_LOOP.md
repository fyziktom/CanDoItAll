# Independent sandbox, assets and development-loop proof

Mount the exact production Content components in an independent host without Workbench,
Foundation/EF bootstrap, provider implementations, real vault or storage drivers. Explicit
scenario sources may provide safe synthetic data and controlled completions. They do not
stand in for native proof. Reuse actual FileBrowser/FileInteraction and shared composer/input
children, not screenshots, mocked components or hand-made lookalikes.

Require source Fast/Parity and independently published host evidence. Test two simultaneous
openings, loading/empty/unavailable/failure, invalid input, current and stale revision,
read-only and editable targets, pending/unknown/partial effects, superseded operation and
actual close/cancel behavior. Generated image state includes placeholder and queue states;
transcript setup includes explicit confirmation without real outbound traffic.

Evaluate the full dependency closure rather than scanning only @inject in the root Razor.
Record allowed graphs at entry and final: WB1 Planning, WB2 Insights, WB3 Structure, Agents,
Workflow/Provider/Workspace/Projects plus their preserved sandboxes. Reject unresolved or
backend edges and new reverse references. Public moved types preserve namespace, serialization
and actual assembly lookup/type-forward compatibility as appropriate. Test API XML/schema
coverage for moved public values; copy of comments without emitted documentation is insufficient.

At 1920x1080/DPR1 inspect actual canvas/window/form/menu geometry, scrolling, keyboard focus,
footer reachability, stacked overlays and all relevant actions. Do not spend this run on
small/medium screens, tablet/mobile breakpoints or broad visual redesign. Existing shared
responsiveness tests are not removed, but no new responsive-tuning campaign is requested.

Capture relevant JS/CSS/font/assembly content hashes for source/published/native hosts. Raw
byte equality and decompressed equivalence are separate results. Load existing shared assets
once in the intended order; feature CSS moves with its renderer, not hidden in the old route.
A fixed Node/assembly count is an observation, never a target that permits fake children.

## Measured watch cycle

Record SDK, OS, all source refs, evaluated graph and watch files, build/start conditions and
actual process identity. Perform three reversible edits per changed owned kind: Razor, C#,
scoped CSS and JS where the feature owns JS. Observe real text/runtime state/computed style/
served behavior, not only console success. Restore every probe byte-for-byte and observe
restoration. Record automatic navigation, manual navigation and process restart separately.

WB3's CSS insertion/removal limitation remains a known qualification. Confirm current local
behavior; repair a small misconfigured path if proven. Do not silently substitute restart
mode and call it hot reload. A reported same PID does not prove every browser change applied
in place. Sampling delay and first/warm samples must be stated; do not promise a universal
speedup without a controlled equivalent baseline. No speculative SDK/build-system overhaul.
