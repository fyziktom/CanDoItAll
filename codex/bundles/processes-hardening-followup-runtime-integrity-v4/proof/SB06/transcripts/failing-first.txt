# SB06 Failing-First / Red-Team Proof

Old workflow failure mode: workflow artifact projection selected process expectations by artifact kind, then title/name/summary similarity. With two same-kind workflow artifacts, a misleading artifact name could map the wrong workflow output to the wrong process expectation.

Old subprocess failure mode: subprocess parent projection selected a child artifact by kind, trust, title, and recency. With two same-kind child artifacts, a child artifact with the parent title could be selected even when it came from the wrong child expectation.

Red-team scenarios added for SB06:

- Workflow: two `Deliverable` process expectations and two JSON workflow artifacts swap names versus node ids. Explicit `workflow-output-id` metadata must select the node id, not the misleading name.
- Workflow: the same two-artifact shape without explicit output ids must return no expectation and report an ambiguity diagnostic.
- Subprocess: two child deliverables have conflicting titles versus child expectation ids. Explicit `subprocess-child-expectation-id` metadata must select the mapped child expectation id.
- Subprocess: the same two-child-artifact shape without child mapping must return no source artifact and report an ambiguity diagnostic.

Focused command:

```powershell
dotnet test tests/CanDoItAll.Tests.Integration/CanDoItAll.Tests.Integration.csproj --filter "FullyQualifiedName~SB06_INV_001" --no-restore --no-build -v minimal
```

Expected old result: the misleading same-kind/title artifacts would be accepted by heuristic ordering.

Current guarded result: explicit mappings select the intended artifact, and unmapped ambiguous cases return no projection with diagnostics.
