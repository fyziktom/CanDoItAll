# Execution, evidence and completion

## Stage order

Entry: actual source/dependency/signing/fixture preflight; read canonical current rules. S0: reproduce and close Scheduler startup and preview-attempt attribution. A1: full current caller/renderer census. A2: shell/Usage. A3: runtime/floating adjuncts. A4: already-isolated settings/SimpleChats verification and residual closure. A5: final source/publish/native/multi-instance/watch/static evidence and signed delivery. Do not end after S0 or the first renderer.

Each stage directly builds affected production projects and uses exact owning test filters. State expected discovery before execution and run build-backed `--list-tests` for new/changed filters. Zero/unexpected discovery invalidates evidence. Dynamic expansions are accounted by exact method/theory identities, not a vague larger count. `--no-build --no-restore` only after the owning assembly matches the tested source.

Evaluate one final broad Stable checkpoint under current named invalidation rules, especially the native Scheduler change and public UI/solution changes. Do not run Stable after each phase or automatically replay old suites before source work. Browser/process/Docker lanes are separate from Stable and must be named honestly. Keep original failed attempts, per-assembly counts and scope. Later focused repairs do not rewrite an earlier mixed full run. A qualified historic baseline may remain with explicit reason; unresolved product blockers cannot.

## Small and complex findings

Repair small reproduced field/lifetime/asset/adapter/harness defects directly with regression tests. The two assigned S0 findings are already implementation work, not another mapping-only assignment. If a discovered issue changes schema, cross-owner authority or a durable protocol, map original/current graph, exact interleaving and persisted effect before redesign. Stop the unsafe mutation path, preserve evidence and continue independent safe work. Never claim completion while a new wrong-target/data/authorization/startup defect remains.

## Static and secret scan closure

Read current `portability-static`, inspect every added/stale item, fix genuine defects, update only reviewed intentional baselines and require final enforcement without baseline-write mode. Preserve hostile-data, authority and unresolved-reference negative tests. No deleting tests or weakening discovery/guard assertions to reach green.

Retained historical bundles and synthetic negative-control artifacts are not automatically new secrets. Preserve originals and classify scanner scope. Record full-worktree result separately from a source-only or changed-line pass with an exact manifest/hash. Never call a failing full scan clean because the delta scan passed. Do not generate credentials into public discovery/report artifacts.

## Final outputs

Maintain an external evidence ledger, raw private artifacts, safe summary, complete updated renderer census and dependency graphs. Record every current renderer's real caller, destination, legitimate host and sandbox/native proof. No unreachable screen invented from a historical API name. No full form hidden in a supposedly thin host.

Update current `modules.md`, module/UI/sandbox READMEs and test instructions, but preserve sealed historical packages. Declare completion of the **presentation boundary** separately from delivery and general release readiness. The next recommended large domain is Workbench (start with bounded calendar/task/read views), then its Structure/cross-owner parts, and Processes last. This run does not start those modules.

The included package checker verifies hashes, local links, source identities and evidence structure only. It cannot prove that TRX or screenshots are genuine or that a referenced test actually exercises the contract. Independently review proof relevance; one unrelated passing test must not certify every group. Do not alter the sealed template; copy it outside the package for execution.
