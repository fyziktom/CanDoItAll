# Sequential review checkpoints

| Gate | Required review before next stage |
|---|---|
| Preparation | Source-backed adjudication, complete traceability, current dependency/consumer map, explicit future RED, documentation-only drift check, links and manifest. No runtime closure claim. |
| G00 -> G01 | Exact compiled RED versus characterization; current source/SDK/sibling/asset freeze; missing-ID page echo adjudicated; choose one minimal read seam; agent/run/context product decisions fixed. |
| G01 -> G02 | Independent target/list/detail lifetime and callback ownership; public negative tests green; actual registered DB reads; no generic framework or expanded backend responsibility; old panel read state removed. |
| G02 -> G03 baseline | Controlled real surface is service-free; host contains integration effects only; both actual child consumers inventoried; real Module browser states reviewed; no source movement yet. |
| G03 baseline -> movement | Current source/fixtures/assets and nine supported edit predicates frozen; fresh full-app cold/warm observation valid; no unresolved asset or public-compatibility blocker. |
| G03 closure | Actual moves/old absence, no wrapper/copy or reverse edge; evaluated graph and real second-consumer builds; Parity/Fast rendering, comparative timing/restoration/process receipts; exact tests and static/evidence gates. |

At every stage review actual dependency direction, constructor obligations, partial-class responsibility, direct test seam, public contract exposure, old-class shrink and remaining callers. A number of files, interfaces, members or test cases cannot pass architecture. Require direct proof of removed responsibilities and behavior preservation.

Before declaring a future child closed, write its architecture/QA review, uncertainty, scope, evidence and next-stage decision. Do not silently advance on a pending/failed gate. Historical documentation debt is separately tracked; it is not a passing documentation or merge gate.
