# SB13 Semantic Invariants

- `ProcessWorkspaceShell.razor` loads route state only through `IProcessWorkspaceProjectionClient`.
- The Process UI module depends on projection/application contracts, not runtime internals or persistence implementation types.
- `/processes` and `/projects/{ProjectId}/processes` render the same projection-first shell with different typed scopes.
- `runId` query selection activates the live-runs tab without querying runtime state from the UI.
- The command strip exposes refresh, agent context, definition, launch, and live-dashboard commands with disabled command reasons where later bundles own behavior.
- Refresh sets an explicit `RefreshRequested` projection status; missing projection-store integration is visible as `ProjectionStoreUnavailable`.
- Agent context entry points are generated by typed application projections and navigate through a context key, not legacy runtime services.
- The shell navigation contributor adds the Process entry through shared navigation contribution contracts.
- App startup migrations no longer fail on stale legacy Process AppDbContext snapshot state.
- AgentFramework startup receives an explicit Process runtime evidence provider that fails predictably if invoked before process runtime evidence is deployed.
