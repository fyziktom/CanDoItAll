# Execution stages and truthful closure

| Stage | Required result | Appropriate commit |
|---|---|---|
| Entry | Inspect current inputs and signed S0; native signing ready; retain evidence and histories | No empty commit |
| R1 | Deterministic/native local-draft concurrency repair and positive controls | Bounded fix + tests |
| PP2a | Real Sharing children and confirmations extracted/wired/tested | Cohesive renderer/seam |
| PP2b | Complete sources/discovery/refresh + independent sandbox | Cohesive complete source family |
| Final | Rebuilt final three-app image, protocol/UI/native consumers, final Stable/static/watch evidence | Validation/harness + maintained docs |

Combine stages only where independent compilation would be artificial; do not stop after one stage
and label all PP2 complete. Final code change after tests requires explicit invalidation review.
The original 38 groups remain; the 39th adds PP2C-R1. Fresh template states are NOT_RUN.

## Evidence classes

1. Source inspection: supports a hypothesis, boundary or code change; not a test result.
2. Historical implementer report: credits S0 with its recorded hashes/outcomes; raw artifacts must
   be inspected when available and are not presumed independently verified by this review.
3. Current execution: build/discovery/log/TRX/image inputs, outcome, native read-back and failures.
4. Package tooling: checks format/consistency only, never product correctness or provenance authenticity.

## Closure flags

`pp2_rendering_complete` requires both real Sharing and source/refresh renderers plus their census.
`independent_sandbox_validated` requires source AND standalone published renderer proof.
`final_multi_instance_validated` requires final-source protocol, native-default and current consumer
proof, not historical S0. `local_settings_concurrency_resolved` requires the new native regression.
`signed_delivery_verified` requires locally verified intended commits and an exact compiled source pair.
`pp2_complete` requires all mandatory current groups and gates, with no unresolved relevant product
blocker. `all_provider_ui_complete` and `application_release_ready` remain false.

A real missing environment/key block must be reported with its exact unperformed phase. Do not
force PASS by deleting tests, removing negative controls, ignoring denied calls, disabling gates,
changing production policy for fixtures or relabeling old results. Fix small causal defects in this
run. New complex changes to authority/schema/owner protocols need a call graph, minimal reproduction,
actual effects, baseline/current comparison and a separate safe repair scope; affected work stays blocked.

A historical S0 signature is not the signature of new uncommitted code. A final metadata-only commit
may cite preceding tests only after proving no executable/asset/test input changed. Preserve raw
failed attempts, source snapshots and cleanup failures, export only explicitly inspected safe data.
Keep all task-owned cleanup exact; ordinary apps and unrelated volumes/processes stay untouched.
