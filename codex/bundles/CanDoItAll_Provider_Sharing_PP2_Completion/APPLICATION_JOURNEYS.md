# Required native and application consumers after extraction

These are completion requirements inherited from the original PP2 assignment, not an additional
module-refactoring scope. Only external upstream responses may be scripted. Product owners,
approval, routing, persistence and user-visible actions remain real.

## Provider and selector paths

In final containers create/save/publish native providers through PP1/PP2, import into both clients,
and inspect source/client labels with an independent catalog oracle. Verify actual tooltip/
accessibility text, default wrappers, selected opaque option values, recommended and saved
unavailable choices. Local provider aliases can legitimately differ from remote display names;
model names must still correspond exactly. Open first/second editors cold, switch A-B-A, save and
reopen. Do not claim parity from only the provider panel when Agent/Simple Chat use different mappers.

## Agent and Project Structure files

Select an imported provider/model in the actual ten-section editor and save through its owner.
Use an isolated project/node and agent with narrow file permissions; preserve unrelated config.
Through actual chat UI read an existing file whose canary was not supplied in the prompt, propose
creation of a harmless new file, and process approvals only after checking exact tool, project,
node, relative path, overwrite and content/attachment source. Exercise an explicit denial too.
Verify recorded run, approvals, tool arguments, new native identity, metadata + content read-back,
UI preview/download bytes or hashes and unchanged unrelated content. Do not infer success from an
assistant completion message. Confirm ordinary history/deletion only where current policy allows.

## Simple Chat and Workflow/TestLab

Create a definition through UI, choose an allowed non-default imported model, save/reopen, start
a conversation and obtain a completed native message/transcript. Assert exact provider and model,
not a user-typed echo. The default path and unavailable saved-choice path are separate controls.
Run a real saved Workflow using that shared provider and a matching TestLab/evidence path. Check
immutable definition/input identity, terminal status, output and downstream persistence. Preserve
the negative case HTTP-success with incomplete model output; do not lower output validation to pass.

## Image/vision and history

For supported publications produce and read actual image bytes from the deterministic upstream,
validate media type and stable artifact identity/hash, and pass a known harmless input through the
supported vision path. A three-byte placeholder transport response is not image viewer/content proof.
Unsupported native features stay explicit refusals; do not implement them in this refactoring.

History remains its current host. Exercise provider/global lazy queries over the same requests,
caller-key separation, pagination/filter changes and authority denial. Use exact private fixture
identities. Existing history helpers replace credentials and delete prefixed fixtures: never point
them at a real retained instance. Do not export private history contents or credential material.

## Neighbor and host behavior

Run impacted PP1/A2, Workspace/API, Storage selection, Projects/Files and Resources tests; key
journeys must preserve actual identity, file authority and independent draft state. Check source/
client server logs, browser console/request failures, dialogs, focus/scroll and circuit teardown.
Expected disconnects must be bounded to their initiating action; never blanket-ignore errors.

Use large desktop 1920x1080. No mobile/tablet tuning. These deterministic executions are not paid
live-provider evidence; paid lanes remain outside the authorized task and are not falsely green.
