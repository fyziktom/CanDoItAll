# PP2 completion validation matrix

This matrix names required outcomes, not immutable test names or counts. Locate current owning
tests through CodeAnalytics or source, build changed production projects directly, perform fresh
filtered discovery, record the expected count and reconcile data-driven rows before execution.
A zero/unexpected count is not valid proof. Do not run stale binaries with `--no-build`.

There are three proof layers that do not replace each other: deterministic state/owner tests,
real production browser journeys, and network-separated application containers. A .NET TestServer
or a sandbox cannot fulfill the container layer. An HTTP status/green toast is not a commit or
correctly routed model. Preserve raw failures and bounded follow-ups separately.

Each group below has one outcome in the initial sealed evidence template. An executed run may
use PASS, FAIL, BLOCKED, NOT_RUN or NOT_APPLICABLE with precise evidence and justification. Core
S0 naming/routing/authentication and final-image groups cannot become NOT_APPLICABLE merely
because Docker was unavailable. A specific unsupported capability is tested as a refusal, not
silently skipped or implemented outside scope.

## Minimum causal controls

The original R1/R2 are repaired by S0. Preserve their current focused regressions and repeat relevant final-image assertions. For PP2C-R1 add failing-first actual component/native tests and final two-circuit assertions. For
R2 use a second owner/circuit to accept a new remote snapshot; changing the same object in a
fake does not model a new catalog. Compare received revisions and identity-keyed model sets.
For all mutations test double dispatch, Enter versus alternate action, late completion, known
rejection, confirmed write then failed refresh, and genuinely unknown write outcome.

For source/import settings test typing before blur, normalized source URI/local alias, catalog
retry, unchanged/missing secret metadata, optimistic conflict, saved disabled/missing references,
changed target A-B-A, closing a nested dialog without closing siblings, and two independent views.
A returned confirmation applies only to its original target/version, never the newest selection.

## Native/default-model controls

Capture the source driver's accepted preset catalog before the old synthetic Configure helpers.
Do not assert a hard-coded current OpenAI model list. Assert names/IDs/default/IsSuggested/Thinking/
prices/capability flags against independently read source/publication facts. Default wrappers in
selectors are presentation; compare the contained name and exact option identity separately.
Keep source-managed hidden option values opaque and persist/invoke those exact values.

A name collision across publications must exercise both routes and inspect source dispatch, not
only compare two strings. Stop central or revoke access and prove a colliding personal provider
was not called. Test a runtime-only seed's actual ineligibility rather than bypassing it.

## Test selection and wider checkpoint

Reuse existing SharedProviderTwoInstanceUiAcceptanceTests, SharedProviderMetadataUiChecks,
SharedProviderOwnedEffectsTests, SharedDeliveryReconstructionTests, provider profile/session/
operation tests, native publication/import/source/identity tests and the existing E2E runner.
Confirm exact current paths/names first. Reference names are navigation aids, not an excuse for
zero-test filters. Re-run direct consumers affected by contract/assembly moves.

Run focused tests during each stage. This assignment requests one deliberate final frozen
checkpoint after the shared-provider behavior and rendered source/publication boundaries settle.
Record the exact broader scope and current repository triggers; do not launch a full Stable sweep
after every section. Browser/container verification is separate from Stable. Do not let a later
build overwrite a still-running checkpoint's output. Use isolated configurations/output roots
without modifying solution membership or environment safety to make a test pass.

Final-image repetition is mandatory: source/container baseline success before extraction does not
prove the final implementation. Record image digest, compiled source hashes, certificate/instance
identities (no secrets) and matching output paths for each phase.
