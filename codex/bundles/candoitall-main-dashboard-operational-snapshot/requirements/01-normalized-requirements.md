# Normalized Requirements

All requirements are mandatory unless explicitly marked as a scope exception. “Five” means a hard maximum, not a default page size that callers may exceed.

| ID | Requirement | Observable acceptance |
| --- | --- | --- |
| `R001` | Home shows exactly four compact square whole-card quick actions with centered icons and labels: Projects, Agents, Live Processes, Scheduler. | DOM and route tests find four unique cards targeting `/projects`, `/agents`, `/processes/live`, `/scheduler`; keyboard activation and visible focus work. |
| `R002` | Projects exposes a dedicated typed recent-project query. | EF query is `AsNoTracking`, projects only required fields, orders `UpdatedAtUtc` descending with stable ID tie-break, and applies `Take(5)` before materialization; >5 seeded rows return exactly the newest five. |
| `R003` | Workflow activity uses a dedicated typed query/store path, not aggregate overview. | With any `Running`/`WaitingForInput` rows, return only up to five active rows; with none, return the latest five across states; query is no-tracking, deterministic, bounded, and performs no overview group-by/count work. |
| `R004` | Process activity uses canonical runtime state for active-or-recent selection. | The runtime-state query returns at most five deterministic IDs; optional projection display data is loaded only for those IDs with lag exposed; no assignment/action/current-step/diagnostic/history/agent/usage enrichment occurs; an active run older than 500 newer terminal projections is still selected. |
| `R005` | Agent usage uses `IAgentUsageTotalsQueryService`. | Implementation calls profile-scoped `ISandboxWorkspaceStore.LoadUsageProjectionAsync` and returns exactly `TotalTokens`, `KnownCostUsd`, `UpdatedAtUtc`; loader depends on the query interface, not the store or full overview. |
| `R006` | A thin scoped `IDashboardSnapshotLoader` composes one typed snapshot from the four narrow query services. | Loader has no caching/UI/persistence policy, materializes every project/workflow/process collection as `ImmutableArray<T>`, rejects any source result above the hard maximum of five, and propagates/wraps source failure without substituting empty data. |
| `R007` | An app-process singleton `DashboardSnapshotService`/cache shares global operational snapshots across Blazor circuits for exactly five minutes. | Cache identity includes active database runtime profile ID, fingerprint, and generation. Every actual refresh invokes a typed singleton load runner that owns a fresh async DI scope and resolves the scoped loader there; no user-specific data or scoped dependency is retained. Fake-time tests prove cross-circuit fresh hits, exact-expiry reload, runtime-identity separation, and singleton registration. |
| `R008` | Concurrent refreshes coalesce and force refresh behaves predictably. | Multiple simultaneous callers cause one loader invocation; force starts a new load when idle even if cache is fresh, but joins an existing in-flight load; fault/cancellation is not retained. |
| `R009` | Refresh errors are explicit. | Initial failure renders an error with retry; later failure keeps prior data only with visible stale/error text and original snapshot timestamp; logs include source/cache identity/force state without secrets. |
| `R010` | Home automatically refreshes while open, exposes forced refresh, and shows a tiny countdown. | Fake time crosses expiry and causes one refresh; manual action calls force; countdown decreases/reset; cancellation/disposal prevents late state mutation. |
| `R011` | Home remains rendering/orchestration only and `QuickActionCard` belongs to AppComponents. | Home injects the snapshot service (and time/logging primitives only if needed), contains no EF/store/module query or cache policy, and uses `CanDoItAll.AppComponents.QuickActionCard`. |
| `R012` | UI uses the existing component system and shared tabs. | `PageScaffold`, compact `PageHeader`, `CompactStatStrip`/`CompactStat`, `Grid`, `Card`/`Button`/`Icon` wrapper, `Tabs`/`TabsItem`, `SelectionListItem`, `LoadingState`, `EmptyState`, and `Alert` express the composition; no custom app shell/assets. |
| `R013` | Desktop composition is explicit and has no feature overlays. | At `1440x900`, header/actions/section headings and at least three rows are in first viewport, remaining rows page-scroll, no nested/lateral overflow, and no dialog/menu/floating surface opens. |
| `R014` | DI and dependency direction remain clean. | No new `.csproj` references or partial/nested services. `IServiceProvider` resolution is confined to the typed Web composition/lifetime adapter that creates an async scope for a refresh; UI, query services, loader composition, and cache policy never resolve services. Module registrations expose typed scoped queries through existing composition roots. |
| `R015` | Snapshot load cadence and query work are bounded. | Normal Home ticks across all circuits do not load before eligibility; one coherent app-process load per five-minute runtime-identity interval, including failure throttling; every immutable project/workflow/process collection has a hard maximum of five; process projection reads are limited to selected IDs; agent query loads one existing projection. |
| `R016` | Usage metrics are semantically honest. | Header labels are “Total tokens” and “Known cost (USD)”; values match Agent usage projection only; no workflow/process usage is summed or presented as total spend. |
| `R017` | Loading, populated, empty, error, and stale-refresh states are distinct. | Component tests and browser evidence demonstrate each applicable state; a source error never becomes a zero/empty state. |
| `R018` | Behavioral proof prevents shallow implementation. | Each SB execution row contains exact source/tests, realistic positive case, adversarial negative case, shallow-pass trap, and anti-stub audit. |
| `R019` | Architecture and final closure are independently gated. | Required C# artifacts stay current, no-partial/no-reference/source-dependency assertions pass, CodeAnalytics is retried or manual gap evidence recorded, targeted suites/build/Playwright pass, and all raw notes close honestly. |

## Non-Goals

- Redesigning the application shell, side navigation, Projects/Agents/Processes/Scheduler pages, or workbench restore behavior.
- Mobile/tablet responsive expansion, charts/trends, filtering/search, editing, dialogs, overlay menus, push notifications, background hosted refresh, distributed cache, or caching user-specific/authorization-sensitive data. Sharing the global operational snapshot across circuits in one app process is intentional.
- Combining cost/token totals from overlapping workflow/process/agent projections.
- Denormalizing process snapshot JSON or adding database indexes beyond the three narrowly authorized by `bundle://evidence/SB01/postgresql-dashboard-index-plans.md`.
