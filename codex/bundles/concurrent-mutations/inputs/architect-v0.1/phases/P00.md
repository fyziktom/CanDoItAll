# P00 · Evidence refresh, writer perimeter and cost baseline

Status: **Proposed — not started or validated.**

## Goal
Turn the sampled architecture map into a complete enabled-writer inventory for the Projects pilot and establish reproducible baseline costs.

## Dependencies and entry evidence
Dependencies: None.

- Package is accepted as a review starting point, not an implementation mandate.

## Included changes
- Resolve the actual working branch, dirty tree and sibling revisions; remap extracted contracts and hosts.
- Trace Projects create/update/delete, children, raw SQL, imports, transfer, seed/test maintenance and every HTTP/tool/UI caller.
- Read current testing guidance, complete CI policy, governance journals and canonical migration composition.
- Record baseline SQL/rows, lock wait/hold, latency, receipt/projection behavior and UI draft memory with isolated data.

## Explicit exclusions
- No application-wide token migration.
- No source checkout/reset or change to the developer environment.
- No claiming default-branch search results prove the target branch.

## Exit gates
- Every enabled Projects writer is assigned a stable inventory ID and exact symbol/caller evidence; unknown pilot writer count is zero.
- Exact owner test discovery is recorded and baseline environment is reproducible.
- Decisions D01–D08 have assigned reviewers and pilot defaults are ratified or replaced.

## Performance review
Required workload IDs: PERF-01, PERF-02, PERF-03, PERF-04, PERF-05. See [performance scenarios](../registers/performance_scenarios.json). Measurements remain unset until executed.

## Tests and downstream consumers
The [test catalogue](../docs/21-test-catalogue.md) and [mutation inventory](../registers/mutation_inventory.json) carry this phase ID. Discover actual current test assemblies, filters and counts before implementation. Updating a shared contract also invalidates affected UI/API/tool adapters, serialization snapshots, import/migration mappings and boundary tests even when their files were not directly edited.

## Safe stopping state
Read-only discovery is useful independently. Existing write risks remain; no new concurrency guarantee is advertised.

## Residual risks and integration notes
Incomplete later-owner mapping remains explicit. Performance baselines may still require a capable local environment, which blocks that gate rather than being labelled passing.

Use [the phase review template](../templates/PHASE_REVIEW.md). No source modification, deployment, migration, commit or push is authorized by this card alone.
