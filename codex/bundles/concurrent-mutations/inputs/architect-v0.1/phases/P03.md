# P03 · Narrow intentions and selective editor reconciliation

Status: **Proposed — not started or validated.**

## Goal
Reduce avoidable whole-object conflicts and list churn without weakening the pilot safety rules.

## Dependencies and entry evidence
Dependencies: P02.

- P02 valid baseline and observed conflict/cost data justify the selected refinement.

## Included changes
- Introduce selected typed add/edit/remove/reorder intentions with their own validated preconditions.
- Define duplicate/foreign row-ID rejection, normalization and no-op behavior.
- Enable scalar three-way merge only for owner-approved independent fields; keep collection merge explicit.
- Preserve submitted/live reconciliation and backend-free rendering boundaries during extraction.

## Explicit exclusions
- No universal JSON Patch engine or mandatory field-level revisions.
- No silent LLM-generated merge applied as safe.

## Exit gates
- Exact intent/collection and third-writer merge races pass.
- UI draft survival and public API/tool schema parity remain proven.
- Comparison reports whether conflict rate or query/allocation cost actually improved.

## Performance review
Required workload IDs: PERF-01, PERF-02, PERF-08, PERF-11. See [performance scenarios](../registers/performance_scenarios.json). Measurements remain unset until executed.

## Tests and downstream consumers
The [test catalogue](../docs/21-test-catalogue.md) and [mutation inventory](../registers/mutation_inventory.json) carry this phase ID. Discover actual current test assemblies, filters and counts before implementation. Updating a shared contract also invalidates affected UI/API/tool adapters, serialization snapshots, import/migration mappings and boundary tests even when their files were not directly edited.

## Safe stopping state
Projects becomes more usable; coarse protected save can remain as explicit replace. Fine-grained collaboration remains out of scope.

## Residual risks and integration notes
More commands increase contract surface. Keep only those with a real use case and testable domain meaning.
