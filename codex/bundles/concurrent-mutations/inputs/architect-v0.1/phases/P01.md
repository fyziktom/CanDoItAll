# P01 · Minimal foundation proof and prerequisite repairs

Status: **Proposed — not started or validated.**

## Goal
Establish correct transaction/outcome/cleanup behavior and choose only the primitives the first vertical slice needs.

## Dependencies and entry evidence
Dependencies: P00.

- P00 complete pilot writer map and measured baseline; actual primitive consumers known.

## Included changes
- Specify exact edit-stamp semantics, original-value binding, coherent read and child-only root advancement.
- Prove source-first lock ordering, nested participation, cancellation/dispose cleanup and commit knowledge on both Projects source paths.
- Separate domain conflict, retryable database failure and commit uncertainty in the owner/adapters without replacing unrelated public contracts.
- Design/reuse the Projects durable operation result and bounded fact-validation ports; instrument existing gates.

## Explicit exclusions
- No blanket removal of local stripes or isolation-level downgrade.
- No generic command bus, global mutation DbContext or reflective field patch engine.
- No new replay truth duplicating existing owner journals.

## Exit gates
- Two-process and deterministic primitive tests show declared participation/cleanup/commit semantics.
- Minimal schema/contract choices and canonical mapping strategy reviewed.
- Projection decision D08 and migration/restore identity policy are resolved before P02 implementation starts.

## Performance review
Required workload IDs: PERF-03, PERF-04, PERF-05, PERF-06. See [performance scenarios](../registers/performance_scenarios.json). Measurements remain unset until executed.

## Tests and downstream consumers
The [test catalogue](../docs/21-test-catalogue.md) and [mutation inventory](../registers/mutation_inventory.json) carry this phase ID. Discover actual current test assemblies, filters and counts before implementation. Updating a shared contract also invalidates affected UI/API/tool adapters, serialization snapshots, import/migration mappings and boundary tests even when their files were not directly edited.

## Safe stopping state
Foundational corrections may ship separately when behavior and guards remain compatible. Project content protection is not yet complete.

## Residual risks and integration notes
Changing a shared utility can affect many owners; named invalidation triggers may require a broader frozen-checkpoint gate before continuing.
