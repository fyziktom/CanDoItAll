# P05 · Bounded owner adoption waves and structural invariants

Status: **Proposed — not started or validated.**

## Goal
Apply proven target/outcome contracts owner by owner, preserving stronger existing semantics and closing graph-level risks separately.

## Dependencies and entry evidence
Dependencies: P02.

- P02 experience available; each wave has its own complete selected-writer map. P04 is additionally required for a wave adopting decision-basis behavior.

## Included changes
- Choose each next owner from refreshed mutation/risk/decoupling inventories; small editors first.
- Wave A candidates: Prompts, Collaboration flags/create/replies, Resource metadata—each requires current code audit before selection.
- Wave B candidates: CRM/HR, Workspace settings, Provider/Agent configuration, Memory/Plugins/Security administration—retain their established contracts and policies.
- Wave C: canonical Workbench tasks, assignments, graph moves/dependencies and bounded multi-owner batches; preserve existing expected state and source ordering.
- Add shared vocabulary only after real repetition demonstrates a useful stable boundary.

## Explicit exclusions
- No mechanical Version-property rollout across every mapped entity.
- No replacement of immutable definitions or append semantics with whole-object saves.
- No new UI/backend coupling while contracts move.

## Exit gates
- Each selected owner has independent coverage declaration, tests, compatibility cutover and benchmark comparison.
- Structural wave proves membership/cycle/assignment invariants under opposing concurrent writes.
- Unconverted owners remain listed, not hidden behind an application-wide completion label.

## Performance review
Required workload IDs: PERF-03, PERF-05, PERF-06, PERF-08. See [performance scenarios](../registers/performance_scenarios.json). Measurements remain unset until executed.

## Tests and downstream consumers
The [test catalogue](../docs/21-test-catalogue.md) and [mutation inventory](../registers/mutation_inventory.json) carry this phase ID. Discover actual current test assemblies, filters and counts before implementation. Updating a shared contract also invalidates affected UI/API/tool adapters, serialization snapshots, import/migration mappings and boundary tests even when their files were not directly edited.

## Safe stopping state
Each closed owner wave can ship independently; unreviewed waves are not required merely to finish a documentation phase.

## Residual risks and integration notes
P05 is a family of bounded slices, not one giant release. Dependencies on other ongoing refactors must be refreshed at each slice.
