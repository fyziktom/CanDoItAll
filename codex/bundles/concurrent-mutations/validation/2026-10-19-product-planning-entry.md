# Product planning execution entry

The repaired candidate is under validation. It is not bundle closure or UI activation. It follows
the [product admission design](../plan/P04-product-planning-admission.md) and the
[123-case atomic start/provider contract proof](2026-10-19-planning-start-contract.md).

The explicit typed owner passes through chat requests/options and execution requests.
Planning requires chat-backed admission and refuses automatic publication, input or typed
context attachments, unsupported owners and unrelated output contracts. Background and
same-source reservation entry points cannot opt into this interactive operation.
Participant preparation reads actual persisted policy and source authority before the
atomic run publication. That publication binds the original provider-contract digest and
planning journal to the real run/chat identities together.

A small Core coordinator owns the planning loop. It uses the registered MAF planning
port and participant without referencing product modules. Every fresh computation uses
the original runtime digest. Each complete provider step retains its own history and usage
before aggregation. Acknowledged refusal and cancellation return their persisted outcome
to ordinary result/metric handling; they cannot become success. A later unknown failure
retains earlier usage through the existing usage-bearing exception and preserves its work
anchor. Publication always pauses for explicit approval, including for Agents configured
to auto-approve ordinary tool calls.

The host keeps its existing activity, credential, cancellation, transcript and metric
owners. Planning skips ordinary handoff preparation, unused transient-context retention
and the ordinary automatic-approval loop. Native/API actions for saved approval, explicit
Refresh/Cancel and bounded Replan remain a separate required integration step. No UI action
or incomplete writer perimeter is enabled by this checkpoint. SPA remains on its own branch.

Five coordinator cases cover RunSnapshot/StepSnapshot, per-step history and usage,
later provider failure and original-contract loss/change before opening work. Eight actual
registered workspace cases use real file persistence and PostgreSQL with intercepted MAF
HTTP transport: explicit review despite Agent auto-approval, invalid output, concurrent
cancellation and four unsupported request shapes. The existing orchestration test host
also verifies that governed context capture retains the explicit planning selection.
Ordinary chat/run tracking and established module admission/publication/receipt regressions
are included in the candidate selection.
