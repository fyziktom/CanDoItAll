## Measured failure and repair entry

The first frozen run passed all nine compatibility and seven HTTP recovery cases,
but all six cost cases exceeded the one-second reference at the first observation.
Even a one-step review consumed about 80 MB of process allocation and 27 Process
SQL commands for a response of about 1.8 KB. This is evidence of substantial fixed
request cost; it does not attribute that cost to a particular owner.

Inspect the actual read call chain and existing telemetry before changing production.
Use scoped profiling of the registered HTTP path with the same accepted child and
authority. Capture all five observations before asserting the unchanged latency
reference, and retain the diagnostic overhead explicitly. Preserve actual current
reads and all authorization/freshness checks. Do not cache authorization across
requests or replace this path with a direct store read that skips disclosure.

A repair must pass the six final unprofiled shapes and re-run the affected owner
behavior plus the seven HTTP recovery cases. Expand to wider storage or factory
tests only if profiling locates the defect there. The failed source/runtime/proof
identities remain immutable; later candidates get separate ownership records.
