## Evidence and reference decision

Persist evidence even if any assertion, cancellation, timeout or cleanup fails. Record outcome/exception type only, expected and actual task/receipt counts, actual writer intervals, C3 guard hold/release, wait latency, SQL wait identity and holder duration, raw elapsed samples and per-writer empirical p50/p95/max. No automatic retry or exclusion of slow samples. Separate failed outcome latency from successful writer latency; no percentile over silently dropped failures.

Record cumulative process allocation for each whole cohort (not invented per-task allocation), setup and operation windows, observed heap/LOH/private/working-set peaks with sampling interval/gaps, absolute retained baseline, and actual machine/GC headroom. Existing JSON diagnostics report logical payload reads/write bytes and counts, not OS device I/O. Count SQL commands across Workbench, Projects and enlisted neutral contexts where observable; raw ADO lifecycle commands need their separate observer or must be explicitly excluded. Command count is not a network-roundtrip count. Record actual 1/100-task batch command/flush/receipt bytes and all encoding/validation phases. Bounded trace callbacks must avoid retaining payload/SQL parameters or introducing full-graph serialization into the measured body.

Parent-proposed reference targets, pending measurement: for normal unrelated writes and cancellation, **p95 <250 ms and maximum <1 second**, per writer class and file profile, with zero lost/incorrect outcomes. Report both absolute latency and independent-organization control; do not subtract a slow control to manufacture a pass. Under forced SQL contention, unrelated writers must not simply inherit a possible 30-second SQL hold: report whether each completes within one second while the actual holder is still present. A timeout or blocked writer fails that activation criterion even if it later completes correctly. The current coarse design is expected by source to expose blocking; preserve that result. These are declared reference targets, not production guarantees or an inferred service capacity.

One ten-minute cooperative row budget covers fixture setup, all four profiles, samples and cleanup. Parent supplies a separate actual process-tree deadline and persistent ownership before launch; expiry is incomplete/cleanup-required, not a passing sample. Reuse an explicit owned environment/profile namespace with manifests outside the disposable root. Dispose authority/SQL/provider before environment, aggregate cleanup failures and verify the exact leased database/client/file-guard cleanup. No speculative delete/prune and no abandoned background tasks. If this finite matrix exceeds the row budget, retain the completed and incomplete cells; parent may approve a separately identified smaller characterization, never silently extend the gate.

Decision after evidence: if the small normal profile already blocks unrelated writes across the real SQL wait, the coarse guard fails the requested reference responsiveness independently of maximum-size throughput. Parent then chooses the narrow writer-perimeter implementation or a smaller feature scope. If the coarse reference profiles pass, maximum-domain/recovery/authority and ordinary producer proof still remain; a finite cost probe does not activate C4. Retain both this characterization and any later candidate with matched source/binary/fixture inputs.
