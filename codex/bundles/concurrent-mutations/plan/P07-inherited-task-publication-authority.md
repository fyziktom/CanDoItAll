# Inherited task-plan publication authority

Prerequisites: the inherited codec has 124 passing cases, exact Process source selection
has 23, and Core's parent-owned saved-effect continuation has 201. This slice connects
those boundaries to the existing Workbench publisher and Process publication fence.
It does not activate the producer, receipt-history or manager routes.

Workbench owns one `ProjectTaskPlanProcessAuthority` implementing the existing publication
and active-work ports. It receives the resolved original command, exact inherited snapshot
expectation, live work and approved binding. The snapshot retains the executor as primary
and the original launching Agent as the optional second selected ID. Validate this set
before acquisition. Missing/changed original bytes refuse the publication; no reacquisition,
catalog refresh or executor-to-launcher permission substitution is permitted.

Current authority requires the source's original/current launch ceilings through the
existing source owner, plus an active non-template executor with original/current tool
and task-write permission. Governed Project read/scope comes from the Process source.
Recheck the executor session's original profile generation against the existing current
generation source on every active-authority/work check, including the final check after
SQL waits and operator-launched Processes:
their source authority has no launching-Agent generation ceiling. This adds no I/O.
An executor's ordinary personal Project list does not widen or narrow that governed scope.
Existing publisher gates cover the exact target lifetime and any distinct original source
Project before the Process root lock. At most one additional Project is admitted.

Require the original source and policy on every active-work check. Core verifies the
live saved-effect lease, approved exact payload and current invocation claim against the
held original run, accounting for elapsed work and basis age. Receipt lookup remains
independent: this mutation authority cannot authorize history or revive expired dispatch.

Inside the enlisted task transaction, repeat current held-source/executor checks, recover
the canonical parent from the held original run, and invoke the existing Process selected
publication fence with Workbench's execution/content contracts and Dispatch purpose.
The publisher calls this before staging and after SQL flush. A changed source/claim refuses
as SourceChanged; source/executor revocation refuses as AuthorityDenied; exhausted live work
refuses as BudgetElapsed. No automatic retry, new provider execution or new operation ID.

No new interface, registration, module edge or runtime partial is necessary. One selected
snapshot is retained across the write; it releases the workspace gate before SQL waits.
Reuse current lock ordering and bounded Process queries. No network/provider work or
catalog reacquisition occurs inside SQL. Canonical parent decoding is bounded and cached
for this one publication. The reusable original receipt remains the only commit-uncertainty
recovery evidence; producer outcome and budget settlement are a subsequent integration.
