# P04 Card B: bounded canonical task basis and writer perimeter

Status: source-only design refinement, 2026-10-16, managed engine continuation checkout. No production change, discovery, execution, throughput or complete runtime-policy closure is claimed. This card resolves the representation choice in [P04/P07](P04-P07-runtime-policy.md); Card C still owns atomic publication and its own durable result. Paths below are repository-relative.

## Decision and exact first scope

Choose a **bounded typed exact-set witness**, not a new collection-revision row, for the first append-only manual task-plan operation. The witness compares the complete current material state of one project with its admitted state. It does not prove that no intermediate event occurred. The parent review accepted this distinction: a same-occurrence value changed and restored exactly is current; deletion/recreation under the same public key is a different occurrence. This avoids adding a revision bump to every existing writer, import and compensation path before that wider writer change is justified.

The descriptor is server-selected and versioned, initially `CanonicalManualTaskPlanV1` (proposed typed enum/member, not a client-selected query). It includes all non-system `ProjectObjectRecord` occurrences in the project for which `ProjectStructureCanonicalTaskMutationPolicy.IsTask` is true. Do not filter by execution status, visible page, selection, assignee or whether the model mentioned the task. Empty is a complete set with the same project/namespace binding, not an omitted witness.

Freeze this material projection for v1:

| Part | Captured and compared values |
| --- | --- |
| Dataset/owner identity | Exact activated dataset namespace, database profile identity, project ID and lifetime; original Projects definition revision. A profile alias alone is insufficient. |
| Project input | Projects-owned definition scalars: name, description, objective, status, current phase and target date. The existing definition revision conservatively also invalidates other definition changes; this is explicit. Phases/options, hierarchy and other projects are not planner inputs in this version. |
| Every task occurrence | Persisted `Id`, ordinal `NodeKey`, nullable `ParentNodeKey`, title, subtitle, notes, status, priority, stored progress mode/percent, start/end and duration. Type/subtype and `IsSystemManaged` define membership; the canonical descriptor is Task, not an arbitrary client predicate. |
| Typed task metadata | `WorkItem.Description`, `DueUtc`, `ExecutionState`, `ActualStartedAtUtc`, `ActualEndedAtUtc`. Compare explicit typed values, including null versus supplied values; retain exact captured text and UTC instant semantics under the versioned codec. |

Exclude positions, view state/Gantt row order, markers, timestamps, arbitrary metadata/unknown extension fields, media/bindings/references, all relationship edges, external artifact content, assignee names/assignment revisions, all estimates/effort/units, expected cost/currency/basis, rates and capacity. The planner receives only this projection. A current link, assignee, resource price or availability claim cannot be inferred from it. Pure assignment/estimate/cost changes therefore do not invalidate v1; an execution change through the same edit/compensation path does. Reparenting changes the captured parent key, but parent titles/ancestry are not planner inputs. Stored progress is captured explicitly, not confused with execution-backed display progress.

The first proposal only appends new unassigned manual tasks with bounded title/description/notes and priority, using the canonical empty estimate and NotStarted execution state. It does not alter existing tasks or propose dependencies, parents, resource bindings, estimates, effort, costs, assignments, executable Workflow/Process attachments, scheduling feasibility or externally derived deadlines. Reject such structured requests before model dispatch/publication; do not silently remove requested fields. Use the canonical project root as the fixed publication parent, which the existing creation path supports (`LoadCreatePlanningNodesAsync` in `ProjectWorkbenchModels.cs:912`); do not silently create/choose the mutable Main backlog. If product acceptance requires backlog placement, capture an explicit original backlog occurrence as an additional target witness before enabling it.

Do not reuse the full `ProjectStructureNodeState` fingerprint: `Workbench/ProjectStructureNodeState.cs:112` includes layout, bindings, references and all metadata. Do not reuse the Memory snapshot provider: `WorkbenchProjectStructureSourceSnapshotProvider.cs:25` composes a structure read and a separate timestamp query and maps missing projects to an empty memory snapshot; those semantics cannot certify this basis.

## Capture and publication boundary

Capture uses a short Workbench-owned ReadCommitted transaction with finite timeout, exact lifecycle shared guard and the complete sorted project-key exclusion acquired **before** the first material read. While these guards are held, use existing `CoordinatedDatabaseTransaction` enlistment for the small Projects-owned definition read and read the complete Workbench projection. All participating definition/task writes hold P, and import/restore holds the conflicting lifecycle/table fence, so the two owner reads are stabilized together even though ReadCommitted obtains a fresh snapshot per statement. This deliberately avoids a pre-wait RepeatableRead/Serializable snapshot. Add a cohesive enlisted read/guard seam to the existing Projects reader/query ownership, returning original definition lifetime/revision plus the six scalars above. `ProjectDefinitionReader.cs:8` currently creates its own context/transaction; `ProjectRecordQueryService.GetManyForMutationAsync:73` enlists but omits objective/revision. Neither can be called unchanged to claim coherent Projects+Workbench capture. Workbench must not reference `ProjectsDbContext` or query copied Projects entities. Capture validates exact dataset binding and current disclosure authority, materializes immutable bounded facts, then releases every transaction/lease before model work. Missing source, invalid metadata, oversized source and unauthorized source are distinct refusal/unavailability outcomes, never empty/current.

Publication uses an explicit **Workbench task-plan** transaction entry point, not a new isolation option for all existing consumers. Reuse the infrastructure pattern in `ProjectMutationAuthority.cs:94` and the existing lifecycle/ordered-key helpers; do not call the Projects definition protocol or write a `ProjectDefinitionAccepted` receipt for tasks.

1. Capture/retain original invocation, binding, basis, resolved policy and immutable proposal; acquire original producer authority outside the SQL transaction. Any Workbench operation epoch/receipt comes from Card C's owner protocol.
2. Begin the new owner transaction with finite timeout; lifecycle/operation admission precedes owner keys and every target table access. Source-authority DB guards precede owner keys wherever the current producer requires that order.
3. Obtain the **complete sorted** set of target and source-project keys, plus any actually required binding key. Validate exact current Project lifetime/revision through the enlisted Projects seam, then reread the entire bounded task projection and compare it before staging any effect. No nested/reentrant acquisition of P in the reader or staging primitives.
4. Stage the bounded tasks and exact Workbench result together, repeat current source/claim/deadline checks, and commit. Known commit survives later cleanup; unknown commit requires exact owner reconciliation, not a fresh proposal or semantic replan.

**Freshness blocker and selected direction:** existing native/source-aware scopes are Serializable. `pg_advisory_xact_lock`/source queries can establish their transaction snapshot before a wait; a later exact-set read may therefore miss a committed insertion or update. An unchanged Project row/lifetime does not repair that snapshot, and SSI is not a guaranteed stale-basis detector for an append-only publisher. The new task-plan entry point uses ReadCommitted after the complete owner exclusion, so the validating reads see commits made while it waited and remain stable until commit. This is narrowly analogous to the protected source-null definition path; the existing protected definition path still uses Serializable when a source exists and cannot be copied blindly.

Ordinary Agent authority is a promising bounded first adapter: `ProjectAgentSourceMutationAuthority` holds the catalog read lease and checks profile generation/original+current grants; `ProjectAgentSourceMutationLease.RequireForMutationAsync:136` does not acquire SQL snapshot-dependent source state. Preserve the task domain and final authority checks explicitly. Process/Workflow authority also owns persistent dispatch/output/claim guards. Before enabling their new ReadCommitted task-plan adapter, prove their complete source exclusion and claim invariants under that isolation; until then refuse this new operation for those producers. Do not downgrade their existing scopes, reorder source versus project locks or label them supported because native/Agent passes. These remaining producer proofs are Card C/E/F/G entry gates, not a reason to hide a generic coordinator in Card B.

The exact-set decision depends on the writer exclusions above. Add architecture/callsite review coverage when a new material writer is introduced. Arbitrary external SQL and unsupported restore bypass are outside the application protocol; restore requires the established namespace activation process.

## Bounded costs and proof gates

Initial sizing candidates, to validate before cutover: at most 1,000 non-system WorkItem **candidates**, 64 KiB for any selected text/raw metadata field, 2 MiB aggregate fetched text/raw metadata and 1 MiB encoded typed basis; at most 100 proposed tasks. Refuse over-limit capture/publication before model work/effects; do not truncate, page or silently narrow the scope. Check bounded candidate IDs/count and server-side byte lengths before copying metadata/text to the process. Do not scan/materialize an unbounded full graph first. Fetch/filter all bounded WorkItem candidates with the existing C# canonical predicate: SQL `ObjectSubtype == "task"` is narrower than the trim/OrdinalIgnoreCase predicate and would miss imported noncanonical spellings. A normalized database constraint/index is a separate measured choice, not an assumed existing invariant.

`ProjectObjectRecordConfiguration` already indexes `(ProjectId,ObjectType,ObjectSubtype,IsSystemManaged)` and `(ProjectId,ParentNodeKey,ObjectType,IsSystemManaged)` and uniquely indexes `(ProjectId,NodeKey)`. Inspect the actual bounded candidate query plan; do not add another index solely from the C# expression. Compare exact typed facts in O(n) maps/sets with duplicate occurrence/key rejection and deterministic ordering for encoding. Hashing is an integrity/index aid; retained exact facts remain necessary for review and collision-independent semantic comparison.

A concrete existing bottleneck is `ProjectNodeBindingStorage.PersistAsync:305`: it reacquires global B and reads binding/reference rows per node, even for a plain task. A loop over it both serializes disjoint projects and creates per-task round trips. Card C must stage a bounded batch of new canonical plain-task bindings using shared validation/normalization primitives, with no external bindings/references/storage object possible, or explicitly measure/accept the B bottleneck. A narrowly typed new-plain-node staging path can omit B only after proving it cannot change managed-storage ownership and that lifecycle/table transfer exclusion still holds; do not add a general “skip locks” flag. Basis capture itself requires neither B nor full binding loads. Keep the single-project P critical section short; no provider, file, pricing, rendering or human work inside it.

Required deterministic proofs (new proposed cases, not existing executed counts):

- Pure projector/codec: every included field changes equality; excluded-only fields do not; malformed/missing typed WorkItem data fails explicitly; empty complete set; duplicate keys/IDs; exact bounds and one-over; canonical subtype whitespace/case; stable versioned reconstruction.
- Real PostgreSQL barriers: a publisher waits on P while each representative material writer commits create/edit/lifecycle/reparent/delete/copy/move/Gantt/compensation/Workflow status; after acquiring P it sees the new complete set and refuses. Include insertion into previously empty scope and task reclassification into scope. Test source and target of a cross-project move.
- ABA: identical public task key with a fresh occurrence fails; same occurrence and all selected facts restored succeeds; estimate/cost/assignee/layout-only edits succeed by declared v1 semantics; restore/new namespace or imported Project lifetime fails even when task IDs are preserved.
- Coherent read: definition change between owner read steps cannot produce mixed Projects/Workbench input. Definition change while publisher waits fails original revision. Current source revocation/claim loss fails independently of equal task values; Process/Workflow RC tests are mandatory before those adapters enable publication.
- Transfer/delete race: protected publication holds lifecycle shared + P; target transfer waits/refuses within its bound and cannot enter the task gap; transfer that commits first invalidates old binding/lifetime. Whole-project deletion never turns absent target into a successful empty-basis append.
- Batch/knowledge: all tasks+native bindings+owner receipt commit or roll back together; no per-task side effects survive partial validation; lost acknowledgment recovers exact original IDs; disposal failure after known commit preserves Accepted. Card C owns these new receipt proofs.

Use existing task, clipboard, lifetime/assignment, transfer and source-authority test fixtures as starting coverage (for example `ProjectStructureClipboardIntegrationTests`, `WorkbenchAssignmentOwnerPersistenceTests`, `ProjectStructureTaskApplicationServiceTests`, `ProjectStructureGanttMutationServiceTests`); their current passes do not prove this new witness. No existing test-count claim is inferred from names.

Measure 0/10/100/1,000 candidates and at-limit text, capture and validation separately plus full read→proposal admission→publication time; 1/8/32 disjoint projects and same-project contention; actual accepted/changed-basis/authority/timeout outcomes; SQL counts, p50/p95/p99, allocations, locks, receipt/basis rows+indexes+TOAST and WAL. Include append batch sizes 1/10/100 and deliberately oversized refusal. Existing Projects performance numbers are not this workload. Report candidate limits, actual max and unmeasured production distributions honestly; no normal database or private field dump is authorized by this source-only card.
