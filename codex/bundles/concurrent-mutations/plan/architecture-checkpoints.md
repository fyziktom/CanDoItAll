# Architecture checkpoints

1. Before P01a: independent review of lock cleanup, exact fault tests and absence of
   new dependencies. Its small repair does not settle transaction outcome/replay policy.
2. Before Projects implementation: confirm complete enabled writer/caller perimeter,
   precise full/scalar command contract, coherent read, CAS, acknowledged outcome,
   receipt lifetime and search choice. Reject a new mutation partial on ProjectsService.
3. After Projects foundation: inspect actual references, directly test extracted pure
   rules/handler, prove delegation removed old mutation implementation, and run the
   native API/tool consumer smoke before UI closure.
4. Before runtime basis: select one exact publisher and all material source writers;
   prove owner port, lock order, membership witness, policy binding and test seam.
5. After runtime wiring: actual registered tool/process producer reaches the new owner;
   fake pure-policy proof alone does not unlock release. Old claims and unknown effects
   cannot publish/replan around the gate.
6. Before overall closure: evaluate dependency graph and compiled boundary tests, audit
   no-new-partial/service-locator shortcuts, verify all original requirements and run
   the frozen broad checkpoint plus applicable host/browser/migration/performance proof.
