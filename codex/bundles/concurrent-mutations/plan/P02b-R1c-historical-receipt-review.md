# R1c historical receipt review across a real host restart

Status: source authoring is in progress; no build, cutover, process restart, receipt read or test execution is claimed. The dedicated cold graph is authored but has a blocking catalog-read amplification defect; see [the frozen graph state](P02b-historical-cold-read-graph.md) and [the proposed invocation-local basis amendment](P02b-historical-catalog-basis.md). It is not approved for integration or activation in its present form. This resolves the design choice left open by `P02b-R1c-reopened-recovery-readiness.md`. The existing native slice still cannot recover a saved nonzero host generation after the host restarts at zero. Producer activation is not complete while this remains unimplemented.

## Selected boundary

Add a distinct, explicitly invoked **Review saved receipts** operation. It reads the original persisted journal and asks the original business owner for bounded, currently authorized receipt observations. It does not acquire a tool-dispatch lease, mutate the journal, mark the run Waiting, resume a provider, execute an approval, retry an effect, or publish a replacement admission. This is sufficient to recover historical knowledge after a host restart without pretending the original execution has current mutation authority.

Keep the existing write/reconciliation admission unchanged. A journal checkpoint after restart, a next provider segment, a new approval decision or a repeated business command requires the separately reviewed R1d/R2 continuation admission. Historical review cannot enable those actions. The same-generation explicit coordination-and-receipts action in the preceding card remains the candidate for resolving a local lease-release warning through actual exclusive acquisition and awaited successful release. A historical read never clears that warning, even if it finds every receipt.

There are two identities, kept in separate fields and types:

- **Original admission:** exact persisted `AgentToolSessionAdmission`, full original profile including its generation, authority ID, run creation witness, governance/source evidence, proposal binding/digest and owner source envelope. Never change these bytes or construct a replacement admission with the current generation.
- **Current observation fence:** profile ID, runtime fingerprint, current local generation, pinned service/workspace scope and native view generation at the start of this read. Validate it before and after awaited owner work. It fences the read and late UI completion; it grants no historical dispatch rights.

The observer proves correspondence of durable identities; it does not need to guess why a local counter changed. A restart and a deliberate switch away/back to the same durable dataset can both permit this restricted read after current authorization. Same profile ID or equal numeric generation alone cannot prove correspondence. A changed fingerprint, dataset namespace, source/target lifetime, caller identity or run/session witness refuses disclosure. This avoids inventing a durable host-generation ledger merely to read an immutable receipt.

## Exact proposed owner seams

Names below are proposed contracts, not callable APIs today. Keep this a small distinct read path rather than adding a bypass flag to dispatch/reconciliation.

1. **Core/Models:** add immutable `AgentHistoricalReceiptReviewRequest` (original run/chat IDs, agent ID and run-created-at witness) and bounded `AgentHistoricalReceiptReview` (original run/journal revision, current observation fence, closed read status and at most four sanitized observations). The full original session is loaded server-side: its background-source envelope must not be serialized back inside this request/result. The result is explicitly ephemeral; it has no checkpoint-confirmed or Waiting transition. A receipt found during this read can be known committed even though nothing was written to the Agent journal. Denial/unavailability before authorization returns no new proposal details or counts. Existing locally known UI knowledge may remain visible under the existing disclosure rules.
2. **Canonical current-read observer:** add a distinct `ObserveHistoricalReceiptReadAsync` method on the canonical authority boundary, with a request carrying the unchanged original source/governance and a separately captured current host fence. Return a read-only observation, not `AgentExecutionAuthorityRecord` usable for mutation. Refactor shared agent/source read checks only where necessary; never call `ResolveAsync` with a rewritten original generation. Validate original authority/read allowance and schema, active agent, current source-derived scope, original source project lifetime and the existing capability/target ceiling. The current generation is checked around the source reads. Unknown source kinds, legacy source without a durable lifetime witness and unsupported historical-read shapes explicitly refuse; no fail-closed-sandbox substitution is an authorization for original receipt disclosure.
3. **Core journal owner:** add `ReadHistoricalReceiptReviewAsync(request, currentRead, providers, cancellationToken)` using the distinct `ISandboxWorkspaceHistoricalReadStore` and existing immutable journal/semantic validation. It validates the exact session/chat/agent/run-created-at relationship, original governance/session consistency, schema-five effects-only journal and bounded proposal identities. Extract common identity validation if useful, but retain the existing full-profile check in `RequireCurrent`. Capture an immutable bounded snapshot and construct a new Core-owned `AgentToolHistoricalReceiptReadClaim`; its constructor is internal, and every provider `RequireAsync` rechecks the owner witness/current fence/current read policy. It is not an `AgentToolRunLease` and cannot be used by command/proposal/checkpoint APIs.
4. **Registered receipt owner boundary:** add a separate historical-read method/interface implemented by the existing `ProjectDefinitionToolReceiptRecovery` adapter. 5. **Process read adapter:** overload the existing narrow `ReadReceiptAccessAsync` for the new read-only pinned claim. A schema-five journal from a provider without an implemented durable source/receipt observer remains explicitly unsupported.

## Coherence, bounds and UI rules

Capture the run/journal revisions before lookup. Re-read the original run witness after the bounded owner calls. A changed run/session/creation/proposal identity or revision returns `SnapshotChanged`; no automatic retry and no synthesized replacement result. This deliberate conservative first version avoids a new shared lock and avoids claiming a coherent mutable journal snapshot across a concurrent writer. The owner receipt itself remains immutable and authoritative for its original address.

Reuse the existing four-observation and five-second cooperative receipt-slice bounds, existing retained schema bounds, exact source codec and cancellation discipline. Do not copy an unbounded journal before validating its supported size. Drain all initiated async work before returning/disposal; timeouts never leave detached reads. No lifecycle/epoch/P mutation guard, catalog mutation lease or file coordination lease is acquired by this path. The historical catalog observer must also be read-only and lease-free; unsupported implementations refuse rather than using the ordinary lease reader. The current-read observer does not introduce a cross-file/SQL atomic revocation guarantee.

Keep receipt statuses distinct. Found means the original owner accepted; a later definition read is current state and cannot replace that acceptance. Open/Draining not-observed remains uncertain; closed retained absence is an owner proof about the original operation; expired, changed namespace, inaccessible or unsupported detail is not absence. None of these authorizes a fresh operation ID or an automatic retry. The Agent-facing review can summarize these closed statuses while keeping raw receipt payloads private.

Native stores the original review target and current host/view fence separately. Late completion after route, profile generation, selection or component lifetime changes cannot populate the successor. Preserve composer text/attachments and existing known commitment on a failed refresh. A read-only review never clears `effectLeaseReleaseUnconfirmed`, never reports a checkpoint as saved, and never changes Process state to successful or Waiting. A same-target newer view must explicitly ask for its own read.

## Accepted paged read contract (implementation amendment)

Historical review uses explicit pages, never an automatic loop. `AgentHistoricalReceiptReviewRequest` retains the original run/chat/agent/creation witness and adds optional `Cursor`. `AgentHistoricalReceiptCursor` contains `executionRunId`, lossless positive Int64 `runRevision` and `journalRevision` decimal **strings**, `nextProposalOrdinal` (integer 0 through 32,768), and sanitized `currentContext` (profile ID, current local generation and workspace scope). The context contains no runtime fingerprint. Numeric JSON revisions, signs, leading zeros, whitespace, fractions, exponents and overflow are rejected by the narrow revision converter; no global JSON policy changes.

The ordinal addresses the canonical flattened saved batch/proposal order, not a filtered UI list. The owner validates the exact original request, current context, run/journal revisions and actual saved sequence length before selecting candidates. An otherwise syntactically valid foreign/stale/out-of-range cursor yields `SnapshotChanged` (a current-context mismatch yields `ContextChanged`), with no snapshot revisions, observations or successor cursor. The cursor is only an untrusted read position: it never supplies admission, caller identity, source authority or permission. Schema and actual journal bounds are checked before materializing candidates.

Every explicit page permits at most four owner lookups within the existing five-second cooperative budget. `LookupLimit` and non-null `NextCursor` mean incomplete coverage. `ExhaustedSnapshot` has no successor, including a sequence with zero eligible effects. A budget/cancellation/owner outage may preserve a cursor at the first unexamined position only if final fresh current-read/context validation and original-witness readback both succeed. No cursor advances past a failed/unexamined owner read. A changed witness never clamps, restarts or merges into another snapshot. Cancellation drains started work; its token is not an authority to skip final disclosure checks. This is a cooperative bound, not a hard deadline for OS/file operations.

Response `runRevision`/`journalRevision` use the same narrow lossless string encoding, and `NextCursor` is bound to the exact response witness/context. The submitted request retains the current page position. Native replaces its visible page and offers explicit Next or Restart; it does not aggregate counts or knowledge across snapshot/context changes. Reading an accepted receipt is ephemeral evidence and does not save an Agent checkpoint, clear file-lease/activity uncertainty or enable execution.

The first two existing contract Facts are extended for this amendment; no new row is claimed. Actual owner cursor range, revision/context race, zero-eligible and later-page access proofs belong to the integration subset. Source-only authoring; no build/discovery/execution has occurred.
