## Semantics and risks

Map found, open/draining absence, closed absence, expiry, dataset change, denied detail,
unavailable detail and unsupported context explicitly. A lookup miss never means retry.
Use the exact original caller binding. Recheck the live historical claim after lookup;
the enclosing reader still verifies the final run/chat and catalog witnesses. A changed
read fence or catalog invalidates the entire page, including earlier observations.

Current source read authorization remains independent of original mutation permission.
Deleting/recreating a source or revoking read access must not reveal cached detail.
Known original owner receipts retain their existing summary semantics when detail is
unavailable. Do not reinterpret a failed lookup as no effect, settle an open work anchor,
or write historical results back to the file journal.

Reuse the existing bounded receipt page and SQL query limits. No file coordination lock
may be acquired by this path; an explicit held-lock test must prove that property.
Receipt SQL has no mutation transaction or advisory project lock. Review DI direction
and the actual per-call factory; no generic historical-reader framework is justified.
