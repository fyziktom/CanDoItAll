## Initialization boundary

`Web/Program.cs` awaits `IAppDatabaseBootstrapper.EnsureCurrentProfileReadyAsync` and API readiness before `app.Run`. `CanonicalRuntimeDatabase` is an initialization owner: its constructor resolves the control-plane profile, may seed/select it, and publishes runtime state. Historical review must not trigger that work.

The operation requires the already initialized canonical profile and a nonempty matching `IDatabaseRuntimeState.GetSnapshot()`. Missing/inconsistent/unsupported binding refuses. The test host completes initialization before starting the observed cold operation. Cold means no Agent execution workspace, ordinary file-store cache, activation cache or provider runtime was prepared for this read. It does not mean that a request initializes an empty application. Custom compositions without an initialized immutable profile are unsupported; there is no control-plane-catalog fallback.

## Bounds and layout perimeter

Semantic journal maximum is 24 MiB; envelope maximum is 8 MiB. Current writer does not establish 64 MiB for the whole persisted run/catalog. Therefore the proposed 64 MiB raw run/catalog ceiling is an explicit compatibility refusal, not proof of support for every currently writable record. Measure retained maximum fixtures' actual indented file lengths before claiming coverage; never truncate or shrink writer limits.

Chat identity streams without materializing messages: separate 256 MiB scan and 1 MiB single-token buffer limits. A long history is not rejected merely for exceeding 1 MiB total. Larger tokens/history refuse explicitly; limits remain provisional until retained/long-history proof.

Before/after layout readiness and pending markers are required, with no recovery. Before and after each target read, any valid pending-publication filename for that target yields RecoveryRequired/unavailable. The observer conservatively matches target casing so Windows aliases cannot evade detection; a false-positive refusal on a case-sensitive filesystem is preferable to disclosure from uncertain publication. No pending file is opened as accepted data, deleted, replayed or promoted.

Enumerate all visited immediate entries of each exact target parent without a glob-filtered iterator, with a provisional ceiling of 4,096 visited entries and a cancellation check for every entry. Do not count only matching pending names: nonmatching entries also consume the bound. Exceeding it is SizeLimitExceeded/unavailable, not absence. This may refuse large existing session directories and is an explicit compatibility bound requiring coverage evidence, not a claim about existing supported workspace size. An absent target with pending evidence is recovery-required, not Missing. A missing parent under a previously required ready layout is unsupported/changed. Enumeration and file calls are cooperative, not a hard OS deadline.
