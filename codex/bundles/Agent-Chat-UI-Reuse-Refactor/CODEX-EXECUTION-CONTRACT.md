# Codex execution contract

1. Execute exactly one subbundle at a time.
2. Read root status, the current subbundle, traceability, architecture decisions, and source evidence before editing.
3. Reconcile the live branch and current SharedInfo skill hashes. Stop for bundle repair when drift invalidates ownership, dependencies, consumers, or test assumptions.
4. Use scoped CodeAnalytics evidence before project-reference or large-component changes.
5. Keep the current subbundle outcome narrow. Do not implement downstream Simple Chat UI.
6. Make the smallest coherent change that creates a real owner and test seam.
7. Do not add partial files to the current large UI types as the primary refactoring mechanism.
8. Keep backend calls, persistence, runtime state, and side effects outside the neutral project.
9. Use Components MCP recommendations and real examples before adding structural markup or CSS.
10. Preserve current large-screen desktop behavior and existing responsive behavior; mobile redesign is out of scope.
11. Use actual diff files and changed line ranges for impacted-test selection.
12. Fail proof on zero or unexpected test discovery.
13. Record exact commands, selectors, discovery counts, results, screenshots, source guards, dependency evidence, and architecture decisions while evidence is fresh.
14. Run unfiltered Stable/full validation only when explicitly promoted or invalidated, and only once in SB09.
15. Stop after final proof with status `awaiting-user-agent-chat-regression`.
