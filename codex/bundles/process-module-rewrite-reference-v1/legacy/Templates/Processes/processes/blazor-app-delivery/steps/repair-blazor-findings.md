# Repair Blazor validation findings

Repair only findings produced by the validation step. Do not expand scope beyond project-structure acceptance criteria. If validation found scaffold-only delivery or deferred acceptance criteria, implement the missing requested product behavior in the approved product root instead of adding more evidence around the incomplete scaffold. Rerun the smallest relevant dotnet build/test checks needed to prove the repair before handoff. If validation found missing dependency injection, inspect the routed component `@inject` directives, constructor-injected services, and transitive interface dependencies, then register every required concrete service and interface mapping in `Program.cs` before rerunning runtime proof. If the finding is a compiler, build, test, or analyzer warning such as MSTEST0037, read the exact stdout/stderr artifact, edit the cited product or test file, and rerun the same command until the warning is gone; do not complete with an unresolved warning when the file is editable. For MSTest count assertions, prefer analyzer-approved APIs such as `Assert.HasCount(expected, collection)` over `Assert.AreEqual(expected, collection.Count)` when available. When runtime startup proof is invalidated by the repair, start the app once with `workspace_dotnet_run` HTTP startup proof and record the startup receipt; leave browser screenshots and console proof to the validation step. Do not mark complete while required behavior, routes, persistence, PWA/static-hosting assets, tests, or command warnings remain deferred to next actions.

If validation found source under the wrong root, a sibling app or sibling test project, a nested copied/probe scaffold, or custom host output properties such as `BaseOutputPath`, `BaseIntermediateOutputPath`, or `MSBuildProjectExtensionsPath`, repair the approved product root itself. Do not complete by validating the sibling project. The final host project must build, test, and run from the contract root, with tests under that root's `tests` child and no probe/scaffold project directories left inside the product root.

## Evidence

Record commands, files, URLs, screenshots, console messages, errors, assumptions, and project-structure writeback references as applicable.
