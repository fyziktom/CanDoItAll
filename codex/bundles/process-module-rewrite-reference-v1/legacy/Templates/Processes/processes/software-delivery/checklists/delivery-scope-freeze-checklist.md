# Delivery scope freeze checklist

**Key:** `delivery-scope-freeze-checklist`  
**Scope:** local  
**Process:** software-delivery  
**Owner role key:** `delivery-manager`  
**Phase:** pre-release

## Summary
Confirms the delivery scope is stable enough for downstream QA, training, and release work.

## Entry criteria
Implementation is materially complete and release-sensitive downstream work is starting.

## Exit criteria
Scope change after this point is either rejected or explicitly re-opened with re-planning.

## Checks
- Release-candidate scope is named and versioned.
- Late additions are either rejected or explicitly accepted with impact review.
- QA, training, and release owners were informed of the frozen scope baseline.
- Open defects and known exclusions are captured.

## Evidence expectations
- Scope-freeze note
- Updated implementation plan
