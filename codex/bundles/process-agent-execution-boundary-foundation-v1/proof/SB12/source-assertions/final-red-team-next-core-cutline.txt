## Next Process Core Cutline

Decision: a follow-up bundle may start actual Process Core extraction, but only as a narrow dependency-neutral extraction with new pre-movement guardrails.

Allowed next-bundle movement:

- Create `CanDoItAll.Processes.Core` only if architecture tests first prove it has no EF, Razor, AgentFramework, Workbench, product-module, or driver-pack dependencies.
- Move only small dependency-neutral value objects, policy snapshots, and pure functions that can be tested without EF, UI, AgentFramework runtime services, or storage.
- Keep `CanDoItAll.Processes.Contracts` as the stable boundary for execution request/source/policy snapshots unless the next bundle proves a stronger typed model is needed.
- Add failing-first architecture tests before any production movement.
- Preserve process tool names, required-tool detection, receipt metadata, artifact lineage, and access/approval policy behavior with focused tests.

Prohibited next-bundle movement:

- Do not move EF entities, DbContext usage, Razor components, UI view models, runtime provider implementations, MAF composition, Tooling contracts, storage implementations, or driver packs.
- Do not introduce a Processes Core dependency from MAF, Tooling, Workbench, Projects, or provider assemblies without an explicit architecture decision and tests.
- Do not rename process runtime tools or weaken access/approval policy.
- Do not run small, medium, or mobile viewport proof unless the product target changes in a new requirement.
