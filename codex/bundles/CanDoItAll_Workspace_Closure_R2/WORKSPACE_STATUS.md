# Workspace completion versus application closure

| Surface | Rendering disposition | Remaining responsibility |
| --- | --- | --- |
| Settings shell/defaults/Secrets/Files/Provider history | Existing Core rendering leaf; preserve | Current owners, sensitive draft handling and regressions |
| API Access | Existing independent leaf; preserve | Instance-local auth/account/token owners and their tests |
| Storage catalog | Existing independent leaf; preserve | Catalog, routing, secret/driver and recovery-launch host |
| Storage Selection | Existing independent leaf; preserve | Agent parent Save and runtime allow-list remain the owners |
| Storage Recovery | Extracted renderer/session/neutral owner seam | Exact original intent and owner continuation authority |
| Data Sources | Extracted renderer/transfer/session; coordinated editor writer now corrected | Canonical profile, safe secrets, partial commits, owned restart |
| Configuration schema rendering | Neutral loop in Configuration.UI | Trusted component registry/adaptation remains production composition |
| Remaining Workspace Razor wrappers | Intentional hosts or compatibility adapters, not automatically residual defects | Keep the census tied to actual callers and rendering responsibilities |

This is structural completion, not certification that every application journey passed.
Current reports retain the 22-entry census / 11 module UI-file classification. This review
has not regenerated the entire recursive census locally; refresh it from the final checkout
before setting a final completion flag. [R02]

Current functional closure remains open for WCL-DEL1 and WCL-NAV1, dependency publication,
and explicitly unavailable live/environment proof. None requires inventing another Workspace
module or repeating the completed extractions. [R03, R04, R13, R14]

Update `docs/architecture/modules.md`: its older descriptions of two renderer extractions
and deferred Workspace surfaces are stale. Keep historical audit timestamps and evidence;
link current summaries to maintained boundary records rather than changing old bundles.

A backend module is allowed to retain route composition, policy, session ownership and
adapters. Do not demand zero Razor files as a closure metric. Conversely, a large editable
renderer remaining in an implementation assembly is not a thin host merely because its
filename contains Host. Apply that distinction to the remaining-module roadmap. [R16–R29]
