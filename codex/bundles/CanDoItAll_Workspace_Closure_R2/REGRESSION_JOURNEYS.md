# Real application regression journeys

These journeys preserve the user's requested coverage beyond one isolated settings page.
Run them against task-owned production hosts and synthetic data. Keep deterministic external
model boundaries distinct from live provider proof; do not seed the very effect being tested.

## A. Agent, history, deletion — primary DEL1 proof

Create a non-managed test Agent through existing setup/owner paths, stage grants in its real
editor, execute two real runtime turns through UI against a local scripted provider, and
independently confirm both terminal runs and exact history identities. Open the real editor,
confirm deletion once, then verify the outcome through applicable owners. Do not replace this
with a no-history Agent. Keep another Agent and its content unchanged. No broad wildcard grant
or manual JSON/index deletion may be used to complete the journey.

## B. Shared navigation and nested dialogs — primary NAV1 proof

Use the actual Settings/API/Catalog/Recovery/Data Sources/Agents/Simple Chats/Collaboration/
TestLab/Project Structure route sequence with rapid changes and controlled pending owner
reads. Include usage-scope changes and back/forward, nested dialog Escape/backdrop, initial
startup and permanent context closure. Track exact circuit and acknowledgement. A view that
survived in another circuit and unrelated dialogs must stay usable. Inspect accumulated logs
through the actual outstanding operations, not only the final page's errors.

## C. Project Structure file roundtrip

Open a concrete project and selected node, launch its actual floating Agent chat, read a seeded
file with an undisclosed test nonce, write a distinct safe managed relative file, attach that
exact file to the intended node, read metadata AND content, and reopen it through FileInteraction.
Verify exact project/node/Agent/run/proposal identities and bytes/hash outside model prose.
Use the shipped tool schemas; the known chain is workspace_write_file ->
project_structure_asset_create -> project_structure_asset_get -> project_structure_asset_content_get.
Keep sibling/project denial and reject-once controls, exact argument-bound approvals and no
replay. Deterministic provider evidence does not count as live model execution.

## D. Workflow, Scheduler and TestLab

Launch a saved immutable Workflow/version/input from UI; verify actual runtime events,
original source authority, one artifact and its content, plus explicit TestLab recording.
Use actual one-shot Quartz delivery for scheduled proof, not a direct runner call presented
as scheduler delivery. Read the saved plan/run IDs and confirm explicit replay/observation
cannot create another artifact. Preserve the max-output-token wire assertion and strict
incomplete-provider-response rejection.

## E. Previously extracted feature consumers

| Feature family | Required real behavior |
| --- | --- |
| Workspace Core/API/Data Sources | Defaults used by a consumer; Secrets safe metadata/value lifecycle; Files correct extension target; explicit history load; API deny/retry; A canonical before/B after owned restart; no transfer of instance-local accounts/tokens. |
| Storage/Resources | Picker Apply is only a parent draft change; explicit Agent Save persists IDs; runtime allow-list remains effective; promotion/reopen reads real safe bytes; Recovery uses original intent, never a new upload/run. |
| Collaboration | Notification/escalation, reply/read state, selection/draft retention and full host-log check after shared navigation. |
| Prompts | UI-created immutable item/version used by the actual composer, exact independent content read-back. |
| Plugins | Safe packaged invocation and real denied grant path before network work; preserve committed identity after secondary errors. |
| Memory | Supported query and result origin/provenance; changed provider cannot relabel old result; unsupported mutations and unsafe provider URLs still refused. |
| CRM/HR | Exact linked person/agent/project/task records and original approval policy; no rate/private fact disclosure outside authority. |

These are regression obligations, not permission to add new tools, provider features,
workflows or permission protocols. Current tests can cover multiple rows, but each row
must identify which assertions and owner evidence actually prove it.
