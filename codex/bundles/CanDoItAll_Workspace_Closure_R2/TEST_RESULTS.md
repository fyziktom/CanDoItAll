The one Stable failure expected a public Simple Chat operation to flush an unrelated tracked
edit from the caller's DbContext. New per-operation scope ownership intentionally prevents
that coupling. The corrected private test targets its actual tracked owner and separately
checks that the public call leaves the unrelated edit untouched. This is plausible and
consistent with the inspected runner and real-context retirement test, not evidence to undo
the isolation fix. Rebuild/run the owning class and new full checkpoint as required. [R07, R08]

The remaining browser failures are DEL1 and NAV1. Six blockers are five actual inference
permissions and one external inventory credential. The generated-app Scenario04 returned
without opening a browser because its fixture was absent. Keep these categories separate.
Missing authorization is not a software defect. Likewise the existence of a valid credential
does not authorize spending or external side effects.

Require discovery and executed identity reconciliation, including any runtime theory expansion
or colliding display names. Do not sum repeated test attempts as unique coverage. Report each
accepted source checkpoint independently from a timestamp sampled at the end of a long run.
Raw attempts remain append-only; a later focused pass cannot make a prior broad log clean.

The next final checkpoint is explicitly required because the remaining repair may change
shared ownership, navigation and deletion persistence. Iterate with narrow builds/tests,
then freeze and run broad gates once the fixes have settled. Do not run the whole suite
repeatedly as a substitute for diagnosing a failure.
