# Closure contract and final report

## Independent decisions

Report these separately, not as one ambiguous PASS:

- Workspace rendering/boundaries complete: the census describes the extracted renderers and
  legitimate remaining production hosts.
- Product corrections closed: WCL-R1, WC-C1, WC-C2 and WC-C3 have actual reproductions, bounded
  corrections and passing controlling tests; preserve the earlier fixes.
- Harness ready: original scopes/effects, live approvals, status/budget/evidence collection
  can produce reliable proof without masking failures.
- Required validation closed: every required group has actual accepted proof on the repaired
  source pair or an explicit still-open blocker. No user waiver is synthesized by Codex.
- Dependency delivery ready: tested Components/app inputs are reproducibly consumable, not
  local changes hidden from the intended build/CI path.

`ready_for_next_module=true` requires all five axes, mandatory gates and no open critical
finding. If live authorization or external fixtures remain unavailable, state code closure
separately and keep unqualified readiness false. If only remote dependency publication is
pending, call the local pair verified and list the exact operator delivery step; do not say
remote CI is verified. A later operator can explicitly accept a bounded risk or authorize a
remaining proof, but that decision is not made by the code agent itself.

## Evidence ownership

Keep raw attempts append-only. Each result names actual app commit, exact source manifest,
sibling SHAs, commands, environment, expected/discovered/executed test counts and semantic
outcome. Hash files under an owned evidence root. The preceding bundle is historical input,
not a new test result. Test tool success only validates format/bookkeeping and hash matching;
it cannot certify authenticity of application execution.

Fill an external copy of templates/closure-results.json. Run the package validator against
the sealed handoff and the closure validator against external results/evidence. The latter
rejects a ready verdict with missing groups, wrong modes, stale source, unknown blockers or
unverified dependency delivery. It does not prove the test actually did what the author says.
Independent review of owner/UI evidence remains required.

Run fresh proof after the last executable changes. If a valid earlier result is kept for a
narrow unaffected group, document an explicit source delta and why it is unaffected; do not
silently edit its checkpoint. For the three repaired shared lifetimes and final Stable/browser
checkpoint, fresh execution is required. The validator intentionally accepts final readiness
only for results bound to the declared final checkpoint; keep older runs as history.

## Small fixes versus larger findings

Fix a small demonstrated local defect with its owner regression and real consumer test.
The three named shared failures in this bundle are already authorized repair work; do not
close the assignment by merely regenerating their maps. Investigate enough to choose the
correct lifetime boundary, then implement and validate it.

For a newly discovered complex schema/authority/transaction/cross-owner problem, stop the
unsafe lane, preserve original effects and produce a causal map using templates/finding.md.
Include scope, affected calls, original IDs, operation timeline, irreversible steps,
pre/post evidence, what is known versus inferred, historical attribution, test coverage and
proposed bounded repair phases. Continue independent safe tests. The unresolved issue remains
a blocker; mapping is not a fix and adding its stack to an allowlist is forbidden.

## Required final artifacts from Codex

A readable closure report; current census; updated findings with exact disposition; per-group
semantic campaign result; fresh Stable and full browser manifests; typed live execution and
provider journal evidence when authorized; source-pair/dependency delivery manifest; mandatory
static/docs/secret results; and ownership cleanup receipt. Keep raw confidential artifacts
ignored and only publish sanitized excerpts/hash references permitted by repository rules.

Describe actual executed pass/fail/blocked/rehearsal/not-run numbers, not the count of TRX files
or commands as coverage. Do not sum repeated tests or a single live execution twice because it
supports multiple groups. If a failing run is followed by a focused repair, retain both and
state whether an entire frozen broad run was repeated.

The next module is explicitly out of scope even if all gates pass. Finish with the readiness
decision and precise remaining obligations, not a new extraction proposal.
