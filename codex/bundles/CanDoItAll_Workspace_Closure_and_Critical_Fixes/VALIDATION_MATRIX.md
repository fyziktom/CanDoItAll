# Validation and cross-application closure

The executable inventory is [closure-plan.json](closure-plan.json): 29 prior campaign groups
plus six closure-specific groups. The prior raw campaign plan is retained byte-for-byte under
[reference](reference/previous-campaign-plan.json), but its old budgets do not authorize new
spending. No fixed test count from the previous source is an expected count for new code.

## Order and source validity

Start with each controlled reproducer and its owning test. Build changed production projects
before refreshed test assemblies. Use current repository filters and build-backed discovery;
record expected methods/cases before running and reconcile actual data-driven expansion.
Use --no-build/--no-restore only for the verified current assembly. Zero discovery never passes.
All tests of the repaired Components assembly must name its exact source revision.

Then freeze an application + sibling source manifest, run a new complete documented Stable
checkpoint and the complete current non-quarantined non-live browser inventory. Run gated
live selections separately with explicit authorization. Keep a complete semantic inventory
including unavailable cases; use runner outcomes and actual execution modes, not totals alone.

A correction after the checkpoint requires an explicit invalidation decision. A shared owner,
common fixture, DI scope, generic component, dependency graph or runtime change invalidates
broader evidence. A narrow observation correction has a bounded rerun but does not rewrite
the old run as all-green. Do not run mismatching outputs concurrently or ignore stale builds.

## Shared-host browser sequence

Keep the full current browser run. Additionally run a bounded explicit sequence in an owned
host: Settings Core -> API open/close/retry -> Storage/Recovery -> Data Sources/transfer close
-> Agents/Simple Chat shell -> Collaboration -> TestLab -> Project Structure/asset preview ->
back/forward, then retire/reopen the context. Vary controlled query completion before and after
navigation. Record iteration count/order and captured UTC events; use fixed seeds when varied.
A route title is not hydration: wait for actual component/controller readiness.

Do not change every existing test to reuse one host; preserve intended test isolation. The
joined sequence is an additional test of shared lifetime behavior. Conversely, do not defeat
it by using a new process for every click, omitting the shell or never closing dialogs.

## Test oracle and evidence

Assert semantic terminal state, exact original identity, persisted ID/version, actual file
bytes/hash, the permitted number of durable effects and absence outside the fixture scope.
Inspect both UI outcome and owner state. A disabled button means busy as well as complete;
a generic Ready marker may predate the action. Each test must await its own operation.

Classify every failed test as product, harness, environment, live-model/provider, budget or
unresolved, with supporting facts. Keep mixed runner results intact; do not quote a repaired
aggregate as if it were a fresh all-green run. No skip/quarantine/filter change is a repair.

For Windows work execute the available Windows host/portability lanes. Provision a private
Linux container and run relevant Linux headless/runtime gates when supported by the existing
environment. Do not invent a macOS pass or silently change CI platform/shard budgets. Record
platform coverage and any unavailable remote run explicitly.
