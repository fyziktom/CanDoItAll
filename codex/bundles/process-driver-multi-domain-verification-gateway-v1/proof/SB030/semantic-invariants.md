# SB030 Semantic Invariants

## SB030_INV_001
- Invariant ID: `SB030_INV_001`
- Source raw note: `Prepare broader phases toward stable Core and domain drivers`.
- Expected behavior: Gate J can close only when the Office verifier is proven read-only and evidence-only through package dependency checks, supplied-content envelope policy, positive supplied email/document metadata proof, missing metadata diagnostics, side-effect denial proof, audit fact assertions, no-mutation response proof, and no runtime/connector source scan.
- Disallowed shallow implementation: claiming closure because the package exists, because one happy-path Office item returns diagnostics, or because the source lacks a single Graph token while skipping envelope binding, denied operations, audit facts, focused pass count, and no-side-effect source proof.
- Failing-first test: `bundle://proof/SB030/transcripts/red-team-office-evidence-shallow-proof-rejection.txt` rejects closure without positive Office evidence tests, missing metadata tests, envelope denial tests, side-effect denial tests, audit fact assertions, no-mutation assertions, 5/5 focused pass proof, and no-side-effect source scan.
- Passing test: `bundle://proof/SB030/transcripts/gate-j-proof-index.txt` verifies SB028/SB029 manifests, clean build, 5/5 focused Office tests, Gate J source scan, red-team rejection, and this invariant contract.
- Changed source files: `repo://src/CanDoItAll.Processes.Drivers.OfficeEvidence`; `repo://tests/CanDoItAll.Tests.Unit/ProcessDriverOfficeEvidenceAlphaTests.cs`; `repo://src/CanDoItAll.Processes.Drivers.Abstractions/Evidence/ProcessDriverSuppliedEvidenceContent.cs`; `repo://src/CanDoItAll.Processes.Drivers.Abstractions/Evidence/ProcessDriverSuppliedEvidenceContentRules.cs`; `repo://src/CanDoItAll.Processes.Drivers.Abstractions/Permissions/ProcessDriverCapabilityScopeRules.cs`.
- Production assertions: Office verifier accepts only supplied in-memory item metadata/text, binds `OfficeEvidencePayload` to `OfficeReadonlyArtifact`, returns immutable diagnostics/audit facts, and always reports `NoMutationPerformed: true`.
- Security assertions: side-effect operations for category mutation, task creation, document write, Graph call, and attachment fetch are denied before analysis; source scan proves no runtime host, registry, selector, provider, DI, Graph, Office365, Gmail, HTTP, process, file, directory, DbContext, workspace, storage, UI/media, or secret-like drift in Gate J targets.
- Attachment fetch is represented as a forbidden external Office call attempt because the current typed driver contract has no distinct attachment-fetch operation; adding a new operation enum value is out of scope for Gate J.
- Adversarial negative case: a closure that checks only package existence or one no-Graph scan is rejected with simulated verifier exit code 1.
- Downstream dependency check: SB031 and later domain verifier phases may proceed only from proof that Office evidence remains supplied-content-only and mutation-free; if Office evidence proof weakens, reopen SB028-SB030.
