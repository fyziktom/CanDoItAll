# Execution boundaries and completion

## Safe scope

Read current repository/family rules before work. Preserve the user's active branch and all unrelated changes. An evidence SHA is never a forced checkout. Keep GPG signing enabled; use the existing unlocked session/agent where applicable rather than changing keys or disabling signing. Local commits may follow repository instructions; this handoff does not authorize push, PR, merge, branch deletion or package publication.

Use task-owned PostgreSQL 18, ports, process/container IDs, browser contexts, storage roots and fixture identities. The ordinary application on 5032 and retained user data are not test fixtures. Inspect exact ownership before stopping or removing anything. A denied cleanup must be reported, not bypassed through a different interpreter/container/mount. Preserve necessary private evidence; sanitize shareable copies with provenance rather than deleting raw failures.

Paid/live inference is not authorized. Preserve the exhausted 40/40 journal. Known remote provider prerequisites, generated-app requirements and unavailable platforms remain explicit; they do not justify weakening production policies or inventing passes. A deterministic scripted provider journey is labeled as such.

## Sequencing

E0 inventories and scopes; S0 closes the bounded known-refusal and modal-interop gaps; P2 extracts and wires both real Files surfaces; the final phase validates actual owners, supported-desktop browser behavior, independent publish and the development loop. Do not stop after S0. Do not create a third module task.

The original shared v3 directory remains sealed and unchanged. Update current maintained architecture/testing docs and the Projects census, not the old shared audit as though it were a live tracker. Archive this package only in the repository's normal location if desired; do not recurse older bundles into new bundles.

## Triage

Fix small reproduced state, callback, renderer, local owner-adapter and test-observation errors in this task. Require causal evidence and regression coverage. Do not classify every late successful run as a repair. New authority breaches, wrong-profile writes, data loss or inconsistent durable owner outcomes stop that affected mutating path.

If a remedy genuinely requires a new durable protocol, schema migration, policy redesign or broad multi-owner restructuring, map the exact entrypoint, origin, awaits, effects, consumers, original/current source, reproduction, scope and proposed corrective stages. Preserve the evidence and mark the affected acceptance group blocked. Continue unrelated safe work; never claim the entire P2 complete when a required critical path is unsafe.
