# Native browser and HTTP journeys

Use the real Web entry point and production renderer/owner lifetimes on a task-owned
PostgreSQL database. Test-only controls may seed a valid fixture or delay a real result;
they must not substitute successful persistence, retain scoped authoring engines, disable
policy or expose a new production fault route. Record console/page errors, affected HTTP
failures, screenshots/trace and native read-back. Screenshots alone do not prove a commit.

## B1: resource-backed role delete and reimport

Open a definition with a real materialized resource-backed unreferenced role. Verify its
resolved purpose/template defaults. Delete through the UI and observe the accepted receipt,
selection and actual stored revision. Open an independent browser context/native scope,
import the same source role and verify exact fields/resource identity in storage and UI.
Repeat with whole-process import when its remapping is affected. Repeated dispatch or lost
postcommit response must not allocate a second revision/import. Preserve unrelated role,
raw drafts and selections. Reopen after restart for the persisted-state assertion.

## B2: project HTTP producer and native surface agree

Publish a valid authoring fixture with driver changes/explicit empty activations. Open the
actual project/source in Workbench, and use the actual HTTP `/launch/check` and `/launch`
endpoints on the same real host (normal local/authenticated test caller as applicable).
Compare native stored preparation, variables, effective publication and assignments with
the corresponding native/UI producer's meaning, not random per-operation IDs.

Hold the definition boundary, publish the next revision, and complete the earlier preparation.
It must stay internally coherent or be refused before acceptance. Repeating a retained intent
must return the original preparation/run without invoking enrichment again. Review/show the
accepted run in the real native surface; retain source links and expected workflow output.
Do not use only direct helper calls as proof of HTTP integration.

## B3: legacy retained child, no accidental new child

Seed an authentic predecessor-format retained run/parent linkage in the isolated host.
Exercise the actual re-entry/recovery surface. When origin is authoritatively known, show
and reuse the same child. When it is unproven, show the precise safe recovery/refusal state
and ensure a second click/retry does not create a replacement. The database oracle must
count the relevant run, assignments and parent-child link, and compare original plan hashes.
Also exercise a project recreated under the same public ID without binding the old child to it.
This may be predominantly an integration test plus one meaningful browser state; do not
build a new recovery UI solely for the test when an existing operator path is sufficient.

## B4: retained PC3 restart/execution floor

Keep the existing exact publication-v1 preparation, later publication-v2, new OS-process PID,
original admission acceptance and real workflow completion regression. It is complementary
to project+node API B2: the old restart fixture's global API call did not exercise that helper.
Use production scopes and the same isolated database/profile, not singleton fakes. Stop only
owned PIDs. Retain artifacts/result/lineage, accepted-run replay and no duplicate workflow.

## Regression selection

Select relevant existing Processes/Workbench native browser cases, chat/context/attachments,
files, cancellation and voice according to changed composition/source lifetime. Inspect all
implicit consumers before omitting a lane as unaffected. No replacing canvas with a placeholder,
removing interactions, disabling assertions or adding blind fixed sleeps. Wait for real
interactivity, loaded editor/manager selector and settled async effects before interacting.

Report each lane separately: source revision, sibling revisions, build/configuration, browser,
owned resources, exact selector/filter and outcome. Never equate a sandbox render, bUnit
interaction, direct native operation and actual browser journey; they prove different layers.
