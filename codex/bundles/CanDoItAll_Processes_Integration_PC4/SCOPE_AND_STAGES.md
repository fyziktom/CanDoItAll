# Scope and staged execution

Stages are tested commit opportunities, not approval gates or stop points. Implement the
complete task after entry. Prefer simple existing native seams; there is no interface,
partial-file, new-project, method-count or test-count quota.

| Stage | Required work | Exit evidence |
| --- | --- | --- |
| S0 | Local PGP unlock, current instructions/source/sibling/index ownership, fresh impact plan; reproduce relevant findings against current code | Captured source/configuration, exact regression fixtures, isolated resources and baseline outcomes |
| S1 | Coherent canonical HTTP/native producer selection, enrichment and captured compile input; preserved replay-first semantics and API documentation | Actual HTTP/native variable and plan oracles, input matrix, held publication race and replay tests |
| S2 | Predecessor-format project/child recovery with origin-aware results, no duplicate fallback and preserved exact historical plan | Real predecessor serialization fixtures, same-origin/recreated/unproven matrix, complete caller-path tests |
| S3 | Role resource/head ownership during delete, add and imports; immutable history and operation replay | Resource-backed native sequences and exact object/key/hash assertions |
| S4 | Real UI/HTTP journeys, relevant restart/workflow/agent/file/voice regressions; clean build at selected sibling tuple | Browser/native evidence, no retained-owner or fake persistence shortcuts; ownership cleanup |
| S5 | Impact-qualified broad closure, portability, docs/OpenAPI, dependency census and remaining work; signed final source/report checkpoints | Source-addressed evidence with unrun lanes visible, no shared update or artificial new extraction |

## Authorized implementation boundary

Affected native Application/Workbench/API mapping and narrow owner adapter/UI-consumer fixes,
tests and maintained documentation. Use the existing Processes persistence, migrations,
contracts and renderer libraries. Small cohesive return data at the internal producer seam is
reasonable; a new orchestration layer that forwards everything is not.

Inspect every actual consumer of changed APIs through CodeAnalytics plus text/DI/serialization
review. Include direct native callers without optional admission and replay paths. A test
request lacking new metadata is sometimes a production compatibility case, not automatically
an invalid test to rewrite into the new shape.

Do not authorize a new portable transfer format, history purge, generic paging redesign,
new remote-authoring write API, JWT ownership overhaul, UI-auth rewrite, model/provider
upgrade or another component migration. Existing authoring transfer refusal remains visible.
No user database, main application on port 5032, retained provider resource or paid model may
be used as a fixture. No sibling commits/pins are changed only to conceal a failing build.

## Drift and unexpected blockers

If a finding is already corrected, prove it on current source and retain the test; do not
reintroduce the old bug to match this document. If a proposed counterexample cannot occur,
record the actual preventing invariant and test that invariant. Fix real adjacent regressions
needed for these paths, but do not expand into a new major subsystem as an incidental repair.
A genuinely necessary schema adjustment must be justified against complete owner/history
semantics and appended canonically; no destructive rewrite or new runtime-created tables.

If a raw broad campaign fails, preserve it. Use current repository rules for exact affected
repair evidence and final-source bridging; a single flaky rerun is not root-cause proof.
Report unresolved blockers without silently reducing scope or representing incomplete work
as complete. Continue other assigned stages where safe.
