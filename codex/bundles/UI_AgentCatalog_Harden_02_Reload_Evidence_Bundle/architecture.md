# Evidence and sandbox state boundaries

Evidence policy: retain the two predecessors' original precompacted proof sets, totaling about 5.2 MB, as an explicitly bounded set copied from their already hash-verified manifests. They include original compressed TRX/console, a compressed full portability scan, exact ledgers/calibration/failure records and the referenced representative JPEGs. No raw multi-megabyte TRX/console or additional runtime directory is imported. The full scan is retained intentionally for its original static-gate audit; it is not a new execution. Root ignore exceptions are scoped to these named bundle proof directories and the current successors' evidence/proof. Bundle-local attributes preserve historical proof bytes. Current manifests cover exactly the approved Git artifact set, excluding only the manifest itself. A local validator checks existence, hashes, Git coverage, relative Markdown links and index/tree availability. Historical proof gains a successor erratum, not altered results.

Sandbox state: one typed CatalogSandboxContext describes scenario, layout and catalog selection. Stable explicit query tokens, not enum ordinals, bind the existing sandbox page. Accept agent/team IDs only from the embedded fixture. Default Normal/Matched/no selection; invalid values normalize to that safe state. NavigationManager replace-history transitions retain the current specimen across a real reload. No production page, route policy or navigation framework changes.

Retain existing Button/Cluster/Stack controls and real catalog/card/tree/tooltip. No new CSS or asset registration. Existing first viewport and separate card/tree scroll owners at 1600x1000 remain unchanged. Isolated fixture IDs are not runtime authority or bookmarks for product routing.
