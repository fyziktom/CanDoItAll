# Execution, review and completion policy

Work sequentially through S0, complete capability authoring, complete teams, then final integration.
Local unit/form/native tests run as each real change settles. Source-census and existing tests
prevent speculative refactoring. Do not use longer runtime as a reason for repeated broad builds,
exhaustive responsive tuning or creating many thin projects. The longer run should close a useful
whole authoring family and its actual integrations.

Before each changed topic: build changed production projects, build owning tests, record exact
filter and expected discovery then actual discovery, execute and retain evidence. A changed
assembly invalidates an earlier --no-build assumption. A zero-test selection is not proof. Use
current repository test bootstrap/disposal helpers; don't repair renderer races by weakening tests.

At final freeze execute complete affected authoring/team families and the named application
journeys on the actual source pair. Make and document one broad-scope decision using current
Testing/CI rules. A change to shared catalog/Core persistence, public contracts, runtime setup
policy or shared fixtures may require a frozen Stable checkpoint. If triggered, run once after
settling changes and reconcile all failures accurately. A narrowly supported follow-up never
retroactively turns a mixed entire run green. No second full run solely for a headline.

Always perform current portability-static scan/review/baseline discipline and final enforcement
without --write-baseline. Include full protected source; fix actual new/stale findings. Do not
weaken scanner suffixes/rules to hide artifacts. Distinguish tracked source scan from ignored
historical evidence scan, preserve original synthetic fixtures and private originals, inspect
large reports and export only sanitized current artifacts. Read current docs/testing.md and CI.

## What must be complete

- Both complete authoring renderers and all real typed children are independent from native modules.
- Whole team metadata/icon/member flow is extracted with actual parent/native behavior preserved.
- Existing definition/assignment/Verify/grouping differences and authority remain correct.
- Current raw inputs, effect origins, accepted identity and concurrency are proven.
- Source/published independent scenarios, desktop geometry and repeated watch probes have evidence.
- Native setup, parent composition, two-owner changes, agent/file/shared provider/History and
  appropriate Workflow/TestLab journeys pass on the final relevant binaries.
- Required source checks and coherent signed commits exist; local/remote dependency delivery is separate.
- Current remaining-renderer census is precise. No imaginary UI feature is added to fill a roadmap row.

## Small versus complex follow-up

Repair a reproduced localized lifetime/validation/reconciliation/test-oracle problem now, including
an additive owner-specific guard if compatible. Preserve failing-first evidence, callers and
regressions. For changes requiring schema, authority redesign, distributed atomicity or broad
runtime policy, record a separate finding with entry/ref, minimal sequence, call graph, actual
native effects, unaffected controls, scope/performance consequences and proposed repair bundles.
Stop the unsafe affected mutation, not all independent work. Do not claim a critical finding fixed
because it is mapped. Conversely, don't stop this entire run after a small documentation or UI fix.

## Report

Use [evidence template](templates/evidence.json) outside this package. Report each required group,
commands/discovery/counters, original and follow-up attempt identities, source fingerprints,
artifact locations, actual local signed commits, source-pair and dependency-delivery status.
Readiness to continue development, completion of selected UI scope and application release-readiness
are different conclusions. This bundle never supplies prefilled product passes.
