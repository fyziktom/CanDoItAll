## Proof retention

Each attempt has source/assembly/image identity, command, discovery, result counters, timestamps
and safe artifact references. Keep initial failures and fixes distinct; cover the exact original
cases in follow-ups. A browser showing a toast, a stubbed service, HTTP 200 without terminal
completion, or an unexecuted live gate is not end-to-end success. Record denied/error scenarios
as successful negative assertions only when their actual assertions passed.
