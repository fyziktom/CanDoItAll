# QA Prompt

Independently determine whether the repaired behavior and proof satisfy the owned raw input. Read actual source and runnable evidence, not just status tables. Check the strongest negative case: SDK observes stream failure, quoted credential is absent after decrypt, retained retry input survives cleanup, cache observes external revocation, or schema describes real fields.

Verify dependency direction, current source/config/dependency hashes, exact test discovery and relevant host/schema provenance. Reject stale binaries, zero cases, row-count-only proof, fixture-only producers, skipped host requirements disguised as stable tests, and diagram-only architecture claims.

Record Pass/Fail/Blocked with exact missing proof and downstream invalidation. Preserve legacy authority and three-application requirements. Do not change product code during independent review.
