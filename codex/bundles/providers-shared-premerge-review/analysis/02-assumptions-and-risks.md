# Assumptions And Risks

## Assumptions

- Current scope is review and preparation; repairs are future work.
- Local development is the review base; recheck freshness before merge.
- Preserve accepted application-visible history-attempt semantics; SDK/inner HTTP retries are not an exact wire/billing ledger.
- OpenAPI is primary schema export; PostgreSQL gets separate EF SQL evidence, not hand-edited schema.
- No paid provider requests, mobile redesign, invented history APIs or unrelated sibling changes.

## Critical Path Risks

- Test failed streams from an external SDK, not only private completion tasks.
- Cache changes must preserve cross-process revocation, secret-deletion and eligibility checks.
- Retention must preserve shared retry inputs while any retained attempt references them.
- Redaction is bounded pattern/known-secret removal, not universal DLP. Already-retained Detailed content needs an explicit cleanup decision without copying real secrets.
- Export only from an identified final host; current localhost counts are unversioned observations.
- Original SB07 three-application proof and host limits remain binding.

## Validation Risks

- No current product build/test pass is claimed.
- Allocation/query/throughput changes need measurements; no invented speedup.
- Scoped cycle absence does not establish whole-solution acyclicity.
- Shell sandbox ACL setup failed before execution; approved escalation enabled review commands.
- Active skill writes and remaining legacy host authority are future execution boundaries.

## Reopen Triggers

- New source, merge base, SDK, dependency mode, authorization or schema invalidates related proof.
- Wire changes reopen SB06/SB08; capture/retention changes reopen SB03/SB04/migration proof.
- Cache freshness changes reopen SB02/SB05 and host acceptance.
- Do not close a legacy gate by renaming it or substituting weaker evidence.
