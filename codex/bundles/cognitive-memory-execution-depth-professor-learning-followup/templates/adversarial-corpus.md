# Adversarial Cognitive Memory Corpus

Use these cases as minimum scenarios for tests.

## Clustering

- Same project/source/month but unrelated topics must not become aggregate-ready.
- Same generic entity token but different claims must not become aggregate-ready.
- Same semantic topic but mutually contradictory facts must split or require review.
- Different titles/topic keys but overlapping normalized claim/entity/relation support should merge.
- Restricted and unrestricted facts must not silently aggregate into a public brief.

## Dreaming

- Aggregate canonical memory must not contain `Cluster quality:`, `Shared signals:`, or similar diagnostic boilerplate as knowledge content.
- Aggregate claim must fail validation when source maps exist but do not support the claim text.
- Duplicate aggregate with changed title but same claim/source signature must be detected.
- Machine-generated-only ancestry must not become strong stable memory.

## Professor/curator

- Ambiguous correction across multiple recall memories must create review.
- Explicit correction should only mutate targeted memory/claim.
- A direct curator-applied memory must not be valid assimilation proof for its own professor anchor.
- Assimilation requires a distinct derived memory/aggregate/repeated-use observation.
- Fading requires assimilation and retained provenance.

## Recall

- Brief must be query-shaped and concise, not title-grouped concatenation.
- References hidden by default but available for each statement/claim on demand.
- Restricted references stay hidden unless policy explicitly allows them.
- Contradictory or stale facts produce caveats, not an overconfident answer.
