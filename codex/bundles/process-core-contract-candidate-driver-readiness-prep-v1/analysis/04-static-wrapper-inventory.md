# Static Wrapper Inventory And Movement Plan

## Scope
SB025 inspected the current dispatch source after SB024 closed. The deliverable is an inventory and movement plan only. No production code was changed in this subbundle because the remaining wrapper surface is broad and Gate I must prove parity after any pure-rule movement in SB026.

Browser validation is N/A: this is a runtime/service source inventory with no UI, Razor, CSS, JS, TS, image, or media scope.

## Classification Rules
| Classification | Meaning | Movement rule |
| --- | --- | --- |
| Pure rule | Deterministic decision, normalization, path/token parsing, or DTO matching with no EF, storage, workspace, service scope, filesystem, logging, AgentFramework execution, or transition write. | Candidate for SB026 movement into named module-local rule families if focused parity tests cover the call sites. |
| Application helper | Uses DB, storage, filesystem, service scopes, process transitions, workspace writes, logging, AgentFramework execution, or mutates an object. | Do not move to a pure rule family. Keep behind explicit service/coordinator names. |
| Compatibility boundary | Converts dispatcher nested models, preserves legacy internal test/caller entry points, or bridges old dispatcher aliases to module-local models. | Keep until a dependent gate removes or narrows the caller surface with parity proof. |

## Movement Sequence For Gate I
1. Move or remove the low-risk pure wrapper entry points first: route eligibility and subprocess artifact resolver wrappers.
2. Move only already-factored forwarding wrappers in artifact path/text/provider-native/quality families after focused tests cover summaries, matching, and projection keys.
3. Leave any method that touches EF, service scopes, workspace filesystem, storage, transition writes, AgentFramework execution, logging, or mutable editor state in an application service/coordinator.
4. Leave dispatcher alias overloads as compatibility boundaries until tests and call sites consume `ProcessArtifactExpectationSnapshot` or route-owned DTOs directly.
5. Gate I must prove no `CanDoItAll.Processes.Core` project, no production process driver API, no UI drift, no stub markers, and no behavior simplification.

EF, filesystem, transition, workspace, AgentFramework, and adapter compatibility behavior must stay out of pure-rule families.

## SB025 Decision
The smallest safe SB025 change is this inventory plus proof scans. SB026 owns the actual pure-rule movement, and SB027 owns parity proof plus the Core-candidate list.
