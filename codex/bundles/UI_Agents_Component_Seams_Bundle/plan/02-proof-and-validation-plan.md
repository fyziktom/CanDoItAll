## Real-host browser proof

Use the actual application at 1600x1000 or larger, recording source/sibling identities, isolated data profile, exact existing URL, action sequence, screenshots and console/Blazor errors.

1. Overview metrics and selection/context; directly open Providers and RequestHistory and verify lazy behavior with instrumentation/test evidence.
2. Catalog select versus open, managed chat readiness, team/member result reconciliation and current requested agentId open-once behavior.
3. Editor default and non-default typed sections with retained draft, real nested storage/avatar/capability UI, and Memory/provider refresh interactions.
4. Ordinary save stays open and preserves fields; create then save again updates the returned identity; close returns to usable catalog.
5. Clear-to-blank, delete cancel/success and exactly one completion; mutation proof uses disposable records.
6. Overlay stacking, internal scrolling, sticky actions, close/escape/focus return, notifications and public Workflows navigation.

Deterministic component/integration tests own exhaustive conflict/failure/race combinations. Browser smoke must exercise representative real production wiring; static screenshots alone are insufficient. Do not unquarantine unrelated broad browser flows or expand to responsive redesign.
