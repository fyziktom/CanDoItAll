# Execution gates and honest closure

## Stages

Entry: inspect current checkout/instructions/history and arrange PGP unlock. Preserve source pair,
ordinary hosts and baseline artifacts. Signed commits are required at coherent checkpoints.
S0: execute actual multi-container baseline, native/default/custom model parity and source/client
UI; reproduce/fix two findings and any bounded newly proven defect; commit tests/fixes.
PP2a: sharing/publication/import rendering + real owner seam; targeted tests; signed checkpoint.
PP2b: source editor/discovery/sync/refresh and nested dialogs + independent sandbox; targeted
native/lifetime/consumer tests; signed checkpoint. Do not stop after one surface.
Closure: final image, rerun required multi-container + UI/consumer/security lanes, frozen common
checkpoint as justified, static gate, dev-loop experiment, safe report and final signed commits.

## Test selection and source provenance

Read current docs/testing.md and CI. Build every changed production project directly; determine
the owning test projects with CodeAnalytics or source census. Confirm expected and actual discovery
for new filters, including data rows. `--no-build --no-restore` only with fresh matching owning
outputs. Report exact commands/configuration, images, test assemblies and source/sibling hashes.
Neither zero discovered tests, a disabled live gate, skipped fixture nor echo-only surrogate is a pass.

This combined task affects a shared administration boundary and multiple app instances. Plan one
final frozen Stable checkpoint once sources settle, plus the separate desktop/container campaign.
Use current named-trigger policy to justify any narrower alternative; never repeatedly run a five-hour
suite just because a phase ended. Run long tests and watch probes in separate serialized output
lifetimes. Post-checkpoint fixes require affected-owner/consumer reruns and a documented source
invalidation review; do not relabel an older whole run all-green.

All protected changes require full portability-static review and final enforcement without a
baseline-writing flag. Inspect added/stale findings and only update intentional baselines with
rationale. Do not change scanner rules or whitelist secrets/real failures to clear the gate.
Run docs/whitespace and safe-artifact scans. Historical provided manifests remain unchanged.

## Findings triage

Small, causal UI/state/tooling bugs are repaired immediately with regression tests. Do not dismiss
an unfamiliar failure as flaky without an experiment. Changes to authority, database schema,
public routing/receipt protocols or multiple owners require exact call graph, original/current
source distinction, stage/effect evidence, risk and proposed repair scope. Do not make a speculative
redesign. Stop the affected mutating path on wrong-target/unauthorized writes; other safe tests can
continue. Distinguish product defects, old defects, environment blocks and test-oracle mistakes.

## Required closure report

Report separately: S0 actual multi-instance pass; PP2 rendering complete; final-image name/default/
routing matrix; owner and consumer results; shared sandbox/publish; repeat hot reload versus restart;
Stable source checkpoint; static gates; signed commits; dependency delivery; unresolved risks.
Do not set `all_provider_ui_complete` or `application_release_ready` true: Request History and
other provider/authoring/operational surfaces remain. No push/merge/public external publication.

Use template copies in an ignored owned run directory. Preserve failing attempts with private
raw evidence and safe hashes/counts. Safe snapshots must not include secret values, full provider
requests, auth headers, PGP material or unrelated personal data. Treat visual screenshots as private
until reviewed/redacted. List exact resources stopped/removed and retained diagnostics. Do not
clean up ordinary app data or destroy failing-test evidence before it is understood.

Missing Docker or GPG interaction cannot be reported as a completed requested task. Seek native
unlock early and use authorized owned local fixture setup. At final delivery state any genuine
block explicitly; do not quietly leave all changes uncommitted because the signing step was deferred.
