# Required outcomes
The 15 adjudicated findings and 31 proof topics are acceptance obligations, not optional suggestions.

Local: provider-specific known rejection/conflict, known commit with identity, commit with secondary warning, genuinely unknown outcome, and owner cancellation. Capture independent immutable submission before any await. Bind first-save ID before reads, preserve later edits/context/raw fields and reconcile authoritative token. Retry reconciliation makes zero writes. Target/operation owns busy/result/notifications; A/New/disposal cancels or fences old effects. Unknown write blocks blind replay. Health (local persisting vs imported diagnostic) and draft discovery retain distinct boundaries.

Shared: typed semantic operation, affected/retired IDs, remote-field and membership flags, canonical commit/warning, genuinely unknown scope. Producers provide IDs. Unrelated/new/local drafts survive metadata refresh with exact context/section/raw values. Only affected imported projection reloads; retirement/missing/malformed fails closed with same ID. Publication-only updates do not reload local draft. Unknown scope marks stale/retry without replacement. Sharing target and sources overlay own token/generation and every continuation; no global CloseAll.

Authorities: local alias/enable intent and selection belong locally; source URL/credential belongs to source; capabilities/models/publication shape belongs to remote catalog; canonical rows, cached projections and materialized runtime are distinct. Enforce guards before diagnostic/connector effects. Preserve sanctioned sanitized health/test chat. Existing publication/import audit records stay permanent.

Publication contract A: reads create no identity. First explicit Publish creates permanent identity atomically with publication, only when eligible. Before identity, generic local delete remains permitted. After first Publish, including Unpublish and legacy identities, delete is blocked with an actionable permanent-history explanation. No silent audit deletion or public ID reuse.

API: stable sanitized expected validation, ownership, delete/reference conflict, concurrency, known commit/warning, and unavailable runtime responses. Preserve successful client response shapes where feasible; do not leak exception details.
