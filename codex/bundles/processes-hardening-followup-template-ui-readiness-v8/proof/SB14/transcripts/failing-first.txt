# SB14 failing-first.txt

Adversarial and failing-first evidence captured during SB14 implementation.

## Initial gaps

- `baseline-release-readiness-and-deployment` and `baseline-architecture-decision-governance` were absent from the baseline scenario catalog, so the required typed-template coverage could not be proven through production template loading.
- Required scenarios did not expose typed `ContractExercises` or `RecoveryExercises`; raw JSON could describe a scenario while failing to assert projected template operation contracts or typed recovery routing.
- Blocked baseline transitions could not carry explicit `BlockCause` from scenario data into runtime seed transitions.
- Customer and incident scenarios did not select real template branches, so branch readiness could be claimed without exercising conditional dependents.

## Failing iterations that rejected shallow fixes

- The Tetris scenario used `blazor-accepted`, which was not a projected branch outcome. The production seed path rejected the transition until the scenario used the actual `quality-accepted` branch and the projected system `__default__` routes where required.
- Release readiness and architecture baselines initially failed runtime seeding because required artifacts were missing; the seed path could not complete required-artifact steps without real expectation coverage.
- Same-title seeded artifacts could satisfy the wrong expectation before artifact reuse was keyed by `ArtifactExpectationId` when present. The customer onboarding baseline exposed this with kickoff artifacts.
- Blazor/Tetris validation artifacts initially failed because screenshot/image evidence wording did not produce managed paths compatible with screenshot contract checks.

## Rejection standard

A passing SB14 implementation must load the real template pack, resolve the required scenarios, compare scenario contract exercises to projected template contracts, classify recovery exercises through production block-state code, and replay seeded runs through production process services.
