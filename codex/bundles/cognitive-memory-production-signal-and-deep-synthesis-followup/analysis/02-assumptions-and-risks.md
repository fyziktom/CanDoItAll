# Assumptions And Risks

## Working Assumptions

- The current uploaded repository state is the source of truth for this follow-up.
- Codex will execute this bundle from the repository root and can modify skills, validators, tests, and production code.
- Existing cognitive memory EF entities and signal ledgers can be extended with new records or metadata when needed.
- Existing embedding/ranker abstractions in the cognitive memory module are acceptable dependencies for approximate clustering.

## Critical Path Risks

- Codex may again satisfy tests by seeding internal records directly instead of adding production emitters and end-to-end pathways.
- Dream synthesis may stay as deterministic phrase joining unless the bundle explicitly rejects meta-statements as shipped aggregate knowledge.
- Professor capture may pass English-only tests while still failing the user's Czech curator/professor workflow.
- Reference resolution may over-attach sources to statements unless per-fragment/claim lineage is enforced.
- Large services may continue to grow unless refactoring has measurable boundaries and closure gates.

## Validation Risks

- Current validator checks proof manifest structure, but not whether source assertions cover producer, consumer, and lifecycle integration for new domain signals.
- A passing test suite can hide that production paths are never invoked.
- Failing-first tests can be too narrow if they assert only record counts or statuses instead of behavior semantics.
- Browser/UI validation is not required unless UI is changed, but backend review endpoints still need API/service tests.

## Reopen Triggers

- Any critical subbundle produces tests that seed new domain signals manually without proving a production emitter.
- Any professor anchor can remain indefinitely in `Comparing` without a review/transition path.
- Any aggregate memory stores meta-evidence text instead of domain knowledge.
- Any recall synthesized statement cannot resolve back to exact claim/source lineage.
- Any validator fixture that should fail can still pass completed-stage validation.
