# Target Solution

## Process architecture

Codex must first install stronger workflow and validator gates. These gates must enforce producer-consumer-lifecycle proof for any new domain signal, state, or lifecycle record. The validator must include fake-proof fixtures that fail when a bundle proves only an enum, a consumer, and tests.

## Professor learning architecture

Professor learning needs four separate flows:

1. Capture natural teaching/correction into structured professor anchor claims.
2. Compare anchors during dreaming and review unresolved contradictions explicitly.
3. Emit accepted-use signals only from production accepted outcomes, not from tests or mere retrieval.
4. Assimilate and fade anchors only when a derived memory has anchor lineage, independent non-descendant evidence, accepted-use events, and cluster/dream integration.

## Dreaming architecture

Dreaming should synthesize claim-aware internalized knowledge. The final aggregate text must be useful to a future agent or user. It must not be evidence meta-commentary. Claim groups require source-specific provenance and validation against contradictions, scope, modality, actor/action roles, and numbers.

## Recall architecture

Recall synthesis must receive the real user query and intent. It should compose a concise task-facing brief, hide scores and internal diagnostics by default, and preserve line-level statement provenance for references-on-demand.

## Clustering architecture

Composite clustering should combine exact signals with semantic approximate candidate discovery. Existing embedding/ranker abstractions should be used when available, with deterministic lexical fallback. Pair-budget handling must avoid silent missed comparisons.

## Maintainability architecture

Large orchestration services must be split into cohesive interfaces: capture extraction, targeting, anchor persistence, pair discovery, graph formation, dream synthesis, dream validation, aggregate apply, recall planning, and reference resolution.
