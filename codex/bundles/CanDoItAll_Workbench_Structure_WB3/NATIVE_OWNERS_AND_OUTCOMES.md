# Native ownership, admission and outcomes

The native owner remains responsible for each effect. A render-only extraction
must not become a substitute version of the product's mutation protocol.

| Fact/effect | Existing owner to preserve | Proof |
|---|---|---|
| Project identity/lifetime/hierarchy | Projects services, existing admission/reservation/creation receipt paths | Recreated public ID refusal, exact parent/child relationships, unchanged neighbor |
| Graph node/link changes | Workbench mutation scope and native graph services | Current source grants, typed IDs/links, transaction readback |
| Generic node metadata | Native editor composition and metadata boundary | Lossless unedited values and intentional subtype transformation |
| Task/assignment/pricing | Existing WB1 coordinators and task owners | Full preserved task, exact assignment revision, historical/unknown prices |
| Copy/move/transfer | Existing forest/transfer services and compensation | ID map, omitted boundaries, exact source/target and recovery |
| View/layout state | Current native view-state persistence | Original admission, ordering, explicit unconfirmed write, no replay |
| Files and generated content | Existing Storage/FileTools and contribution owners | Safe leases, exact bytes, approval and provenance |
| Agent/Workflow/Process execution | Original source/admission and runtime owners | Accepted run identity, no automatic launch or permission expansion |

At acceptance capture immutable collections as well as scalar values. Mutable
lists referenced from a record are not a snapshot. Preserve target/source node,
parent, original selection, native project admission and relevant expected fields.
A visible operation is not permission for a late callback after another opening.

Native overloads accepting original admission already exist in multiple areas.
Use the correct one; do not downgrade to a convenience ID-only overload during
extraction. A public ID plus latest read is not the original permission. If one
in-scope path lacks a required native guarantee, introduce the smallest explicit
editor boundary at the writer and preserve legacy non-UI behavior.

Distinguish known rejection, acknowledged commit, commit with later failure and
actually unknown result. Use the native result/exception/receipt, not exception
class heuristics that pretend every cancellation rolled back. Preserve original
causes, identities and reached phases when compensation also fails.

A view lifetime governs publication/cleanup, not durable rollback. Accepted work
may outlive the renderer, but it must retain its scoped dependencies and be observed.
Do not use fire-and-forget work against a disposed DbContext or delete another
view's callback registration. Retire cancellation sources after their accepted
operations unwind; errors remain observable without mutating a successor view.

No new table, migration, broad optimistic-version protocol, universal repository,
message bus or domain-wide transaction redesign is authorized. If a true blocker
crosses that boundary, retain evidence and explicitly isolate the unsafe action;
continue safe independent implementation without calling the entire bundle complete.
