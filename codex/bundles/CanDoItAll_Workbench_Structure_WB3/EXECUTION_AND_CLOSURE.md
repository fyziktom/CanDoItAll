# Execution checkpoints and closure

The [prompt](prompt.md) authorizes a longer coherent implementation run. Use the stages
below to keep work recoverable without replacing implementation with repeated planning.
Current repository instructions and the sealed shared foundation remain applicable.

## Entry and focused stages

Record main/Components/FileTools source identities, dirty files, input mode, SDK and
current asset ownership. The previous bundle in the commit history is context, not an
instruction to execute it again. Preserve user edits and signed history. Inspect the
current code even if the supplied branch has advanced past the reviewed SHA.

Request native PGP unlock early as needed. Build affected production projects first;
use CodeAnalytics/Components/dotnetwatch MCPs when available. If unavailable, document
that once and use explicit source tracing, evaluated MSBuild graphs and real CLI/browser
runs. Do not block a correct extraction solely on the absence of an optional MCP.

S0 closes WB3-H1 and relevant in-scope structural-dialog siblings with failing-first
reproductions. W1 establishes the real seam and current caller/asset census. W2 extracts
and validates the complete stage/toolbox/composer. W3 closes graph/hierarchy/clipboard
and native owner outcomes. W4 integrates actual completed and deferred surfaces.
W5 supplies publication, development-loop and application proof. Do not stop after
S0 or the first renderer and describe the complete family as finished.

A focused signed checkpoint can combine closely related stages. Avoid both hundreds
of trivial commits and a single unreviewable unsaved overnight working tree. Verify
each signature and record the final tested source pair. No automated push or merge.

## Test efficiency and validity

Read current `docs/testing.md`, CI and local project instructions before changing tests.
For every changed filter, state and verify discovery before execution. Refresh affected
test assemblies before `--no-build`. A zero-case run, stale copied DLL or interrupted
runner is not success. Use renderer-dispatched find-and-click and await actual async
click completion; do not introduce timing sleeps to hide a known event synchronization
problem. Keep the established component-disposal helper and genuine assertion intent.

Do not run unfiltered assemblies or all Stable merely after each stage. Reuse existing
owning test families and add missing deterministically controlled transitions. Maintain
an invalidation ledger: changed public/serialized types, native owners, shared component
behavior, composition and CI/test registration versus unchanged neighboring code.

Once the final meaningful product source is stable, decide on one broad frozen checkpoint
using the repository's named triggers. The expected WB3 addition of project/CI membership
and any admitted writer changes can justify it; record the actual trigger. Do not repeat
the entire broad run just for a clean headline after a narrow documented test-only repair.
Conversely, a later actual owner/contract/runtime change requires reassessing which earlier
results remain valid. Run the mandatory final portability-static enforcement after all
source edits, without baseline-write mode, and review intentional baseline changes.

Capture source and primary assembly hashes BEFORE a frozen run. Record deferred theory
expansions separately from discovery. A broad suite with one historical synthetic scan
failure is still a failed original suite. Specific follow-ups may establish bounded
acceptance, but never rewrite that result. Keep release readiness separate from scope
completion and permission to proceed to the next Workbench slice.

## Findings and recovery

Fix a small reproduced local defect in this run with native/renderer regression proof.
Classify findings as new regression, existing issue, fixture/tooling failure or unresolved
cause; absence of a root cause cannot be claimed as a root-cause fix. Examples of bounded
work are target-bound callbacks, missing draft fields, a narrowed existing admission port
or proper postcommit readback. UI-refactoring permission is not blanket authorization to
change schemas, durable replay, transaction boundaries or cross-module authorization.

For a complex finding, preserve the original evidence and map the actual call graph,
accepted identity, exact phase, affected owners, rollback/compensation and safe scope.
Isolate an unsafe mutating path, continue unaffected safe work and provide a concrete
follow-up proposal. A documented blocking issue remains blocking; do not hide it behind
completion percentages. Do not duplicate native effects to reproduce a timeout when their
original committed records already establish what occurred.

After accepted writes, a failing list/readback, view retirement or lost client reply cannot
be called NotCommitted unless the native owner knows it. Recovery reads the original
identities without repeating create, transfer, attachment, approval or runtime launch.
Warnings and original unknown outcomes survive navigation and reporting appropriately.

## Artifacts and exact evidence

Use the existing repository evidence conventions; this package's JSON template is a
minimal optional structural aid, not a replacement framework. Keep sealed instructions
unchanged and store actual execution evidence outside the sealed package. Record failed,
qualified, blocked and not-run groups truthfully. Each passing claim needs its own source,
command, result and safe artifact references; file existence alone proves none of them.
The optional strict completeness flag intentionally rejects qualifications and is not a
reason to erase a known historical failure or spend time manufacturing a clean label.

Export only safe IDs and hashes. A reference to a path containing a key is not safe
metadata. Never copy vault contents, model credentials, plaintext secret drafts, private
signing material, transcripts or complete connection strings into tracked evidence.
Retain original private artifacts and test negative controls. Use source/delta scans for
new changes and state their exact scope; do not scan dependency copies for hours merely
to claim the whole historical worktree is clean. Keep required repository scan gates.

## Completion report

The final English implementation report, with an optional short Czech user summary,
must distinguish:

1. Which actual Structure renderers, descendants, CSS/JS and callers were moved;
   which native/deferred owners deliberately remain, and measured dependency changes.
2. WB3-H1 and any additional concrete fixes, exact regression evidence and remaining
   findings, without attributing inherited defects to WB2 without proof.
3. Source/published sandbox results; native graph/hierarchy/transfer/clipboard proof;
   affected real Agent/file/Workflow/Scheduler and multi-instance journeys.
4. Every broad original run and separate focused repair, source/image provenance,
   portability and source/delta secret review. No synthetic PASS placeholders.
5. Repeated edit-to-visible measurements: hot reload, automatic browser navigation,
   manual reload and rebuild/restart separately. Native SDK CSS limits stay explicit.
6. Verified signed commits and exact dependency delivery, owned resource cleanup,
   retained fixtures and what remains for Workbench/Processes. Product release is not
   certified merely because this extraction is ready for another slice.

Only stop owned processes/containers and temporary execution resources. Keep the original
fixture data/evidence needed for review according to repository policy. Never delete
historical bundles or clean user work before a separately authorized merge.
