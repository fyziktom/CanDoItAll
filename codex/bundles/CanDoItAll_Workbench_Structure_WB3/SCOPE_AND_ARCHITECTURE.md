# WB3 scope and architecture

## In scope: one complete structural-authoring family

| Surface | Required real renderer | Native authority retained |
|---|---|---|
| Structure route presentation | Loading, unavailable, explicit retry, supported tabs and stage | Route/profile/actor, canonical project read, Agent invocation context |
| Main canvas | CanvasWorkbench, accessibility mirror, toolbar stats/modes, focus, gestures | Native graph and layout owners, admission, result reconciliation |
| Standard blocks | Actual toolbox, groups, search, descriptions and generic create dialog | Semantic catalog, eligible actions and dynamic reference loaders |
| Generic node editor | All current generic fields and trusted setup composition | Metadata composition, exact original node and write admission |
| Structural dialogs | Hierarchy add/reconnect, block/note conversion, subtree transfer, exact delete/cleanup presentation | Projects/Workbench coordination, original receipts, existing recovery |
| Clipboard/layout | Copy/Cut/Paste, placement, reparent/connect/disconnect, recomposition | Canonical forests, links, native validation and cross-owner constraints |
| Retained siblings | Actual Planning/Insights slots and deferred integration openings | Their existing sessions, authorities and effect owners |

The new renderer cannot receive the entire native page or its old Canvas fragment
as its implementation. Actual toolbar/toolbox markup, composer composition,
structural-dialog markup and relevant CSS/assets must move. Legitimate native
hosts and explicitly deferred forms may remain; enumerate them rather than
claiming an all-Workbench extraction.

## Recommended assembly direction

`Workbench (host) -> Structure.UI -> neutral Components + justified light values`.
`Workbench -> Planning.UI` and `Workbench -> Insights.UI` remain independent paths.
`Structure.UiSandbox -> Structure.UI` may compose the already-light sibling
renderers for representative integration scenarios; it must not reference module
implementations or bootstrap production services.

Keep native graph objects, records, metadata serializers, process state, source
credentials and `IServiceProvider` out of the leaf. Prefer safe projected values
and the existing neutral Canvas contracts over cloning the native model universe.
An additional `Workbench.Structure.Contracts` is optional, justified by actual
shared value types and their complete evaluated reference closure.

The new leaf does not grant authorization. Presentation identity can name a
profile/project/lifetime; the host retains the real admission and revalidates it
at the appropriate owner. Never reconstruct current authority from a returned
row label, Guid, mutable route or JavaScript field.

## State ownership

One canonical native read per admitted load, one route/view identity, independent
editor openings and immutable per-operation submissions. Keep each draft and its
validation/raw text as one owned lifetime. Read result, busy state, graph selection,
clipboard, composer, view-state writer, runtime progress and durable run are not
a single global generation counter.

A selection change may retire a context action but should not destroy unrelated
accepted data. A parameter echo must not reload every source or reset editing.
A same-ID recreated project is not the original target. A committed graph refresh
can invalidate stale intents without erasing the original operation receipt.

Expose a cohesive presentation/view contract, not dozens of wrapper services that
only forward. Keep rendering-local disclosure/focus local. If a typed imperative
canvas handle is needed for open-composer/focus/export, bind it to the original
mounted view; do not pass the component instance through native request DTOs.

## Compatibility

Preserve existing `/projects/{id}/structure` behavior and supported tab tokens;
verify direct load, Back/Forward and toolbar navigation before changing any route
policy. Do not add query-string storage of drafts or confidential fields.

A moved public type requires callers, namespace/assembly-qualified compatibility,
serialization and XML/OpenAPI documentation review. Preserve existing type forwards
where appropriate. Avoid a broad move of mixed files. No migration, table rename,
new ledger, global concurrency token, runtime protocol or SDK upgrade is planned.

## Stage boundaries

S0 fixes the inherited opening/completion problem. W1 establishes the real seam;
W2 implements canvas/composer; W3 completes structural operations/dialogs; W4 wires
preserved integrations; W5 validates final sources and publishes safe evidence.
Commit meaningful working checkpoints. Do not label W1 as complete WB3.
