# Dependency and delivery review

## Required before/after graphs

Capture evaluated references/packages for the new leaf/sandbox and all previously completed UI/sandbox roots. Inspect runtime assembly closure, public contracts, build/watch inputs and asset delivery independently. An allowed source filename or a forbidden-namespace scan alone is not transitive proof. Include failing controls for forbidden owner, unresolved reference and cycle.

No existing Agent Editor/Core, Workspace, Projects, Resources or neutral shared root acquires Providers.UI merely because the module composes both. No Providers.UI/sandbox reference to AgentFramework module, ProviderManagement implementation, Infrastructure, EF, Core/runtime/Voice/Canvas, Web composition, credential resolvers or raw transport clients. An abstraction is acceptable by actual content/graph, not its name.

Reuse safe Models types where they genuinely fit. Separate the product `SecretListItem` dependency in the current read port into a safe UI choice at the production adapter. Do not migrate Security models/owners just to eliminate one reference. A new contract does not become product-neutral simply because two renderers use it. [R06, R18, R23]

## Assets and compatibility

Move local scoped CSS with actual owning components, retain the Tailwind source scan, generated product CSS, BaseLib fonts/icons, isolation bundles and any real JS dependency. Do not ship or copy font files in this handoff; product assets remain in their established owners. Independently publish the sandbox and run its DLL outside the source tree in Production, without database/runtime configuration.

If public component types relocate, review all actual callers, tests, reflection/static-asset references and whether forwarding or an effect-host compatibility wrapper is needed. Do not use forwarding wrappers to leave the full renderer in the old module. No class/interface/file-count quota.

No SDK/package upgrade, new project-wide watch exclusion, runtime-source replacement or global CSS redesign. Broadly shared control changes require current consumer mapping and named test invalidation before completion.
