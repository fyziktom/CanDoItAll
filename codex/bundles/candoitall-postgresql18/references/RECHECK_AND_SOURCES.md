## Primary external verification

The official versioning page and Docker documentation were checked again for this revision. The chosen scope is stable PostgreSQL 18; the observed current patch is **18.6**. Recheck releases and real artifact bytes at execution rather than preserving that patch number if a newer stable 18.x maintenance release is available. Do not silently turn this task into a different major-version upgrade.

| ID | Official source | Narrow point to verify/apply |
|---|---|---|
| E01 | [PostgreSQL versioning policy](https://www.postgresql.org/support/versioning/) | Stable target and upgrade policy; a major upgrade needs data conversion, not just new executable files. |
| E02 | [Official PostgreSQL Docker image](https://hub.docker.com/_/postgres) | Major 18 uses version-specific PGDATA `/var/lib/postgresql/18/docker` and persistent mount `/var/lib/postgresql`. Verify actual selected-image behavior and persistence. |
| E03 | [Npgsql EF 10 release notes](https://www.npgsql.org/efcore/release-notes/10.0.html) | The current provider family supports PostgreSQL 18 features. Targeting generated SQL is separate from upgrading stored data. |
| E04 | [pg_dump 18](https://www.postgresql.org/docs/18/app-pgdump.html) | Use explicitly selected current-major tools and a complete logical archive; a one-database dump is not a backup of cluster-global roles. |
| E05 | [pg_restore 18](https://www.postgresql.org/docs/18/app-pgrestore.html) | Restore into the identified empty target with checked errors. Listing the archive is not a completed restore. |
| E06 | [pg_dumpall 18](https://www.postgresql.org/docs/18/app-pg-dumpall.html) | Consider required global roles separately without overwriting unrelated server administration. |
| E07 | [PostgreSQL 18 major release notes](https://www.postgresql.org/docs/18/release-18.html) | Review compatibility changes including collation/text behavior and default checksums. |
| E08 | [pg_upgrade 18](https://www.postgresql.org/docs/18/pgupgrade.html) | Only if justified instead of logical restore: compatibility check, matching prerequisites, extension binaries and an independent recovery plan. |
| E09 | [EDB binary downloads](https://www.enterprisedb.com/download-postgresql-binaries) | Authoritative binary distribution channel. Resolve exact Windows packaging, byte count and hash from real downloaded artifacts; none is fabricated in this package. |
| E10 | [PostgreSQL 17 compatibility notes](https://www.postgresql.org/docs/17/release-17.html) | Also review the intervening major's relevant changes when migrating an actual version-16 source. |

A logical restore recreates indexes and does not need checksum-mode matching between old and new clusters. Do not copy a pg_upgrade-only hard-link/checksum/reindex recipe indiscriminately into the preferred logical route. Recheck the selected patch's own release notes and actual source settings; old installations may have custom extensions or database-level settings beyond the repository defaults.
