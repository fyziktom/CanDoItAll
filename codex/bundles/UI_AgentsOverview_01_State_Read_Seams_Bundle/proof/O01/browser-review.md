Real Web / Kestrel, PostgreSQL-backed workspace and controlled aggregate sources, Chromium 149.0.7827.55 at 1600 x 1000. This is current execution, not historical browser proof.

`browser-o01` preserved a failed navigation while a held aggregate ran during prerender. The page now starts initial reads in first interactive OnAfterRenderAsync; subsequent parameters use the same session. This avoids prerender quiescence without introducing unobserved background work or changing global render mode. [Framework lifecycle contract](https://learn.microsoft.com/en-us/aspnet/core/blazor/components/lifecycle?view=aspnetcore-10.0).

`browser-o01r2` passes 13 scripted states: normal, nominal Long, partial, empty, pending Overview, initial Overview failure, Usage failure, header failure, bound failure, stale Overview, stale Usage, new-scope failure and retry recovery. The nominal Long state used ordinary labels; it is explicitly not long-content proof. `browser-o01-long` supplies and asserts actual long consumer/provider/team labels, builds the fixture again, and passes. All twelve distinct ordinary screenshots and the actual long screenshot were visually inspected. DOM files and process shutdown receipts are retained. Both successful fixture processes exited 0; no page errors.

HR remains enabled through pending/failed Overview, Usage failure and bound failure. Initial failure shows unavailable markers and no fake summary; same-scope failure retains values with a warning. Failed Chats scope has no old Agents data and disables detail buttons; retry accepts Chats and enables details. Header failure alone disables HR and exposes header retry without failing aggregates. Real bar/donut SVGs are present when matching usage exists. No horizontal dashboard overflow in recorded frames; widths and scroll widths agree.
