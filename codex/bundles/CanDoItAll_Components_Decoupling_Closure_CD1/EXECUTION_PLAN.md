# Execution plan

This is one authorized staged assignment. Continue after checkpoints; do not ask for another
bundle after each module or after creating a plan. Update the progress log before compacting
context so a resumed agent continues the queue rather than recertifying completed slices.

| Stage | Work | Exit evidence / commit boundary |
|---|---|---|
| S0 — entry and baseline | Request PGP, preserve worktree, read current standards, identify source/siblings and reusable fixtures. Review PC4 delta and available raw proof. Discover tools and affected-test seeds. | Entry tuple, signed-commit readiness, baseline evidence availability and resource ownership. No obligatory full Stable. |
| S1 — bounded completion queue | Reconcile complete product census, existing records and evaluated graph. Name all residuals, legitimate native hosts and out-of-scope items. Select app leaf placement and small contracts. | Current queue with owners, risk and tests; preserved behavior matrix. Sign a useful planning/guard checkpoint if it is a coherent change, not artificial commit padding. |
| S2 — application surfaces | Complete Dashboard, Runtime Capabilities, database dialog/flyout/utilities and top bar. Wire actual native hosts and the independent scenario host. Keep owner and route semantics. | Focused light/native tests, actual UI inputs/children, graph and asset checks. Commit coherent tested slices incrementally. |
| S3 — remaining edges and global guard | Complete every further in-scope active edge in the S1/delta queue; reconcile dynamic contributors/assets and install bounded regression guards. | Zero remaining or unclassified active edges, or exact genuine blockers. No audit-only handoff for feasible work already assigned. |
| S4 — integrated verification | Execute affected native/browser journeys, dependency/publish checks and development-loop measurements. Close policy-required final integration using an explicit evidence ledger. | Exact build-backed test discovery/results, screenshots/traces/native readback, graph/asset proof and final portability enforcement. |
| S5 — close and hand off | Finish current docs/index, final renderer map, known backend limitations and next-refactor invariants. Verify signed commits and owned resource disposition. | Completion decision linked to tested executable source; no new shared ZIP, no automatic push/merge. |

## No circular work

A passing checkpoint is reused until its source, consumed dependency, selector, serializer,
registration, asset or fixture contract changes. Refresh only affected proof. An old historical
`in progress` line is not an instruction to repeat the extraction; map it to current evidence
or name the still-missing validation dimension. Never change an original failed report into a pass.

Do not preassign a dozen microscopic sub-bundles. Use independent analysis/test tasks where
safe, but serialize overlapping file edits, shared output builds and DB/profile mutations.
Keep one authoritative owner for each change. Checkpoint code in reviewable signed commits,
not one enormous final commit and not a commit per generated log.

Any source changes after S4 invalidate only their real affected closure, but that closure must
be rerun before S5. A report-only final commit references the tested executable source; it must
not claim its own as-yet-unknown hash or hide an untested production change.
