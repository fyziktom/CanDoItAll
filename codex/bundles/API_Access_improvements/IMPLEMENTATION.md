## Implementation

Implemented private ordinary accounts with stable GUIDs, normalized unique usernames, salted Identity V3 password hashes, optimistic versions and authentication revisions. User/admin sessions are registered v2 credentials; existing registered machine credentials remain v1 and the deliberate unmarked legacy path remains supported. Claims alone never establish administrator authority.

Added independent deployment-owned user-authentication and HTTP-management switches, login/me/logout, safe account and token-management contracts, bounded login throttling, explicit section capabilities, stream revalidation, TLS/proxy/CORS enforcement and API-safe failures. Settings retains local operator authority and machine-token controls and adds account lifecycle management using the shared component library.

The [operator guide](../../../docs/api-user-access.md) records the configuration truth table, hash helper, complete capability and route behavior, migration limits and deployment example. No default administrator password, refresh tokens, ordinary-account promotion, public registration or generic security-configuration writer was added. Existing machine lifetimes remain 480/1440 minutes; session default is 60 minutes. Managed credentials expire at the registered instant; the JWT handler retains its existing 30-second skew. Active streams check before delivery and at most every 15 seconds while idle.

## Ownership decisions

Infrastructure owns private account/token documents and atomic persistence; it does not reference a module. Workspace ApiAccess owns account rules, password hashing, sessions and administration. Web owns JWT-handler adaptation, verified request authority, endpoints and transport policy. The existing Settings host calls application services directly. No new project boundary or general identity framework is required. A single coordinated account document gives atomic uniqueness/revision changes without coupling credentials to the selected database. Session validation must compare registry metadata and current account state; claims alone never establish administration. Existing endpoint/resource policies remain additional restrictions. New behavior is tested through isolated owners and the real HTTP handler, not an always-admin principal.
