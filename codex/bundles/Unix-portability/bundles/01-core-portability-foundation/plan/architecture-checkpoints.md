# Architecture checkpoints

| Checkpoint | Required evidence | Stop condition |
|---|---|---|
| C0 / A00 | Current anchor, reviewed scan, path/persistence inventories, project graph, baseline classification | Unowned critical/high finding, unknown host-bound record, or source delta not reconciled. |
| C1a / A01 | Typed logical-path contract, focused tests, no reverse project edge | SharedKernel gains I/O/host probing or a new project cycle appears. |
| C1 / A02 | Physical filesystem policies and actual Windows/Linux proof | Containment, link, case, permission, or atomic-write behavior is ambiguous. |
| C2a / A03 | Versioned migration with backup/restart/rollback proof | Existing records can be overwritten without verified recovery. |
| C2 / A04 | Explicit secure provider matrix and migration/restart proof | Any claimed profile uses plaintext/raw colocated key or silent fallback. |
| C3a / A05 | Narrow capabilities wired only in composition | A broad platform service or capability-based authorization bypass appears. |
| Hosting / A06 | Headless start/stop and support-profile evidence | Desktop dependency blocks headless startup. |
| C4 / A07 | Actual Windows, Ubuntu, and macOS evidence plus publish/start | Any claimed OS lacks actual-host evidence. Runtime bundle remains blocked. |
| R0 / B00 | Rebase to exact C4 commit, child-bundle records, direct-reference graph | External repo scope is unowned or project-reference topology cycles. |
| R1-R4 | Focused runtime proofs followed by actual-host matrix | Name-only kill, shell-string execution, secret leak, or residual owned child. |

At each checkpoint, update the execution report, requirement traceability, gate log, changed-file list, residual risks, and next eligible subbundle. No checkpoint is satisfied by compilation alone.
