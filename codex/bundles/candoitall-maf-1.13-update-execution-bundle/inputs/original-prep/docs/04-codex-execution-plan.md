# Codex Execution Plan

## Branch and commit strategy

Create a small dedicated branch from `memory-providers`:

```powershell
git checkout memory-providers
git pull
git checkout -b maf-1.13-basic-update
```

Use at least these logical commits:

1. `chore(maf): capture package update baseline`
2. `chore(maf): update Microsoft Agent Framework packages to 1.13`
3. `fix(maf): adapt compile breaks from MAF 1.13`
4. `test(maf): update focused regression coverage`
5. `docs(maf): record update evidence`

## Phase 0: Inventory and freeze

Goal: capture baseline and prevent accidental wide changes.

Steps:

1. Record current git status.
2. Record current package references in MAF projects.
3. Record baseline restore/build/test state if feasible.
4. Search for direct MAF package references outside the two known MAF adapter projects.
5. Search for stale process direct-tool names.
6. Identify existing failing tests before the update.

Commands:

```powershell
git status --short
dotnet --info
dotnet list src\MAF\Common\CanDoItAll.AgentFramework.Maf\CanDoItAll.AgentFramework.Maf.csproj package
dotnet list src\MAF\Workflows\CanDoItAll.AgentFramework.Workflows.MafAdapter\CanDoItAll.AgentFramework.Workflows.MafAdapter.csproj package
rg "Microsoft\.Agents\.AI|Microsoft\.Extensions\.AI" src tests tools -g "*.csproj"
rg "ProcessAgentRuntimeToolProvider|processes_" src tests docs -g "*.cs" -g "*.md" -g "*.json"
dotnet restore CanDoItAll.slnx
dotnet build CanDoItAll.slnx --configuration Release --no-restore
```

Exit criteria:

- Baseline package list captured.
- Any pre-existing build/test failure is recorded separately from package-update failures.
- No source changes yet except optional evidence notes.

## Phase 1: Package update only

Goal: apply only package reference changes.

Allowed files:

- `src/MAF/Common/CanDoItAll.AgentFramework.Maf/CanDoItAll.AgentFramework.Maf.csproj`
- `src/MAF/Workflows/CanDoItAll.AgentFramework.Workflows.MafAdapter/CanDoItAll.AgentFramework.Workflows.MafAdapter.csproj`
- optional package lock files if present and generated by restore.

Steps:

1. Update stable MAF packages to `1.13.0`.
2. Update explicit `Microsoft.Extensions.AI.Abstractions` to `10.6.0`.
3. Update explicit `Microsoft.Extensions.DependencyInjection.Abstractions` to `10.0.9`.
4. Verify A2A/Mem0 with NuGet CLI.
5. Keep preview packages unchanged unless CLI reports compatible updates.
6. Restore.

Commands:

```powershell
dotnet list src\MAF\Common\CanDoItAll.AgentFramework.Maf\CanDoItAll.AgentFramework.Maf.csproj package --outdated --include-prerelease
dotnet restore CanDoItAll.slnx
```

Exit criteria:

- Restore succeeds, or restore failures are strictly package compatibility issues with a clear next action.
- No application code changed yet.

## Phase 2: Compile-break adapter fixes

Goal: make build compile while preserving current behavior.

Allowed files:

- Existing files under `src/MAF/Common/CanDoItAll.AgentFramework.Maf/**`
- Existing files under `src/MAF/Workflows/CanDoItAll.AgentFramework.Workflows.MafAdapter/**`
- Existing tests that directly assert MAF adapter behavior
- Minimal internal contracts only if required by new package signatures

Disallowed:

- New product module references from MAF.
- New direct process tool provider.
- New process API routes.
- Broad class splits.
- Replacing finalizer logic with free-form JSON parsing.
- Removing approval wrappers, traces, context filtering, provider lane gates, or serialized-session validation.

Fix order:

1. Restore errors.
2. Type or namespace changes.
3. Constructor/signature changes.
4. Skill-source and approval changes.
5. FileAccess/FileMemory changes.
6. Streaming/session/run-options changes.
7. Workflow adapter changes.
8. Tests.

For each compile error, add a short code comment only if it clarifies compatibility intent. All source comments must be in English.

Exit criteria:

```powershell
dotnet build CanDoItAll.slnx --configuration Release --no-restore
```

## Checkpoint: architecture drift review

Before running broader tests, inspect the diff:

```powershell
git diff --stat
git diff -- src/MAF/Common/CanDoItAll.AgentFramework.Maf src/MAF/Workflows/CanDoItAll.AgentFramework.Workflows.MafAdapter
rg "registers .*ProcessAgentRuntimeToolProvider|new ProcessAgentRuntimeToolProvider|class ProcessAgentRuntimeToolProvider|Add.*ProcessAgentRuntimeToolProvider|Current direct runtime tools: 23|/api/processes/definitions|/api/processes/templates|/api/processes/runs/\\{runId\\}/detail|ProcessManagerTools" docs src tests -g "*.md" -g "*.cs" -g "*.json"
```

Reject the diff if it:

- creates a new dependency cycle,
- adds product module references to generic MAF/core projects,
- adds process direct tools,
- removes finalizer enforcement,
- removes approval enforcement,
- makes provider-specific behavior global,
- suppresses important warnings broadly instead of fixing the cause.
