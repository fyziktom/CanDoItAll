# Native application journeys

These are required producer/consumer checks, not merely screenshots of seeded result cards. Use owned
isolated data, current setup helpers and actual services. Script only the external model response.
Do not replace the native catalog, runtime, approval gates or file owners with echoing fakes.

## A. Lossless edit and concurrency

Create a valid rich workflow with nonempty input parameters, explicit shapes/ports, custom config,
metadata/provenance and immutable component/prompt references through its actual owner or supported
import. Open it through `/agents/workflows`, edit only its name and save. Fetch exact new version and
compare the full semantic snapshot. Repeat a node edit and an unchanged round-trip. Verify legitimate
zero coordinates and unaffected graph fields. Two native owners then save competing edits: retain the
actual expected-version conflict and the losing draft. Repeat controlled failure after a confirmed
Save but before validation/callback, and prove there is one intended new version, not a blind retry.

## B. Author a graph with real controls

Through the new canvas create a minimal workflow, add a supported deterministic route and a prepared
LLM component using the real controls. Move nodes, edit an edge, delete/reconnect an eligible node and
save. Reload and inspect actual graph IDs/configuration. Exercise the actual rendered canvas gestures,
not only direct calls to handlers. Use a separate branching fixture for decision routes; do not change
runtime routing behavior as part of the renderer move.

## C. Prompt Gallery and immutable component

Open the actual Gallery picker for a specific node, select a compatible exact version, create/bind its
native component and save the workflow. Read back the accepted Prompt and component identities. Change
the gallery head elsewhere and confirm pinned original execution. Include incompatible selection,
source-managed model choice and callback/read failure after component commit; retries must not create
a second component. Close/replace the original node/editor while compatibility is pending.

## D. Preview and Project Structure files

Run a real preview over a selected owned project/node and exact input. Include an existing file whose
hidden canary is not supplied to the model. Use actual tools to read it, then request a non-overwriting
write/attachment. Inspect exact tool name and arguments, project/node, relative path and expected
content before operator approval. Fetch native receipts, asset metadata, byte/hash read-back, preview
and download; neighboring project/content must remain unchanged. Explicitly deny another proposed
mutation and prove no corresponding effect. A scripted model is not a shortcut around native authority.

Also edit the canvas while a preview is in flight. Its result/progress belongs to the submitted graph;
it must not validate, focus or overwrite a successor document reusing the same node IDs. For a captured
unknown/admitted-but-details-failed result, recover reads using the original identity without launching
another run. Deliberate node simulation is separately labeled and not counted as real file-tool proof.

## E. Workflow outcomes and callers

Execute accepted and deliberately incomplete LLM outputs; preserve native success/failure, MaxOutputTokens,
input and immutable version semantics. Use actual TestLab recording where already supported. Exercise
one supported held human/external request and its authorized continuation; a rejected/stale response
must remain rejected. Schedule a real workflow using the existing Scheduler and observe native Quartz
delivery once, not a direct call masquerading as scheduled execution. Keep archived/suspended/unsupported
backend refusals. Do not add new executor/backend capabilities to get a passing run.

## F. Templates, history and navigation

Inspect a real template in read-only CanvasWorkbench; no run or template mutation occurs. Add it to
my drafts, retain accepted ID/provenance, and verify subsequent native load. Exercise page and canvas
preview-input dialogs and run/event overlays. Close and reopen same IDs, change source/target/profile,
use direct valid/invalid routes and back/forward. Old reads and callbacks may not operate on the new
selection. Use real global/provider History for produced requests: explicit Search, separate content
request, exact canonical owner, denied credentials with zero disclosed data and current request counts.

## G. Adjacent families

Run CA1-R1 and affected capability authoring/team/native checkpoint controls; preserve A2 whole-agent
assignment/Verify semantics. Retain relevant Projects Files/Resources/Workspace cases, not all unrelated
visual suites. Exercise shared-provider name/route parity in Workflow and a representative Agent and
Simple Chat after the final image rebuild. Do not repeat unchanged paid or external acceptance lanes.

Every journey records actual inputs/source hashes, native IDs, expected effects, final persisted facts,
server errors and exact selected test identities. A green toast, HTTP 200 or textual model claim is not
proof of completed execution. Negative refusals are matched to the expected request, not ignored broadly.
