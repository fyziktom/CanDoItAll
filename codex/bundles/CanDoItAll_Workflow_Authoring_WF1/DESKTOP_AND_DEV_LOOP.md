# Large-desktop development-loop proof

Use 1920×1080, scale 1, for all new visual acceptance. A second genuinely large desktop size is optional
only for a specific functional question. No new small/medium/mobile/tablet tuning campaign. Do not delete
existing library tests; do not spend this run adjusting unrelated responsive breakpoints.

The real canvas must be visible, interactive and sized correctly, not only present in DOM. Test pan/zoom,
node drag, route handles, opening inspectors and actual floating windows. Check footer/focus/scroll,
long instructions/JSON, menu bounds, two simultaneous canvases and disposal of one while the other keeps
working. Static images and substituted fake children are not acceptable. Fixture graphs should include
ordinary and realistically large cases, not arbitrarily huge stress sizes that redefine product limits.

Before extraction record existing shell, new target descendants, evaluated graph and watch paths.
After extraction compare the same inputs/mode/SDK. Verify standalone source and independently published
sandbox; no hidden production modules, database, provider runtime or prebuilt Web output dependency.

Measure cold launch separately from warm edits. Perform at least three consecutive visible edits each
for Razor, C# presentation logic and scoped CSS; include owned JavaScript if the move changes any. Record
watch PID, restart count/iteration, actual browser observation and whether a new component activation
was required. Restore probe files byte-for-byte. A successful rebuild/restart is useful but must not be
called hot reload. Do not change SDK/build policy speculatively to obtain a nicer timing.

Use actual neutral Canvas/Overlay assets and any required registrations. Track package-to-sibling-source
resolution, Tailwind/content inputs, scoped styles, import URLs and cache behavior in source and publish.
Preserve the existing small Workflow shell graph and the prior sandbox closures. Do not promise the
canvas sandbox has the same tiny graph as the noncanvas shell; measure the necessary dependencies.
