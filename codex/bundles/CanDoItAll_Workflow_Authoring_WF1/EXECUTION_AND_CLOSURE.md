# Execution and closure

## Stage order

S0 repairs CA1-R1 and establishes the real source pair. W1 maps callers and proves lossless definition
state. W2 completes the actual canvas and child renderers. W3 completes remaining page overlays and
production composition. W4 validates source/publish, native owners and final multi-instance consumers.
Continue across all stages; checkpoints do not limit the user's requested longer run to one panel.

Keep a concise progress ledger in maintained task evidence outside this sealed package: completed
surfaces, pending defects, source pair, current command/filter, decisions and next concrete step.
Use available analysis/component/watch tools when useful, otherwise state the exact CLI/source fallback.
Do not spend most of the run writing a generic evidence framework or re-auditing unchanged families.

## Efficient testing without false closure

Build every changed production project and refreshed owning test assembly. Derive expected case counts
from actual source/discovery and confirm them before execution. Preserve nonserializable theory expansion
by method. Use awaited event handlers and real component readiness, not heading-only waits or sleeps.
Check the repository's current bUnit disposal helper. Renderer tests, PostgreSQL owner tests, real Web,
independent publish and multi-instance wire tests prove different layers.

Make one final broad Stable decision after changes settle. This bundle authorizes one deliberate frozen
checkpoint when the current named invalidation rules apply; a new test assembly/CI selection or native
catalog/admission change is a plausible trigger. During stages use targeted selectors, not repeated broad
sweeps. If a late fix invalidates the frozen checkpoint, identify the exact affected coverage and rerun
what is required; never relabel old binaries. A genuine release-wide conclusion requires its own proof.

Preserve the original counters of failed broad runs. A passing focused follow-up closes only its named
cause, not the entire broad run retrospectively. Existing historical generated scanner controls require
scope-qualified handling: preserve originals, compare the exact constructed control/hashes, and report
whole-worktree versus source-only/safe-export coverage separately. Do not disable scanners or erase
historical evidence to get green output. Verify final portability enforcement without baseline-write mode.

## New findings

Fix small reproduced defects in the selected family directly, with regression tests and affected native
consumers. Preserve the first failing attempt and exact input/source identity. For complex changes to
authority, durable execution, schema or several owners, record reproduction, call graph, phases/effects,
blast radius and a separate repair plan. Halt an unsafe mutation path, not all independent safe work.
Do not invent an optimistic repair based only on a timeout or treat every negative fixture log as a defect.

## Deliverable distinctions

Record separately: CA1 prerequisite fixed, full selected Workflow rendering complete, lossless native
round-trip, native consumer campaign, final regression disposition, sandbox/watch evidence, and local
versus remote dependency delivery. Residual chat/usage/Voice screens and non-selected runtime work remain
listed. No blanket 'AgentFramework finished', 'all logs clean' or 'all tests green' statement is allowed
without the corresponding scope and evidence.

Use `templates/evidence.json` externally; keep this package immutable. The checker establishes structure
and file integrity only. A PASS group means its stated acceptance requirement has real evidence. The
regression-accounting group may reference a passing review of a correctly qualified mixed attempt;
it must also retain the failing attempt and explicit disposition, not falsify that test's status.
All behavior groups require actual successful relevant proof. Unresolved in-scope product blockers
remain unresolved, not hidden under that accounting convention.

## Cleanup

Stop only named task-owned watcher/browser/process/container resources. Keep original receipt/private
artifact roots and required retained fixture data; record what is retained. Never kill all dotnet/docker
processes, reset retained volumes or touch the ordinary developer installation. No paid calls or new live
budget. Make verified signed checkpoints and report any signing/delivery blocker honestly.
