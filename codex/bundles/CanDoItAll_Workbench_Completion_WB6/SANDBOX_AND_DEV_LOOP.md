# Independent UI, assets and practical development loop

Use the actual new Workbench Execution renderers and all candidate/staffing children in the
independent sandbox. A fake list of the same labels or the old module injected as a fragment
is not an extraction. Native owner/admission is substituted only at the actual boundary;
fixture responses are explicitly labelled and do not count as a real Process or Workflow.

Show normal, empty/unavailable, loading, error/retry, invalid raw input, read-only, pending,
accepted, conflict and observation-required states. Demonstrate two independent dialogs and
nested picker lifetimes. Include a long role list, missing candidate, shared-provider display
names, direct source/version selection and managed-file disposition. Use actual child
renderers, styles, browser scripts and production-like composition.

Build and publish the sandbox independently. Verify resolved project graph (including source
substitution for sibling packages), runtime files, asset registration, scoped CSS, gzip/identity
serving and route discovery. Preserve all old leaf closures; a forbidden dependency cannot be
hidden behind a neutral filename or unresolved package.

Only large-desktop 1920x1080/DPR1 is required. Check title/toolbar overlap, fixed visible action
footer, owned body scrolling, pointer/keyboard selection, focus and nested modal hit testing.
Do not add small/medium responsive work. Existing library tests stay intact.

Measure a bounded repeatable watch sample: source Razor, C# and scoped CSS edits and restores,
real rendered/computed result, process identity and browser navigation identity. Prefer three
small reversible samples per changed class of assets, once on stable sources. Distinguish hot
reload, rerender/remount and process restart. An SDK limitation is reported, not disguised as
fast hot reload. Do not chase a known unrelated toolchain issue at the expense of a runnable
demo. The final customer candidate is a frozen production publish, not a watch process.
