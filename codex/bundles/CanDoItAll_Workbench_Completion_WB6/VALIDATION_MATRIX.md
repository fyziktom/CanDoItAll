## Evidence acceptance

Build each changed production project first; refresh owning test assemblies. Exact list-tests
counts must match the declared data-driven expectation. Zero selected tests, a disabled live
gate or stale `--no-build` binaries do not pass. Use original failing attempts plus separately
identified retests; never replace an old TRX or rewrite its reported exit code.

Mandatory Workbench structural groups require PASS. One planned final broad checkpoint may
be qualified only with explicit preserved original result and exact exception mapping. Known
unchanged synthetic security controls do not justify disabling the scanner. New product/data/
authority failures are blockers. An inherited result needs input equivalence and affected-path
reasoning; it cannot substitute for mandatory changed-path/customer UI proof.

G16-G21 require a **non-scripted genuine model** and real application owners. A deterministic
external response alone is insufficient. G18 needs both image generation and actual image
analysis. G19 needs a valid native XLSX and a second revision-aware analytic read. G20/G21
must actually execute, not only prepare. A blocked genuine lane leaves demo readiness false,
but does not require unsafe spending or pretending completed structural work is unfinished.

Use `templates/evidence.json` as a shape, not prefilled truth. `tools/validate_handoff.py`
checks structural consistency; it cannot authenticate native results or replace code review.
The independent artifact inspector is read-only and makes no claim that an Agent produced
what it inspects. Manual review of actual images/screenshots remains required.
