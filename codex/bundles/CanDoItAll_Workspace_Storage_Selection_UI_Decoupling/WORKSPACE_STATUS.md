# Workspace status and remaining sequence

## What “complete” means here

A completed renderer extraction is not completion of the entire Workspace backend or a proof that every application function has been independently rerun. The latest implementation record explicitly defers Data Sources, placement Recovery, shared catalog pickers and remaining configuration hosts. [EV03]

| Area | Current source / scope status | Treatment in this bundle |
|---|---|---|
| Settings shell, defaults, Secrets, Files, Provider history | Earlier Core extraction, retained by current implementation | Preserve; run relevant Core/route regressions; no new ownership redesign |
| API Access | Separate leaf, AP-R1/AP-R2 repairs present in current source | Retain focused disposal/current-denial checks |
| Storage catalog administration | New independent contracts/UI/sandbox and real production owner adapter | Repair SCAT-R1; retain Save/Test/routing/Recovery launch semantics |
| Storage catalog selection field/dialog | Still compiled in Workspace, references Workspace summary/Infrastructure types, used in Agent details | **The next complete small extraction** |
| Placement Recovery and owner continuation | Still a production host outside catalog UI | Preserve passively and defer its own full audit/extraction |
| Data Sources / profiles / activation / transfer | Deferred production surface with broad runtime consequences | Preserve; do not mix with picker work |
| Generic settings renderer/fallback integration | Remaining trust/owner/schema-aware host | Preserve and retain a separate final dependency/consumer audit |
| Providers Settings item | Navigation to Agents, not a local provider-management implementation | Preserve redirect; do not recreate another provider page |

The actual next family is confirmed by its current source and Agent call site. This is not an exhaustive inventory of every route or helper across the repository. P1 must complete the current local reference scan before migrations. [WS01–WS08, WS13, ST14, ST15]

## Recommended sequence

Complete the selection family now. Then handle Recovery/owner continuation as a dedicated slice, and Data Sources as its own independently reviewed slice. A residual renderer-host audit may identify another small task before final Workspace closure. Its exact ordering depends on the then-current consumer graph; do not pre-emptively move its dynamic-renderer or trust contracts into selection.

Do not start Processes or Workbench while silently treating unreviewed Workspace remnants as done. Conversely, do not use “Workspace is broad” to bundle database switching, storage recovery and Agent permissions into one controller.

## Final Workspace closure checklist (future, not all assigned now)

- Every routed/embedded surface and active slot is accounted for, including non-Settings consumers.
- Every feature's UI/rendered closure is independent of backend implementations, or a remaining host-only adaptation is explicitly justified.
- No feature-neutral shared assembly or Foundation/MAF runtime depends on a concrete Workspace rendering feature.
- Profile-local data, machine/instance control-plane data and caller-sensitive views retain their different lifetimes.
- Generic configuration renderer registration preserves owner/trust/schema checks and actual loaded children.
- Current end-to-end routes, parent saves, file/attachment paths, authorizations and profile transitions have source-derived proof.
- Sandbox success, local implementer evidence and independent review verification remain clearly separated.

This bundle may close the **picker family**, not the entire Workspace module.
