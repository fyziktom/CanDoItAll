# Development-loop measurement and asset proof

## Baseline and protected graphs

Record actual checkout/sibling SHAs, SDK/OS, source/package mode and the host configuration. Use an isolated short configuration (for example `StSelProof`) if repository tooling supports it. Do not change global build policy, machine NuGet feeds or running application outputs merely to obtain measurements.

Before moving the picker, record the real Agent details nested chooser journey and the evaluated production host graph/watch inputs. Record the Core, API and catalog-admin sandbox graphs/watch sets as protected comparison inputs. After extraction, repeat those and evaluate the new independent picker host.

The implementation record reports prior Core/API/catalog-admin sandboxes with 8/5/5 projects, respectively. These are historical measurements, not acceptance constants and not a target for the new picker. AppComponents' actual ResourceCardPicker/SelectedReferenceTable reuse can produce a broader neutral closure. An allowed neutral dependency is not a hidden backend; unexplained implementation/transitive dependencies are. [EV03, WS09–WS11]

Use evaluated restore graph/project assets (including sibling package-to-source replacement), runtime assembly/public-type closure and the real rendered component tree. Source-text ProjectReference checks alone cannot establish the watch/runtime boundary. Include negative forbidden, unresolved and cyclic fixtures.

## Observe, do not assume a speedup

Measure original Web and post-extraction Web in the same private fixture, then the independent selection sandbox. Record startup to a specific interactive action (open chooser and toggle/Apply), not merely the time a heading/input becomes visible. Distinguish startup, rebuild/restart and edit-to-visible response.

Use multiple reversible samples for an actual feature Razor change and an executed C# presentation change. Record each sample, process/output, host readiness criterion and failure, not only a favorable average. Restore exact source bytes in finally. Do not add fixed sleeps in place of a visible readiness condition or claim full-Web improvement from the sandbox's smaller startup.

Measure/prove feature-owned CSS/JS when present. When there is no owned CSS/JS, record N/A honestly while still proving shared component styles/fonts/dialog/clipboard assets in source and independently published Production hosts. Move scoped asset ownership with the renderer if code movement requires it.

## Runtime/query workload

Count owner reads for: initial empty field, initial saved IDs, repeated parameter echo, each dialog open, explicit retry, local search and toggles. Empty-field rendering should not read needlessly; selected labels may read once; new dialog opens use current metadata. Local filtering should not query the backend. Do not force a single universal count where the chosen current design deliberately performs an independent field read and dialog refresh; explain and bound the lanes.

No picker action dispatches a Storage Test/Save/Delete, Agent Save, file launch or driver call. Existing bootstrap through the real catalog read owner is retained and measured separately. Do not use an artificial no-op source to conceal actual production work.

## Published and nested dialog checks

Publish to a fresh owned directory and run its DLL in Production without a database/vault/runtime configuration. Render the real field, actual ResourceCardPicker/SelectedReferenceTable and shared BaseLib dialogs. Check CSS requests, fonts, focus/caret, keyboard navigation, long names/IDs, missing references, empty/error states and two-instance isolation. Check parent/child dialog stacking and closing only the child at the supported desktop viewport.

A linked parity CSS file as content is allowed. A project reference to Web or module implementation to make assets appear is not. No screenshot of a mock renderer counts as real tree proof.

## Cleanup

Stop only owned watch/browser/published hosts. Keep proof outputs separate from normal app outputs. Verify restored source bytes, unchanged read-only sibling sources and no abandoned fixture roots/processes. Include ordinary-port non-interference in the final record. Measurements here are requirements for Codex, not results produced by the source review.
