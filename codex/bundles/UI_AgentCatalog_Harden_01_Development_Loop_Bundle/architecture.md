# Development-loop decisions

Preserve the real catalog rendering and existing production-parity assets. Add explicit Parity (compatible default) and Fast modes; Fast owns a separate generated output and minimal audited Tailwind scan roots. Mode is visible in a development probe/root attribute. Fast build cannot depend on production CSS existence and cannot fall back to it. No new project or sibling edit.

Direct benchmark: local OS dotnet watch plus companion Tailwind process, local Playwright, one monotonic source-flush-to-browser clock, SDK events separately. Freeze one Razor, C# and CSS edit/undo/predicate and three repetitions per full-app/Parity/Fast lane before collection (27 warm primary successes). Preserve all calibration/failure classifications and byte restoration; no Manager or MCP observation endpoint. Reuse isolated prior full-app database/environment without printing credentials. No operator database.

Parity proves production theme bytes and real assets/events; Fast proves representative utility/style, scroll/actions/tooltips and asset independence without claiming byte parity. No routing, new editor, Manager optimization or generic sandbox framework. Cold measurements optional; no performance conclusion before retained data.
