# Execution and closure

## Entry

Read current AGENTS, engineering instructions, UI seams, full testing guide and CI before
changing source. Use available CodeAnalytics/Components/watch MCPs; if unavailable, document
the gap and use direct source tracing, MSBuild/CLI and actual browser tools instead. Availability
of an optional MCP is not a license to substitute fake product behavior. [S25-S29]

Record actual repository state, package hashes, sibling refs, signing readiness, evaluated
protected graphs and named affected tests. Historical input is not executable current truth.
Do not reset to this review commit, discard dirty changes, remove historical bundles or rebuild
all tests merely to enter a new stage.

complete. A proven complex blocker gets a concrete report while independent safe work continues;
no permission to conceal a required unresolved product fault.

## Focused testing loop

Build affected production projects first, then current owning test assemblies. Use exact or
bounded filters with declared and checked --list-tests discovery. Explain data-driven expansion.
No-build/no-restore is valid only for the recorded current binaries. Keep logs, source hashes,
assembly inputs, fixture identity and code changes tied to each attempt. Use the documented
bUnit dispatcher/disposal helpers; stale element references and unawaited events are not valid
negative tests. Separate policy, native persistence, actual-host process, Playwright and paid/live
lanes; none substitutes for another. [S27]

Use existing party/assignment, secret-reference, runtime-adapter/registry, readiness, web-preview
and Workbench action-lifetime test families discovered in the current checkout. Test names here
are search topics, not assumed fixed discovery counts. Preserve all relevant original assertions.

## One deliberate broad checkpoint

Choose broader Stable only once after the final production source set settles and name the
invalidation trigger. Likely triggers are new public shared values/CI membership, modifications
to canonical assignment or secret owners, runtime acquisition/result contracts or shared UI
primitives. If the final changes are truly presentation-local, record why focused owning tests
suffice under the actual current policy. Do not run the aggregate after each stage or repeatedly
just to erase an old synthetic-control failure. [S27, S28]

A broad run must have pre-run source and binary manifests, current discovery, the exact documented
lane filter and an adequately provisioned owned PG18 instance. Record original exit code and all
results. Test-only repairs use separate output configurations. If a production repair follows the
freeze, state which earlier results no longer apply and run fresh affected proof; a material
shared change can require a new broad checkpoint. Never rewrite original failed runs as passing.

Mandatory closure includes current no-write portability enforcement, reviewed added/stale deltas,
source-secret scanning with explicit coverage and unchanged negative controls, documentation,
real dependency directions and public compatibility. Do not claim a whole-worktree scan is clean
when only added lines or a copied source snapshot were scanned. Seal no private credentials.

## Evidence and final answer

Use a working copy of templates/evidence.json outside the input package. For every G group
record status, actual attempts, relevant source/image/fixture, native identities, negative
counterexample and qualification. Counts are not automatically additive. A package validator
checks structure and hashes only; it cannot authenticate native receipts or certify software.

Final closure separately states: extracted families, original native semantics, small repairs,
remaining product findings, tests and original failures, asset/dependency delivery, actual watch
observations, safe resource disposition and exact next work. Workbench remains incomplete until
its remaining Workflow/Process integration family and final caller census are actually done.

## Resources

Stop only owned listeners/processes after tests; use native stop before teardown when that is
part of the scenario. Archive exact captures before changing fixture components, and preserve
volumes, original attempts and accepted artifacts for review unless explicitly authorized to
clean them. Do not free arbitrary ports or delete every Docker resource matching a broad name.
