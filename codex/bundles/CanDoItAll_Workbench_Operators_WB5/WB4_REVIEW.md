## Decision

Preserve WB4 as the completed bounded Content/File rendering family. No new blocking
WB4 defect was identified in the reviewed paths. Keep WB1 Planning, WB2 Insights,
WB3 Structure, Agents, provider and Workflow boundaries intact. Workbench still has
specialized operator and orchestration integration families; it is not complete. [S02]

The newly identified S0 issue belongs to the unchanged, deferred participant editor,
not to WB4. Reproduce it before fixing it, then continue all WB5 families.

## Positive implementation findings

- The text creator captures original admission, parent/source occurrence, opening,
  immutable submitted values and receiver before native effects. The original held-upload
  counterexample has a concrete repaired path, not only an added UI busy flag. [S05, S06]
- Content.UI declares only neutral component/FileTools dependencies. The real file
  children, text form, image form, Summary/transcript and Mermaid rendering moved.
  Native adapters retain permission, serialization, persistence and effect ownership. [S04, S08]
- Writable storage is rechecked both when an edit grant is issued and when it is
  resolved. An already issued handle does not bypass a later read-only/capability change. [S09]
- Image processing distinguishes provider invocation/completion, stored media and
  node attachment; original project/content and provider configuration are rechecked.
  Header/MIME/size checks are not a universal image decoder or proof of safe arbitrary bytes. [S10]
- Transcript analysis uses the original node and content expectations, retains external
  completion separately from native Save, and preserves unknown metadata. Tests include
  real pre/post-commit faults and one-call assertions, not only an echo fixture. [S11-S13]
- Neutral CanvasOverlayDialog is now owned by Components and is remotely available.
  Do not reimplement the former Structure wrapper or keep claiming it is local-only. [S03, S30]
