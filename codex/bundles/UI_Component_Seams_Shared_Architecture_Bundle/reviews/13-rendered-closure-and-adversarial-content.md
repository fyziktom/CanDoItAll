# Rendered closure and adversarial content

Evidence: [Capabilities extraction](../../UI_AgentCapabilities_03_Extraction_Sandbox_Bundle/proof/SB01/closure.md) and [sandbox visual review](../../UI_AgentCapabilities_03_Extraction_Sandbox_Bundle/proof/SB02/visual-inspection.md). These observations extend the earlier asset and direct-observation rules; they do not prescribe a feature-specific project layout.

1. A successful Razor build does not prove that every intended child component resolved. An unknown tag can survive compilation while its real action disappears. Pair the evaluated reference graph with a public rendering/action test. When a small shared child blocks extraction, inspect its actual dependencies and existing consumers before moving it to an already appropriate lightweight owner; do not add a reverse dependency to a broad UI assembly.
2. Validate representative long content visually and with observable geometry. Presence of the correct DOM nodes alone does not prove usable layout: intrinsic title width can collapse adjacent statistics, and a nested card child can size beyond its parent. Correct the smallest CSS ownership boundary, retaining real controls and scroll behavior.
3. A comparison fixture includes its surrounding controls and frame geometry. Freeze and verify those coordinates and interactive readiness before timing. If a visual correction is necessary after extraction, retain its failing evidence and refresh post-change source hashes before starting the comparison; never relabel earlier baseline bytes as the corrected source.

4. Rendered asset closure includes runtime-composed utility names and CSS cascade layers. A generated class can exist and still lose to an unlayered reusable-library rule. Verify computed layout in every supported asset mode. If production supplies a required compatibility rule, give that rule one shared asset owner rather than copying it into specimens or importing a broad application stylesheet. Preserve an incomplete-asset timing run as negative evidence and repeat the comparable series after correction. [Direct browser evidence](../../UI_AgentCapabilities_03_Extraction_Sandbox_Bundle/proof/SB03/responsive-utility-adjudication.md) proves this case.

No performance conclusion follows from these findings. Exact timing results and their limitations remain owned by the executable child.
