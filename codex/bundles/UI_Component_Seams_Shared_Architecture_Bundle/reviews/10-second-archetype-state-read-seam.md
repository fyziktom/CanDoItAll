# A second stateful rendering archetype

Proven by the [capability state/read closure](../../UI_AgentCapabilities_01_State_Read_Seams_Bundle/closure.md):

- A controlled catalog is one example, not a universal component template. A stateful feature can keep one effect host and one service-free surface, with a cohesive read boundary and per-instance read lifetime.
- Requested semantic identity and accepted loaded selection have different roles. Clear a prior editor during replacement, retain the failed target for Retry and ignore both stale success and stale failure.
- Keep local search, filters, expansion and raw form draft in the stable rendering instance. Authoritative snapshot replacement need not reset that presentation state.
- Rendered-wrapper disposal in a component test is not necessarily component removal. Verify the actual renderer lifecycle and corroborate owner cancellation with direct session and browser tests.
- A state/read child can close while mutation defects remain explicitly assigned to its successor. Unsafe characterization is temporary defect evidence and must not become intended mutation acceptance.
- Extraction readiness includes actual child consumers, CSS scope and project direction. A service-free surface alone does not prove a lightweight assembly or browser sandbox.

This is successor feedback. No provider-specific types, new universal framework, routing or performance claim is introduced.
