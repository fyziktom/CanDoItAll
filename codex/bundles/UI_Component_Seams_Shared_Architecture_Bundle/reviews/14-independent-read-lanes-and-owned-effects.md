# Independent read lanes and owned dashboard effects

Evidence: [state/read closure](../../UI_AgentsOverview_01_State_Read_Seams_Bundle/proof/O01/closure.md), [in-place effects closure](../../UI_AgentsOverview_01_State_Read_Seams_Bundle/proof/O02/closure.md), and [measured extraction closure](../../UI_AgentsOverview_01_State_Read_Seams_Bundle/proof/O03/closure.md). These rules describe proven ownership and observation boundaries, not a mandatory dashboard class hierarchy.

1. Aggregate availability is not workspace access. Keep independently useful reads and action eligibility in separate lanes. A failed summary must not erase a successfully resolved action target or override a valid selection access decision. One accepted immutable summary supplies every consumer of its totals; missing totals are omitted or unavailable, never invented zeroes.
2. Desired semantic selection and the scope of accepted data have different owners. Retain useful same-scope data after a failed refresh with an explicit stale state. Data accepted for another scope may remain cached internally, but must not be labeled, displayed, or passed to effects as the desired scope. Fence success, error and finally by both generation and request identity.
3. Prove presentation ownership against the real overlay service and navigation path. A page canceling only its own references is insufficient if a shared navigation handler independently closes all overlays. When direct regression proves this conflict, prefer a bounded opt-in ownership policy preserving the service's default behavior, and test unrelated presentations and scope release.
4. CSS isolation must reach actual rendered elements, not merely a Razor component invocation. A rendered-closure move requires computed-style and real-child checks, including long content at intermediate breakpoints. A chart title or decorative SVG is not proof of a usable chart; observe nonempty plot geometry and stable series paths.
5. A late visual correction can invalidate an earlier performance baseline even when the nominal extraction boundary is unchanged. Preserve the original series. Repeat the corrected pre-extraction owner with guarded source restoration and evaluated dependencies before comparing it with the corrected extracted owner. Keep cold startup, first-visible edits, settled edits and reverse restoration separate; performance conclusions belong to the completed measurement receipt.

These observations do not authorize new routes, a generic state framework, global dialog policy changes, or incidental sibling work. The bounded child records its explicit exception, evidence, compatibility scope and remaining repository validation debt.
