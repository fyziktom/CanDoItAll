# Project Structure Agent Generic Scenarios

This matrix captures scenarios that should be supported by prepared project-structure tools instead of long, fragile multi-call agent sequences. The requested `.xlsx` workbook could not be generated in this Codex session because the installed Spreadsheets skill requires `@oai/artifact-tool`, and that package is unavailable to the runtime.

| # | Scenario | Example prompt | Recommended one-call tool | Inputs | Tool responsibilities | Dependency handling |
|---:|---|---|---|---|---|---|
| 1 | Move selected nodes into a new subproject | Take selected nodes and move them to own new subproject named XYZ | `project_structure_nodes_to_new_subproject` | Source project id, selected node ids, subproject name, include descendants | Create child project, link it under source, move selected nodes and descendants, attach moved roots to target root | Preserve internal dependencies; remove cross-project links that would point outside moved set |
| 2 | Create several dependent work tasks | Add tasks for API, UI, tests, and release in correct order | Batch task-create tool candidate | Parent node, task drafts, dependency pairs | Create `WorkItem:task` nodes and link prerequisites in one operation | Create `DependsOn` from dependent task to prerequisite task |
| 3 | Create node with managed files/assets | Create a requirements docx node and attach this generated file | Existing `project_structure_asset_create`; future bulk asset tool | Parent node, file path or media payload, object subtype | Store file through managed asset pipeline, create node, connect to parent | Optional `Uses`/`DerivedFrom` links if source node supplied |
| 4 | Move multiple selected nodes on canvas | Move selected node with all under it more to top part with enough spacing | Bulk layout/move tool candidate | Node ids or root id, direction/anchor/spacing | Compute readable positions and apply node moves in one call | No dependency change; preserve all links |
| 5 | Change selected node types | Change selected notes to work task nodes | Batch type-change tool candidate | Node ids, target object type/subtype | Validate reclassification, preserve titles/notes/timing, normalize metadata | Keep dependencies unless target type is incompatible |
| 6 | Reparent selected nodes | Put these selected tasks under the implementation block | Batch reparent tool candidate | Node ids, target parent node key | Move multiple nodes under parent and prevent cycles/orphans | Preserve dependencies; warn if parent is also moved unexpectedly |
| 7 | Extract a branch from a parent node | Move all nodes under selected block to project ABC | Existing descendants transfer plus future branch extraction wrapper | Source node id, target project id | Move descendants under target root while source node remains | Preserve internal moved links only |
| 8 | Import outline into typed nodes | Import this outline as feature blocks and tasks | Existing import plus future typed import plan tool | Source outline, container subtype, leaf subtype | Parse source, create hierarchy, set types/subtypes | Infer serial or explicit dependencies when outline includes order markers |
| 9 | Convert notes into actionable work | Turn selected notes into tasks and decisions | Batch note-promotion tool candidate | Node ids, conversion map | Reclassify eligible notes and preserve note content | Add dependencies only when prompt names blockers/order |
| 10 | Build Gantt-ready plan | Create project tasks with dates and dependencies for this feature | Batch schedule planning tool candidate | Parent node, task list, durations, dates, dependencies | Create tasks with duration/start/end fields and dependency links | Must validate acyclic `DependsOn` graph |
| 11 | Normalize orphaned nodes | Ensure all selected nodes have proper parent connections | Invariant repair tool candidate | Project id, node ids or all nodes | Detect missing/invalid parents and attach to project root or chosen parent | Preserve dependency links; report broken external refs |
| 12 | Attach validation evidence | Add test evidence under this test plan and link it to tested task | Evidence creation tool candidate | Test plan id, task id, evidence asset | Create evidence node/asset and link it to tested node | Use `Tests` or `Validates`, not `DependsOn` |
| 13 | Create approval blocker | Ask for approval before deleting or moving this branch | Existing approval request; future operation wrapper | Requested operation, node ids, reason | Create approval-request node with enough operation detail | Add `Blocks` link to blocked work if relevant |
| 14 | Link process artifacts into structure | Connect this process definition/run to selected node | Existing process link tools | Node id, process definition/run id | Create proper process reference link | Use `Uses` for process definitions/runs |
| 15 | Bulk status/progress/priority update | Mark selected tasks complete and priority 2 | Existing batch mutation endpoints plus future combined tool | Node ids, status/progress/priority | Apply status, progress, priority, markers atomically | Recompute readiness after status updates |
| 16 | Split a large block into sub-blocks | Split selected implementation block into API, UI, tests | Block split tool candidate | Source block id, child block specs, redistribution hints | Create typed child blocks, reparent matching children | Preserve existing dependencies among redistributed nodes |
| 17 | Merge sibling blocks | Merge selected small blocks into one delivery block | Block merge tool candidate | Source block ids, target title/subtype | Create or choose target, move children, archive/delete empty shells | Preserve dependencies; remove obsolete hierarchy links |
| 18 | Create runtime infrastructure bundle | Add server, repo, script, env nodes for deployment | Infrastructure bundle tool candidate | Parent node, environment details, repo/script paths | Create infrastructure, repository, script, environment nodes | Use `Uses` links for runtime dependencies |
