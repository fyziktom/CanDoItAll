# Target Solution

The target solution is the architecture in `bundle://architecture/01-target-architecture.md` implemented through the ordered subbundles.

- Process definition contracts and target grounding produce typed metadata.
- Tool authorization consumes authoritative ledger records before legacy alias heuristics.
- Artifact identity is normalized once and persisted with a stable projection identity hash.
- Automated finalizer and manual/API transitions share the same artifact contract validator and storage-backed content reader.
- Block state and recovery routing use typed causes, persisted next actions, and invariant diagnostics.
- Refactoring checkpoints extract cohesive services instead of growing runtime partial classes.
