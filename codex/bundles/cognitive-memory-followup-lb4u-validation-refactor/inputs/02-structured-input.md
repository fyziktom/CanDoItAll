## LB4U Project Summary For Staged Input

LB4U means "Live Button For You". It is a patient-call and care-team notification system. A patient presses a WiFi-connected button module, the module sends the signal to a local server, and staff devices see which room or module needs attention. Staff can acknowledge the call. The system is intended for quick installation in hospitals or care facilities, low hardware cost, browser-based operation, no required internet dependency, and possible later extensions such as emergency buttons, infusion tracking, cameras, voice, door indicators, issue tracking, and project knowledge.

The source set contains final-state artifacts. Execution must replay them as staged project work:

1. Product discovery and pain statement.
2. Basic system concept and UX workflow.
3. Technical architecture and installation plan.
4. Procurement and device alternatives.
5. Custom button engineering.
6. Field testing and release plan.
7. Business plan, marketing plan, staffing, costs, and generalizable planning knowledge.
8. Consolidation and probing cycles.

## Validation Bias

- Useful memory is not a dump of source text. It must produce canonical project facts, traceable source chunks, recognized decisions, procedures, risks, assumptions, open questions, and reusable cross-project knowledge where justified.
- Generic business-plan or marketing knowledge must be derived from repeated evidence and consolidation, not hand-authored directly into canonical memory.
- A good answer must include relevant LB4U specifics and provenance. A generic model answer without source-backed memory should fail the gate.
