# Normalized Requirements

| ID | Requirement | Acceptance signal |
| --- | --- | --- |
| R01 | Define a generic Memory Protocol v1 with structured request/response envelopes, capability negotiation, correlation, policy, budgets, provenance, and extension payloads. | Contract tests cover sync query, async accepted operation, event envelope, feedback handle, source request, and provider manifest. |
| R02 | Introduce provider registry and provider instance profiles for zero, one, or many memory providers, with zero providers treated as a first-class typed state. | Base app starts with zero providers; provider management works; operations return typed no-provider diagnostics; two mock providers can be configured and selected independently. |
| R03 | Support provider-specific capability manifests and driver factories for HTTP, MCP-style, native remote, and mock providers. | Driver factory tests prove each driver is selected by profile kind and unsupported capabilities fail predictably. |
| R04 | Add operation ledger for sync/async operations, network timeouts, cancellation, polling, callback/event completion, and TTL cleanup. | Long-running mock provider returns accepted operation, status updates, cancellation, and final context. |
| R05 | Add event inbox/outbox for proactive memories, including dedupe, priority, causation/correlation, loop guard, and policy routing. | Event routing tests reject duplicates and block memory-agent-memory loop scenarios. |
| R06 | Add feedback ledger linking context pack deliveries to agent/process/session/workflow/customer/economic outcomes with retention and optional IPFS snapshot metadata. | Feedback tests submit immediate and delayed outcomes and expire/unpin evidence by policy. |
| R07 | Add Source Gateway abstractions and source snapshot contracts for projects, processes, CRM, resources, and future modules, reusing, rehoming, or explicitly migrating the current MAF `MemorySourceSnapshot*` contracts. | Providers can request snapshots only through adapters with provenance, sensitivity, and redaction metadata; no parallel incompatible source snapshot contract family exists. |
| R08 | Add manual ingestion actions such as `Ingest into memory` from source modules without exposing native EF entities. | UI/API action creates ingestion job for selected provider and source adapter. |
| R09 | Add generic memory operation service shared by MAF tool, workflow executor, context contributor, UI, and API paths. | Tool, executor, context contributor, and UI/API tests prove all routes invoke the same handler and operation ledger path. |
| R10 | Add provider selection for agents, workflows, processes, and runtime context contributors using current MAF provider/runtime context seams. | Business and programming mock providers can be assigned to different agents without cross-use; no-provider state does not fall back silently. |
| R11 | Replace direct `CognitiveMemory*` MAF context contributor/executors with generic memory contributor/tool/executor integrated through current `IAgentRuntimeToolProvider`, `IWorkflowExecutor`, and `IAgentContextContributor` patterns. | Architecture guard fails if MAF references native Cognitive Memory namespaces; tests prove current MAF runtime sees the generic memory registrations. |
| R12 | Build generic memory UI shell with provider management, query/chat, operations, events, feedback, and empty-state support. | Browser proof covers zero providers, mock provider, and failed provider states. |
| R13 | Support provider-specific UI through RCL components or iframe/external surfaces. | Native UI can be projected only when provider surface is available; fallback remains safe. |
| R14 | Scaffold native `CanDoItAll.CognitiveMemory` service/projects with independent DB, EF migrations, InMemory tests, workers, and API. | Native service builds and persists native records without main AppDbContext. |
| R15 | Migrate native engine/domain/persistence code from current module to native repo without requiring the main Agent module. | Native project references MAF abstractions only where needed and has no main module dependency cycle. |
| R16 | Expose native Cognitive Memory through generic protocol and optional advanced endpoints/surfaces. | Main app talks to native memory through remote/native driver and protocol contract tests. |
| R17 | Remove base CanDoItAll dependencies on native Cognitive Memory and Qdrant. | Base host starts with PostgreSQL plus app only; Qdrant appears only in optional native provider/projection path. |
| R18 | Provide migration/export/compatibility strategy for existing main DB native memory tables. | Migration plan and tests prove old data can be exported or retained read-only without forcing new native tables into AppDbContext. |
| R19 | Rebalance tests into generic memory tests, native memory tests, adapter compatibility tests, UI tests, and architecture dependency guards. | Final test suite passes and direct dependency guards are included. |
| R20 | Add checkpoint/refactoring gates after each phase. | Checkpoints produce proof for bounded public APIs, no duplicated handlers, no overgrown helper files, async correctness, no direct native dependencies, and source coverage. |
| R21 | Align the bundle with the current live repositories before implementation or repair. | Implementation agents read `analysis/04-live-repo-reentry-alignment.md`; historical assumptions are replaced with the 2026-07-12 source truth that both the generic implementation and external Cognitive Memory service exist but require repair. |
| R22 | Add a strongly typed agent memory invocation mode with `Disabled`, `Automatic`, and `ExplicitDirective` behavior. | Agent settings round-trip the enum; automatic mode contributes configured memory without a directive; explicit mode performs no memory query without an authorized directive; disabled mode never invokes memory and reports an explicit rejection when directed. |
| R23 | Model one agent's memory access as strongly typed provider bindings with unique aliases so the agent can use zero, one, or many providers without stringly typed profile logic. | Agent editor/API persistence round-trips multiple bindings; aliases are validated case-insensitively for uniqueness; two-provider tests prove deterministic fan-out/selection and provider-labelled merged context without cross-use. |
| R24 | Parse, authorize, and remove explicit memory directives such as `/mem:memory1` before the user prompt reaches a model or provider. | Parser tests cover one or many directives, whitespace/casing, deduplication, prompt sanitization, unknown aliases, disabled providers, and attempts to select a provider outside the agent's bindings; invalid directives fail with typed diagnostics. |
| R25 | Enforce fail-closed provider selection and operation ownership. Selection must honor the requested provider, allowed provider IDs, and explicit fallback policy; status and cancellation must authorize the original requester and runtime scope. | Registry tests prove deny-fallback never selects the first enabled provider; ambiguous selection fails; status/cancel tests reject another agent, session, or requester without disclosing operation data. |
| R26 | Propagate typed execution, workspace, and project context from the real agent invocation through generic memory requests and HTTP/MCP protocol envelopes. | Integration tests prove agent, session, workspace, project, process, workflow, and step identity survive routing; project-scoped recall works; missing or malformed scope fails explicitly rather than degrading to global; runtime code does not depend on magic tag keys for required identity. |
| R27 | Repair project and namespace ownership so configuration, routing, context contribution, tools, application operations, drivers, workers, and persistence have cohesive boundaries; capability-grouping partial classes are prohibited. | Architecture inventory, boundary map, dependency audit, CodeAnalytics review, and guards prove no new project cycles, no prohibited partial clusters, bounded constructors/public APIs, independently testable services, and an explicit composition root. |
| R28 | Preserve provider transport configuration safely, register HTTP/MCP/native/mock drivers explicitly, resolve secrets by reference, and advertise only capabilities implemented end to end. | Provider edit round-trip preserves unknown and driver-specific extensions; persisted/exported profiles contain no raw secrets; MCP can be selected through production DI; unsupported ingestion, feedback, event, operation-status, or UI capabilities are rejected or omitted consistently. |
| R29 | Secure the external Cognitive Memory service and prove protocol conformance, including authentication, caller authorization, access/redaction policy, strict project isolation, request limits, and a real main-driver seam test. | Unauthenticated calls return 401; unauthorized project/provider access returns 403 or a typed denial; invalid project scope never falls back to global; restricted/unapproved/redacted memories are filtered by policy; manifests match implemented behavior; main HTTP driver conformance tests pass against the hosted external service. |
