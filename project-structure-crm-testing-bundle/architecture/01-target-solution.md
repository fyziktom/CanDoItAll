# Target Solution

- Use one umbrella project that represents the CRM/HR bundle as a whole and attach execution-oriented subprojects for the major B01-B13 workstreams.
- Keep the umbrella project readable by using overview nodes that summarize waves, gates, and control points rather than dumping every detailed task into one canvas.
- Create detailed subproject structures from the source bundle using a mix of import-driven hierarchy and typed follow-up nodes where richer semantics matter.
- Add AI-agent participants as explicit `Participant/ai-agent` nodes, then assign targeted work items to them through work-item metadata instead of burying ownership in notes.
- Use import-driven dependency capture for at least the roadmap/dependency surfaces because the public MCP API currently lacks direct link mutation.
- Judge success on three axes: technical correctness of project-structure creation, visual readability of the canvas, and managerial usefulness of the resulting plan.
- Route any weakness discovered during the browser review into the same run before closure instead of accepting a technically-created but operationally-weak plan.
