Project-structure runtime tools are governed by the typed `ProjectStructureAccess` field on `hr_agent_create` and `hr_agent_settings_update`, not by capability-catalog entries. Do not create or assign a capability merely to grant these tools. On creation, omitted nested fields default to no grant. On update, `ProjectStructureAccess` is a nested patch: omit every field that is not changing, because omitted booleans and project IDs preserve their current values. An empty `AllowedProjectIds` array explicitly clears the ID scope. Setting `AllowAllProjects=true` clears existing IDs; supplying non-empty IDs disables `AllowAllProjects`. Never explicitly request `AllowAllProjects=true` and non-empty IDs together. For an agent that must maintain structure, tasks, and assets across existing projects, use the least-privilege shape `CanRead=true`, `CanWrite=false`, `CanWriteNonTaskStructure=true`, `CanWriteTasks=true`, `CanCreateProjects=false`, `CanCreateSubprojects=false`, `AllowAllProjects=true`, and no explicit project IDs. Use explicit project IDs instead of `AllowAllProjects` when narrower scope is sufficient. After creation or update, call `hr_agent_settings_get` and verify the normalized `ProjectStructureAccess` readback before relying on project-context tools.

Workspace file, command, external-target, and storage tools are governed by the typed `WorkspaceToolAccess` field. Its fields are `Profile`, `CanReadFiles`, `CanWriteFiles`, `CanRunValidationCommands`, `CanRunLocalScripts`, `CanScaffoldProjects`, `CanManageWorkspacePaths`, `CanTransformArtifacts`, `AllowedExternalTargetAliases`, `CanReadStorage`, `CanWriteStorage`, `AllowAllStorageCatalogs`, and `AllowedStorageCatalogIds`. On `hr_agent_create`, omitting the whole object preserves the legacy `Custom` read-files-only default; supplying it is a complete requested setting whose omitted nested booleans default to false. For no workspace or storage access, explicitly use `Profile=Custom`, every permission boolean false, and empty alias and storage-ID arrays. A named profile is a minimum grant: normalization enables its required permissions; manage, scaffold, and transform imply file write; file write, validation, scripts, or external aliases imply file read; and storage write implies storage read. On `hr_agent_settings_update`, `WorkspaceToolAccess` is a nested patch: omit the object or individual fields to preserve them, while a supplied array replaces that list and `[]` clears it. Every external alias must be an absolute path or canonical `external-target/<drive>/<path>` below a drive root; invalid aliases and empty storage GUIDs fail. `AllowAllStorageCatalogs=true` clears existing IDs, and supplying non-empty IDs disables allow-all; never send true and non-empty IDs together. To remove every storage scope, set `AllowAllStorageCatalogs=false` and `AllowedStorageCatalogIds=[]`. After creation or update, call `hr_agent_settings_get` and verify the normalized `WorkspaceToolAccess` readback.
