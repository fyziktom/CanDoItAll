# Validate Blazor runtime and browser evidence

Run validation against the delivered Blazor SSR, WASM, or WASM PWA app. Use the authoritative product root from the delivery contract and implementation change set. Before reporting an external-target access failure, call `workspace_stat_path` or `workspace_read_file` against the exact path and cite the failed receipt; absence of a failed receipt is not proof of access failure.

Run dotnet restore, dotnet build, and dotnet test when a test project exists or was created. Start the app once from the approved product root and record the startup receipt. Use Playwright browser tools for every visible UI surface named by project structure or implementation evidence. Capture screenshot image paths, browser_snapshot or browser_evaluate state output, browser_console_messages output, actual URL or entrypoint, visible behavior assertions, and cleanup receipt. For new app delivery, include the matching API/backend proof as well. Missing, blank, detached, stale, or chat-only screenshots are not acceptable.

If implementation evidence or runtime inspection shows a scaffold-only app, deferred acceptance criteria, missing routes, missing product behavior, no-op handlers for named interactions, missing persistence, missing PWA/static-hosting proof, failed browser assertions, or incomplete screenshots/console proof, choose the `repair-required` branch and write both required validation artifacts with concrete findings. Use `Blocked` only for a confirmed tool, policy, or infrastructure failure that prevents validation and has a matching failed receipt. Project-structure evidence-node attachment is not part of this validation decision: after the managed validation artifacts are written, do not fail this step solely because `project_structure_node_create` or project-structure writeback cannot attach the evidence node, and do not call `project_structure_node_create` or `project_structure_asset_create` from this validation step. Do not use `workspace_pwsh_run_script` for cleanup or diagnostic helper scripts; record startup/cleanup receipts from `workspace_dotnet_run`, browser tools, and managed artifacts. This review step must select exactly one governed branch: `quality-accepted` only when all criteria and proof are satisfied, otherwise `repair-required`; do not complete with the Default branch.

## Evidence

Record commands, files, URLs, screenshots, console messages, errors, and assumptions. Project-structure writeback belongs to the result-recording steps, not this validation step.
