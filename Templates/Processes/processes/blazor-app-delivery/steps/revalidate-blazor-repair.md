# Revalidate Blazor repair

Run validation against the delivered Blazor SSR, WASM, or WASM PWA app. Before running restore/build, stop any prior `workspace_dotnet_run` process for the same product root by calling `workspace_dotnet_stop` with the recorded startup.json receipt when available; do not run build while the product executable is still locked by a previous validation runtime. Run dotnet restore, dotnet build, and dotnet test when a test project exists or was created. Start the app once from the approved product root and record the startup receipt. Build, test, and analyzer warnings remain validation defects after repair; if a warning still cites an editable product or test file, choose repair-required with the exact warning and line instead of repair-escalation. Use Playwright browser tools for every visible UI surface named by project structure or implementation evidence. Capture screenshot image paths, browser_snapshot or browser_evaluate state output, browser_console_messages output, actual URL or entrypoint, visible behavior assertions, and cleanup receipt. After browser proof, call workspace_dotnet_stop with the startup receipt path and record cleanup.json evidence before returning any branch outcome, including repair-required or Blocked. For new app delivery, include the matching API/backend proof as well. Missing, blank, detached, stale, or chat-only screenshots are not acceptable. Do not call `project_structure_node_create` or `project_structure_asset_create` from this validation step; result writeback belongs to the result-recording steps. Do not use `workspace_pwsh_run_script` for cleanup or diagnostic helper scripts; record startup receipts from `workspace_dotnet_run` and cleanup receipts from `workspace_dotnet_stop`, with browser evidence and managed artifacts. Do not return any branch outcome until the validation runtime is stopped or an explicit failed cleanup receipt is cited as the blocker.

Revalidate the approved product root only. If the repair leaves a sibling app project, sibling `*.Tests` project, nested copied/probe scaffold, or custom host output path property inside the product root, choose `repair-required` again and cite the concrete path or property. Do not accept proof from a different project root.

## Evidence

Record commands, files, URLs, screenshots, console messages, errors, and assumptions. Project-structure writeback belongs to the result-recording steps, not this validation step.
