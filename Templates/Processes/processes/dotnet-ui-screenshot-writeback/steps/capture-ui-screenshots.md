# Capture UI screenshots when required

For UI targets, start or reuse the app using the recorded Run app node. When the app is not already reachable, call `workspace_dotnet_run` with `targetPath` set to `DotNetAppProjectFileAlias` when present, otherwise `DotNetAppProjectFile`, with `workingDirectory` set to `ProductRootAlias`, `WorkspaceAlias`, or the equivalent product-root alias, `keepAlive` enabled, and `lifetimeScope` set to the current process run. `workspace_dotnet_run` accepts project files only; never pass `DotNetSolutionFile`, `DotNetSolutionFileAlias`, `ProductRoot`, `WorkspaceAlias`, `DotNetAppProjectDirectory`, or any directory path as its `targetPath`. If a previous attempt used a `.sln`, `.slnx`, or directory target, retry once with the app `.csproj` target before returning `Blocked`. `workspace_dotnet_run`, `browser_navigate`, `browser_snapshot`, `browser_take_screenshot`, `browser_console_messages`, and `workspace_dotnet_stop` are declared required runtime tool receipts for UI targets. Then use Playwright MCP tools to navigate and capture proof: `browser_navigate` for each concrete route, `browser_snapshot` to a durable `.yml` filename, `browser_take_screenshot` to a durable `.png` filename, and `browser_console_messages` to a durable `.log` filename under the current process-run artifact root. Stop any app process you started with `workspace_dotnet_stop` and include the startup and cleanup receipt refs. For no-UI targets, do not launch a browser; write an explicit no-UI screenshot receipt instead. Do not create project-structure nodes or image assets here; the storage step owns Screenshots writeback.

Prefer the recorded Run app node for launch. Missing base URL or missing Run app node is not a successful capture result for a UI target. If those references are missing and the launch variables include `DotNetAppProjectFileAlias`, `DotNetAppProjectFile`, `ProductRoot`, `ProductRootAlias`, or `DotNetAppProjectDirectory`, call `workspace_dotnet_run` with the app project file target and use the returned current-run URL for browser capture before returning `Blocked`. Do not return `Blocked` only because the base URL is absent when a product root or app project file is present; attempt `workspace_dotnet_run` against the app project file first and cite the receipt. If the manifest marks command-node references as missing but cites verified upstream QA/runtime browser evidence, use the cited base URL as the launch target and capture fresh current-run artifacts from that URL. Treat prior screenshots as source evidence only; do not submit screenshots from another process run as this step's output. If the verified URL is unreachable and no launch command is available, block with the exact missing launch reference, URL, route, and browser error. Do not write `Status: Completed`, do not say screenshots were captured, and do not hand off to storage until the evidence includes successful `browser_take_screenshot` and `browser_snapshot` receipts for each required route and viewport, or an explicit no-UI receipt. If the capture itself proves the UI is only scaffold chrome, blank, wrong-route, unstyled, non-interactive, or materially inconsistent with a named source visual target, write the screenshot and browser evidence but return `Blocked` with the concrete visual defect instead of declaring capture complete.

## Contract
- Inputs: Screenshot target manifest, Run app command node reference when available, or verified upstream runtime URL/browser evidence from the manifest.
- Outputs: Screenshot files and browser evidence for UI targets, or explicit no-UI receipt for non-UI targets.
- Evidence: Current-run screenshots, route URLs, console state, runtime command references or cited degraded runtime evidence, cleanup receipt, or no-UI evidence.
- Operation target scope: `ExternalProductTargetReadOnly`
