# Capture UI screenshots when required

For UI targets, start or reuse the app using the recorded Run app node. When the app is not already reachable, call `workspace_dotnet_run` with `targetPath` set to `DotNetAppProjectFileAlias` when present, otherwise `DotNetAppProjectFile`, with `workingDirectory` set to `ProductRootAlias`, `WorkspaceAlias`, or the equivalent product-root alias, `keepAlive` enabled, and `lifetimeScope` set to the current process run. `workspace_dotnet_run` accepts project files only; never pass `DotNetSolutionFile`, `DotNetSolutionFileAlias`, `ProductRoot`, `WorkspaceAlias`, `DotNetAppProjectDirectory`, or any directory path as its `targetPath`. If a previous attempt used a `.sln`, `.slnx`, or directory target, retry once with the app `.csproj` target before returning `Blocked`. `workspace_dotnet_run`, `browser_navigate`, `browser_snapshot`, `browser_take_screenshot`, `browser_console_messages`, and `workspace_dotnet_stop` are required receipts only for the `ui-capture-complete` outcome. Then use Playwright MCP tools to navigate and capture proof: `browser_navigate` for each concrete route, `browser_snapshot` to a durable `.yml` filename, `browser_take_screenshot` to a durable `.png` filename, and `browser_console_messages` to a durable `.log` filename under the current process-run artifact root. Stop any app process you started with `workspace_dotnet_stop` and include the startup and cleanup receipt refs. For a target explicitly classified as having no browser-visible UI, do not launch a browser; write the evidence-backed no-UI receipt and select `no-ui-evidence-recorded`. Do not create project-structure nodes or image assets here; the storage step owns Screenshots writeback. A create-required `Screenshots` child is normal downstream storage work and is outside this step's completion gate. Do not describe it as a managed fallback, missing current-run evidence, a limitation, a warning, a blocker, or a capture next action. Once the applicable browser and cleanup receipts exist, return `Completed` with `ui-capture-complete`; `store-ui-screenshots` will create or reuse the child node and attach the captured images.

Ground every DOM assertion in the same-run browser evidence. Begin with `browser_snapshot`, then record selector or locator provenance from that snapshot, a same-run DOM enumeration/evaluation, or an exact product source read before using it to assert presence, absence, count, or state. A zero match from an ungrounded selector is inconclusive and is not evidence that the UI element or behavior is absent. Reconcile evaluated state with the same-run snapshot and screenshot. When they conflict, omit the unsupported structured claim or recapture it with a locator observed in the current run; do not convert an ungrounded conflict into a product defect. A visible discrepancy that remains grounded after reconciliation is still evidence for downstream assessment, not a capture blocker. `browser_evaluate` is optional and does not replace the required snapshot and screenshot receipts.

When the `DotNetAppProjectFile*` aliases are absent, use the explicit `requiredProjectFiles` in runtime-forwarded `solution-context` only as candidates for grounded runnable-project inspection in the inherited implementation handoff. If that context is also absent, inspect the grounded product root and use the discovered project-file target. Do not guess a conventional directory, project name, or framework. The cross-run child ref shown in forwarded context is trace-only; use the copied payload or grounded readback.

Prefer the recorded Run app node for launch. Missing base URL or missing Run app node is not a successful capture result for a UI target. If those references are missing and the launch variables include `DotNetAppProjectFileAlias`, `DotNetAppProjectFile`, `ProductRoot`, `ProductRootAlias`, or `DotNetAppProjectDirectory`, call `workspace_dotnet_run` with the app project file target and use the returned current-run URL for browser capture before returning `Blocked`. Do not return `Blocked` only because the base URL is absent when a product root or app project file is present; attempt `workspace_dotnet_run` against the app project file first and cite the receipt. If the manifest marks command-node references as missing but cites verified upstream runtime browser evidence, use the cited base URL as the launch target and capture fresh current-run artifacts from that URL. Treat prior screenshots as source evidence only; do not submit screenshots from another process run as this step's output. If the verified URL is unreachable and no launch command is available, block with the exact missing launch reference, URL, route, and browser error. Do not write `Status: Completed`, do not say screenshots were captured, and do not hand off to storage until the evidence includes successful `browser_take_screenshot` and `browser_snapshot` receipts for each required route and viewport, or an explicit no-UI receipt. A missing browser, launch failure, or inaccessible UI route is not no-UI evidence: use `no-ui-evidence-recorded` only when the applicability manifest explicitly classifies the target as having no browser-visible UI and cites the supporting product or architecture evidence. If the capture itself proves the UI is only scaffold chrome, blank, wrong-route, unstyled, non-interactive, or materially inconsistent with a named source visual target, write the screenshot and browser evidence, record the observed state, select `ui-capture-complete`, and continue to storage and evidence assessment. That observed product discrepancy is not a capture blocker. Return `Blocked` only when launch, browser, route, access, policy, or provider execution prevents capture of grounded evidence.

## Contract
- Inputs: Screenshot target manifest, Run app command node reference when available, or verified upstream runtime URL/browser evidence from the manifest.
- Outputs: `ui-capture-complete` with screenshot files and browser evidence, or `no-ui-evidence-recorded` with an explicit no-UI receipt.
- Evidence: Current-run screenshots, snapshots, route URLs, console state, selector/locator provenance for any DOM assertion, reconciliation of evaluated state with the same-run snapshot and screenshot, runtime command references or cited degraded runtime evidence, cleanup receipt, or explicit no-UI classification evidence.
- Operation target scope: `ExternalProductTargetReadOnly`
