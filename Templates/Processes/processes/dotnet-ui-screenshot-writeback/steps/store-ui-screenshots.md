# Store screenshots under process run node

Create or reuse a Screenshots parent node under the current process run node. Prefer `ProcessRunNodeId`, `ParentProcessRunNodeId`, or `TargetProcessRunNodeId` from launch variables as the parent node id; do not fall back to `ProjectNodeId` or project root when one of those process-run nodes is present in project structure. For UI targets, inspect each screenshot, reject blank/error/wrong-route images, and create image asset nodes under Screenshots for accepted screenshots. For no-UI targets, record a no-UI screenshot receipt under Screenshots or as managed evidence so the parent release step can see that screenshot capture was intentionally not applicable. Do not mutate product files.

For UI targets, `workspace_inspect_image` and `workspace_analyze_image` are declared required runtime tool receipts for this step. Call `workspace_inspect_image` and `workspace_analyze_image` for every accepted or rejected screenshot before storage, and ground the visual reason in the provider-backed result rather than dimensions, filenames, or chat-only description. If the assigned provider/model is not vision-capable, return `Blocked` with that exact capability gap.

When project structure, launch variables, the screenshot manifest, or upstream QA evidence list source visual target ImageAsset nodes such as proposals, mockups, reference screenshots, layout targets, or wireframes, compare the delivered screenshot against the relevant source target before accepting visual alignment. Resolve the target by node id and media path with `project_structure_read`, `project_structure_asset_get`, or `project_structure_asset_content_get` as needed, then call `workspace_analyze_images` with the ordered source-target image and delivered screenshot paths when the image files are accessible in the workspace. If the target asset content is not accessible to image-analysis tools, return `Blocked` with the missing node id, media path, and failed tool receipt instead of accepting screenshots in isolation. The storage review must include a `Visual target comparison` section naming the source ImageAsset node id, media path or file name, delivered screenshot ref, comparison method, and accepted or blocked disposition.

When accepted UI screenshots exist, project-structure writeback is a required action. `project_structure_node_create` and `project_structure_asset_create` are declared required runtime tool receipts for this step. If the Screenshots parent is missing, call `project_structure_node_create` with objectType `ProjectBlock`, objectSubtype `delivery`, and `parentNodeKey` set to the process-run node. Then call `project_structure_asset_create` once per accepted screenshot with objectType `ImageAsset`, objectSubtype `screenshot`, `parentNodeKey` set to the Screenshots node, and `sourceWorkspacePath` set to the current-run PNG path such as `artifacts/process-runs/{runId}/browser-route-home-desktop.png`; also set `sourceFileName` and `sourceContentType` explicitly. If `project_structure_read` works, do not infer the writeback tools are unavailable from memory or prompt text; attempt the required writeback tools before reporting a boundary. Do not read binary screenshots as text or base64 when `sourceWorkspacePath` can be used. If an upload attempt fails because an inline media payload is invalid base64, retry once with the accepted screenshot using `sourceWorkspacePath` instead of the inline media payload. Record the Screenshots node id and every returned image asset node id.

Do not write `Status: Completed`, do not say storage completed, and do not hand off with only a managed receipt until `project_structure_asset_create` has been attempted for every accepted UI screenshot. A managed-only storage receipt is allowed only after the exact project-structure tool call is unavailable, denied, or fails because the process-run/Screenshots parent cannot be read or written; the receipt must name the failed tool, failed parent target, screenshot path, route, viewport, inspection result, and failure receipt. If `project_structure_asset_create` or `project_structure_node_create` is unavailable or denied for this governed step, return `Blocked` with the missing tool or operation allowance instead of completing silently. Block when screenshots are missing, blank, wrong-route, unreadable, or when project-structure writeback is available but fails with an unexplained or partial mutation.

## Contract
- Inputs: Screenshot files, browser evidence, and screenshot target manifest.
- Outputs: Screenshots parent node under process run node and image asset storage receipts for accepted screenshots.
- Evidence: Screenshots parent node id and image asset ids when available, or managed storage receipt with explicit writeback limitation, plus `workspace_inspect_image`, `workspace_analyze_image`, and when source visual targets exist `workspace_analyze_images` receipt refs, `Visual target comparison` details, rejected images, and no-UI receipt when applicable.
- Operation target scope: `ExternalActionControlled`
