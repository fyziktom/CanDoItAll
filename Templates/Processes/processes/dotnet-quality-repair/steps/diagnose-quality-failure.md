# Diagnose the exact quality failure

Begin with every exact ref under `AgentFramework inherited parent-step artifact refs` and read the relevant parent artifacts before diagnosis. Runtime-appended gate findings are authoritative even when the original agent summary claimed acceptance.

When the inherited refs contain an original scope or acceptance packet, keep it authoritative throughout diagnosis. Do not reduce a multi-criterion product request to the latest missing receipt or scaffold finding. Determine whether the product actually implements the full core workflow before classifying the issue as proof-only.

Then read the actual failed command, browser snapshot, console log, screenshot, or output evidence. Name the exact failed invariant and correlate it to the most likely owning source or composition boundary before anyone edits the product.

A missing accepted implementation handoff is a symptom of the child no-go, not a standalone proof-only diagnosis. Read why the child withheld acceptance, compare the actual product against every authoritative core criterion, and diagnose the unresolved product behavior or owning source gap. The quality-repair subprocess cannot repair another subprocess merely by requesting a different handoff artifact.

Before completing, read representative current product source under the grounded product root at that likely owning boundary. For a workflow or behavior criterion, inspect the owning application/component/domain source and relevant test; project files, bootstrap files, router/app shell, imports, navigation, or stylesheet readback alone are insufficient unless the failed criterion is specifically owned there. Upstream diagnosis prose is not product inspection. For a visible UI error, compare rendered state, console diagnostics, styling, and the owning source before assuming which layer caused it.

Treat source grounding as an ordered execution obligation, not a prose requirement: inspect the external target, descend from a directory listing when needed, then call `workspace_read_file` on one concrete behavior-owning product file under the grounded `external-target/...` alias before writing this step's managed artifact. A managed artifact read, a directory listing, or a project/bootstrap/shell file does not satisfy that receipt unless it directly owns the failed criterion.

Do not propose broad cleanup. Record the smallest repair target, exclusions, and the proof that must turn green. A visible error, failed command, invalid calculation, or broken output is an unresolved defect, not residual risk.
