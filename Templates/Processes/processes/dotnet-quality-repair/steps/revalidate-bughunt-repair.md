# Independently revalidate the bughunt action

Reproduce both the original and persistent failed proof, then run current-execution restore, build, tests, and conditional runtime/browser validation against the typed second action. Read the actual repaired app project, representative workflow source, and relevant test source. For UI work, capture baseline state, perform the representative click/fill/select/key/type/drag or elapsed-time action, and capture post-action `browser_evaluate`, snapshot, screenshot, and console proof. Apply the corrected proof target or recipe when the action selected `proof-only-revalidation-prepared`. Known failed proof is not residual risk.

Verify the inherited authoritative scope packet criterion by criterion, but gate the result only on criteria with `kind=ProductAcceptance` and `required=true`; do not accept an app shell or one changed control as the complete required workflow. Preserve `kind=DeliveryPlanning` items as nonblocking context. They cannot select `quality-repair-no-go`, block `quality-repair-accepted`, or require human confirmation unless a separate typed decision gate explicitly requests that decision. Before writing the artifact or finalizing, reconcile every required current-execution tool receipt. Read concrete owning product source and run `browser_evaluate` after the representative interaction and before `workspace_dotnet_stop`.

For persistence proof, a deterministic test through the typed storage adapter or coordinator is sufficient to prove graceful unavailable behavior unless a required ProductAcceptance criterion explicitly demands a live browser storage outage. For normal IndexedDB reload proof, use `browser_evaluate` to seed and inspect the declared database and object-store schema, reload the app, and verify restored UI state; do not require playing or operating the workflow until it naturally creates a nonzero value.

Pass full managed filenames to every browser screenshot, snapshot, and console capture: `artifacts/process-runs/<current-process-run-id>/browser/<evidence-name>.<ext>`. If an inherited or newly captured bare provider-native screenshot cannot be opened by a workspace image tool, recapture it once with the full managed current-run filename and retry analysis before choosing `quality-repair-no-go`, `Blocked`, or escalation. When a source visual target exists, call `workspace_analyze_images` with the ordered pair of source target first and delivered current-run screenshot second, and cite that receipt in final evidence.

If the second action was routed as `repair-attempt-incomplete`, do not retry that implementer inside this subprocess. Reproduce the unresolved defect and select `quality-repair-no-go` with exact current-run evidence.

Select `quality-repair-accepted` only when both defect sets are resolved and no new release blocker exists. Select `quality-repair-no-go` with exact failing evidence when the defect persists or the second repair introduces another release blocker. Do not request a third blind mutation inside this subprocess.

Capture all proof before writing the primary managed artifact and write it once with the final branch. A reproduced defect or unchanged expected interaction is a completed `quality-repair-no-go` decision, not a Blocked outcome. Do not create a provisional `Status: Blocked` artifact merely because the proof is negative.
