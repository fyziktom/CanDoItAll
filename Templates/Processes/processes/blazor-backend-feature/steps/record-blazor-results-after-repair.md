# Record repaired Blazor results and evidence index

Write a compact run evidence index, agent self-review summary, output-root path, screenshot references, console status, build/test status, and final verdict back into project structure through APIs/tools. Resolve the target WorkItem from the current launch context and use that WorkItem as the direct parent; never fall back to the project root or another delivery/output block. Before creating a result node, call `project_structure_read` for the target WorkItem and its children and look for a result Note for the current process run. On retry, reuse that current-run Note: call `project_structure_node_reparent` first if it is not a direct child of the target WorkItem, then call `project_structure_node_update` to refresh its title, notes, and verdict. Do not create a duplicate. Only when no current-run result Note exists, call `project_structure_node_create` with objectType `Note`, no subtype, parentNodeKey set to the target WorkItem id, and metadataJson `{}`; the result is a plain descriptive Note, not a WorkItem, ProjectBlock, asset, or runnable node. Use `project_structure_asset_create` separately for screenshot or evidence files that must become project assets. Read back the final Note, and record whether it was created, reused, updated, or reparented plus its node id, direct parent WorkItem id, asset ids, and raw record pointers needed for selective follow-up. If a required read, create, update, reparent, asset, or readback call fails, return status Blocked with the exact failed tool and receipt; do not select the Error branch as a completed outcome.
