# Resolve .NET run and test commands

Read current project structure, architecture handoff, implementation evidence, and QA proof to determine the product root, app type, runtime project, test project, working directory, environment variables, ports, and stop behavior. Treat the step brief process run id, managed artifact root, `CurrentProcessRunId`, `CurrentProcessRunNodeId`, `CurrentManagedArtifactRoot`, `ParentProcessRunId`, `ProcessRunNodeId`, `ParentProcessRunNodeId`, and `TargetProcessRunNodeId` as typed launch context: `Current*` identifies this subprocess and `ProcessRunNodeId`/`ParentProcessRunNodeId`/`TargetProcessRunNodeId` identify the parent process-run node that will receive durable Run command nodes. Produce a manifest with planned runtime-capable project-structure node payloads for Run app and Run tests. Run app must plan an `Environment` node with subtype `dotnet-runtime`, `dotnet-watch`, or `dotnet-release` when the app is runnable. Run tests, build, and utility commands must plan a `Script` node with subtype `console` or `powershell` and script metadata for command, arguments, and working directory. Do not plan runnable commands as `ProjectBlock` + `delivery` nodes. Do not call project-structure mutation tools in this resolve step. If the delivery target is a class library or otherwise non-runnable, the planned Run app payload must still carry a not-applicable reason rather than being omitted. Do not block only because the parent process-run node is projection-backed or not returned by a direct persisted-node read; record the target node id from launch variables and let the writeback step verify or create durable project-structure receipts.

## Contract
- Inputs: Architecture handoff, implementation evidence, QA evidence, and project-structure run node context.
- Outputs: Typed manifest for planned runtime-capable Run app and Run tests project-structure node payloads.
- Evidence: App type, command strings, working directories, ports, environment notes, and no-run-app rationale when applicable.
- Operation target scope: `ExternalProductTargetReadOnly`
