# Write Run command project nodes

Create or reuse exactly one organizational runtime command group under the process run writeback node, then create or update child nodes Run app and Run tests under that group as runtime-capable project-structure nodes. Resolve the process run writeback parent from `TargetProcessRunNodeId`, `ParentProcessRunNodeId`, or `ProcessRunNodeId` in that order; do not fall back to `ProjectNodeId` or project root when one of those process-run nodes is present in project structure. Use a non-runnable operations organizer such as `ProjectBlock` + `operations` for the group; do not create a `ProjectBlock` + `delivery` node named like a runnable command. Do not create Run app or Run tests directly under the process run node when the group exists. On retry, reuse the existing group and child nodes with the same parent, object type, subtype, and title instead of creating duplicates. Run app must be an `Environment` node with subtype `dotnet-runtime`, `dotnet-watch`, or `dotnet-release` when the target is runnable, with `metadata.environment.projectPath` populated as an absolute project file/folder path or paired with `metadata.environment.workingDirectory` when the project path is relative. Include launch profile, protocol, and localhost URL when known. Run tests, build, and utility commands must be `Script` nodes with subtype `console` or `powershell`, with script metadata for command, arguments, and working directory. Do not create runnable command nodes as `ProjectBlock` + `delivery` or any other delivery block. You must call `project_structure_node_create` for the durable runtime command writeback and then `project_structure_read` to read back the created or reused Run app and Run tests nodes before completing this step; do not return `Completed` with only intended node payloads, placeholder node ids, or "pending writeback receipt" text. Each child node must include command, working directory, app type, source evidence, and any required environment or cleanup notes. After writing each runnable node, read back the node metadata with `project_structure_read` and record a launcher-compatibility receipt: object type, subtype, project path or command, arguments, working directory, and whether the metadata is sufficient for `ProjectStructureRuntimeLauncher.Resolve` to create a launch plan. Write the required receipt artifact for this step at `artifacts/process-runs/<current-process-run-id>/steps/run-command-node-receipts.md`; do not use `runtime-command-handoff.md` for this step because the handoff belongs to the downstream `runtime-command-handoff` step. If a runnable Run app or Run tests node cannot be made launcher-compatible, return `Blocked` with the missing field and why instead of returning `Completed` with a non-working node. Use project-structure write tools only through this externally controlled step; do not mutate product files.

## Contract
- Inputs: .NET run command manifest and current process run project-structure node.
- Outputs: Runtime-capable Run app and Run tests nodes under the process run node, plus a grouping node only when needed for organization.
- Evidence: Project-structure write/read receipts, node ids, commands, launcher-compatibility receipts, and unresolved blockers written to `steps/run-command-node-receipts.md`.
- Operation target scope: `ExternalActionControlled`
