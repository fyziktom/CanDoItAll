# Run QA validation and runtime or browser proof

Execute targeted regression, runtime/API/browser proof as applicable, and defect triage against the reviewed implementation package. When project structure, scope, or implementation evidence identifies a visible browser workflow, capture current-run process-visible browser artifacts under `artifacts/process-runs/<run-id>/browser/` before selecting quality-accepted.

For every screenshot used to accept or reject a visual claim, call `workspace_analyze_image` and cite the current execution run, provider, model, token counts, and tool receipt path or id. For before/after comparisons, animated behavior, queued work, background loading, polling, timers, streaming, or any claim that visible state changes over time, capture ordered screenshots over elapsed time and call `workspace_analyze_images`. If image analysis is unavailable but current browser snapshot/evaluate output, console evidence, screenshot inspection, and validation receipts are enough to identify a repairable defect or proof gap, return status `Completed` with branchOutcomeKey `repair-required`. Return `Blocked` only for a confirmed tool, policy, environment, access, or process-contract failure that prevents QA from collecting enough evidence to choose `quality-accepted` or `repair-required`; cite the failed tool, provider/model, and receipt or missing capability.

## Contract
- Inputs: Peer-reviewed change set, changed-surface inventory, and release-scope assumptions.
- Outputs: Targeted QA result with runtime/API/browser evidence as applicable, regressions, warning and executed-test counts, shipped entrypoint/runtime consistency, residual quality risk, and an explicit accepted or repair-required branch. Browser-workflow quality acceptance requires process-visible screenshot, current-run `workspace_analyze_image` or `workspace_analyze_images` receipt for visual claims, browser_snapshot or browser_evaluate state output, browser_console_messages output, actual URL or entrypoint, launch and cleanup receipts, and acceptance-state assertion.
- Evidence: Regression logs, warning-free validation output unless explicitly accepted, nonzero executed-test proof when tests are expected, shipped entrypoint plus referenced-runtime inspection, stale or unreferenced artifact assessment, runtime/API/browser proof as applicable, screenshots for UI surfaces, provider-backed image-analysis receipts for visual conclusions, defect notes, and current-run process-visible browser artifacts when a visible browser workflow is in scope.
- Operation target scope: `ExternalProductTargetReadOnly`
- Outcome rule: Return a completed process-step outcome with branchOutcomeKey `quality-accepted` or `repair-required` for evaluated QA dispositions. Do not combine status `Blocked` with branchOutcomeKey `repair-required`.
