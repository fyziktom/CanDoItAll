# Normalized Requirements

| Requirement ID | Requirement | Proof |
| --- | --- | --- |
| `RQ-01` | Extend the shared `CanvasWorkbenchAction` contract so menu actions can expose a single-key accelerator that the runtime can consume and the UI can render. | Component tests covering action metadata and any assignment helper. |
| `RQ-02` | Preserve the architect-specified shortcut letters for the named top-level groups and named nested items, then assign deterministic collision-free shortcuts to the rest of the currently visible project-structure menu siblings. | Catalog and adapter tests that verify fixed mappings plus collision-free sibling sets. |
| `RQ-03` | When the right-click menu is open, pressing a matching key must either open the matching submenu or execute the matching leaf in the current menu layer, and that behavior must continue through second-layer and third-layer menus. | Playwright flow that opens the menu, drills through nested layers by keyboard, and asserts the expected action path. |
| `RQ-04` | Menu labels that show text must visually call out the active shortcut letter and expose accessible labeling that reflects the shortcut. | Browser screenshots plus component or DOM assertions around rendered shortcut markup. |
| `RQ-05` | Existing global canvas shortcuts and editable-field behavior must remain intact; shortcut routing must not steal keyboard input from text entry or unrelated canvas commands. | Focused automated tests plus browser regression smoke for `Escape`, help, zoom, and editable controls. |
| `RQ-06` | The help modal must become a browsable documentation surface with a dedicated menu-shortcuts page or equivalent section that explains the new keyboard interaction model and still retains the existing global shortcut documentation. | bUnit assertions for help-modal structure and Playwright screenshots of the open help pages. |
| `RQ-07` | Address the maintainability concern by extracting shortcut-heavy runtime logic out of the current `03-interaction-and-state.js` monolith where practical, keeping load order and shared exports stable. | Code review of the resulting file boundaries plus build and browser confirmation that the route still loads correctly. |
| `RQ-08` | Record component, Playwright, screenshot, and bundle-validator proof before closure and map each raw note to `Solved`, `Partially solved`, or `Not solved`. | Updated execution report, validator output, and final raw-note closure table. |
