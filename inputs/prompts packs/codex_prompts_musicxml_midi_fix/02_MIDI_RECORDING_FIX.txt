Task 2: Fix MIDI recording accuracy (stop time, note lengths, sequential vs chord starts)

Current flow
- NotationEditorPlayground.razor:
  - StartMidiRecordingAsync creates MidiRecordingSession
  - HandleMidiMessageReceived forwards parsed MIDI to recordingSession.Capture(...)
  - StopMidiRecordingAsync calls session.Complete(stopTimestampMs: null, flushActive: true)
  - Performed notes are quantized and mapped via MidiRecordingNotationMapper.MapToNoteEvents(...)

Problems to fix
1) Wrong note lengths at stop:
   - MidiRecordingSession.Complete(stopTimestampMs: null, flushActive: true) uses lastTimestampMs for flushing.
   - If the last note is still held (or sustain pedal is down), the note end time becomes the last MIDI message timestamp (often the NoteOn),
     producing a near-zero duration and then getting clamped to MinimumDuration.
2) Sequential notes sometimes collapse into a chord after quantization:
   - When tempo and rounding differ, multiple starts can quantize to the same grid point.
   - We need a chord threshold window and monotonic start enforcement per onset-group.

Implementation steps

1) Provide a stop timestamp in the correct time base (performance.now)
- Add a small JS export in MusicNotation.Editor/wwwroot/midiInterop.js:
  - export function nowMs() { return performance.now(); }
- In MusicNotation.Editor/Services/IMidiService.cs:
  - Add Task<double> GetNowMsAsync();
- In MusicNotation.Editor/Services/MidiService.cs:
  - Implement GetNowMsAsync() by invoking jsModule.InvokeAsync<double>("nowMs")
  - If not initialized/supported, return 0 (but recording should already guard on support)
- In App.Blazor/Pages/NotationEditorPlayground.razor:
  - In StopMidiRecordingAsync():
    - var stopNowMs = await MidiService.GetNowMsAsync();
    - session.Complete(stopTimestampMs: stopNowMs, flushActive: true)
  - Keep flushActive = true

2) Improve quantization so sequential notes do not become chords accidentally
- Extend MusicTheory.Core/NotationEditor/Recording/MidiRecordingQuantizationOptions.cs:
  - Add int ChordWindowMs = 40 (default)
  - Add bool EnforceMonotonicStarts = true (default)
  - Add bool QuantizeEnd = true (default) OR implement “quantize end” implicitly when computing duration
- Update MidiRecordingNotationMapper.MapToNoteEvents:
  - Sort performed notes by StartMs
  - Group notes into onset groups:
    - Notes are in the same onset group if (note.StartMs - groupStartMs) <= ChordWindowMs
    - This group represents a “played chord”
  - For each group:
    - Compute quantizedStartWhole using QuantizeStart step
    - If EnforceMonotonicStarts:
      - Ensure groupStart >= previousGroupStart
      - If groupStart <= previousGroupStart, set groupStart = previousGroupStart + startStep
    - For each note in the group:
      - Compute quantizedEndWhole:
        - Option A (recommended): quantize end time directly using QuantizeDuration step:
          - endWhole = MsToWhole(note.EndMs)
          - quantizedEnd = Quantize(endWhole, durationStep)
        - duration = max(minDuration, quantizedEnd - quantizedStart)
      - This reduces drift versus quantizing only the duration delta.
- Keep existing tie segmentation logic (SplitIntoTieSegments) but feed it the improved (start, duration).

3) Add tests
- Add tests for MidiRecordingSession:
  - Complete_WithStopTimestamp_FlushesActiveNotesToStopTime()
    - Simulate NoteOn at t=1000, no NoteOff, then Complete(stop=1500, flushActive=true)
    - Expect performed note EndMs-StartMs >= 500
- Add tests for MidiRecordingNotationMapper:
  - SequentialNotesOutsideChordWindow_DoNotShareSameStart()
  - NotesInsideChordWindow_ShareSameStart()
  - QuantizeEnd_ReducesDurationError_ForLongNotes() (optional but useful)
- Tests must validate:
  - placement.Note.Duration == NoteValueMath.ToDuration(placement.Note.BaseDuration, placement.Note.DotCount) for representable durations
  - Absolute start order is strictly increasing for sequential notes

4) Update docs
- Update docs/midi-recording-to-musicxml.md:
  - Mention stop timestamp fix
  - Mention chord window and monotonic starts
  - Mention quantize end vs quantize duration

Acceptance criteria
- If the user holds the last note and presses Stop, the recorded last note duration matches the time held (within quantization tolerance), not MinimumDuration.
- When recording a simple scale, notes appear sequentially, not collapsed into a single chord.
- Existing recording tests still pass (and new tests pass).
