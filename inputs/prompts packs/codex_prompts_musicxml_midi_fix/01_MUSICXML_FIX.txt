Task 1: Fix MusicXML import/export (MusicXmlSubsetService) to support standard MusicXML durations and common real-world files

Primary target files
- Typical MusicXML partwise exports from notation software
- Files that include a DOCTYPE (DTD)
- Files that use divisions like 480 (common) and include <backup>/<forward>

Key problems in current code (must be addressed)
- Import uses XDocument.Parse(xml) which may throw on DOCTYPE/DTD. Fix this by loading with XmlReaderSettings:
  - DtdProcessing = Ignore (or Parse without external resolution)
  - XmlResolver = null
- Import currently assumes DivisionsPerWhole = 16 and ignores <attributes><divisions>.
  - This is non-standard and breaks third-party MusicXML. Switch to MusicXML standard: divisions are per quarter note.
  - Export should also use the standard meaning.
- Import currently uses per-staff cursors and treats <backup> as “switch to staff 2”.
  - Replace with a proper “global cursor within the measure” that is moved by <forward>/<backup> durations.
  - Keep chord note handling (<chord/>) via lastStartByStaffVoice map.

Implementation steps

1) Safe XML loading (DTD + namespaces)
- In MusicXmlSubsetService.Import:
  - Replace XDocument.Parse(xml) with XDocument.Load(XmlReader, LoadOptions.None)
  - Use XmlReaderSettings with DtdProcessing.Ignore and XmlResolver = null
- Make element lookup namespace-agnostic:
  - Do not use Element("measure") directly; many MusicXML files can include namespaces.
  - Implement small helpers:
    - ElementsByLocalName(XElement parent, string localName)
    - ElementByLocalName(XElement parent, string localName)
    - DescendantsByLocalName(...)
  - All searches for "part", "measure", "note", "pitch", "duration", "attributes", "divisions", "time", "beats", "beat-type", "backup", "forward", "staff", "voice", "harmony" should match by Name.LocalName.

2) Standard divisions semantics (per quarter note)
- Read divisionsPerQuarter from the first measure’s <attributes><divisions>.
  - If missing, default to 16.
- Define:
  - divisionsPerWhole = divisionsPerQuarter * 4
- Convert duration divisions to internal Rational (whole-note basis):
  - Rational duration = new Rational(durationDivisions, divisionsPerWhole)
- Convert internal Rational to MusicXML duration divisions:
  - int durationDivisions = (duration.Numerator * divisionsPerWhole) / duration.Denominator when divisible
  - otherwise round safely (AwayFromZero) but also consider quantizing/normalizing durations if the editor can’t represent tuplets.

3) Legacy compatibility (files previously exported by this app)
- Old exports used a non-standard model where divisions were “per whole note”.
- Add an import heuristic so legacy files still load:
  - If <divisions> exists and <time> exists, compute:
    - expectedMeasureDivisionsSpec = divisionsPerQuarter * beats * (4 / beatType)
    - expectedMeasureDivisionsLegacy = divisionsValue * capacityWholeNotes
  - Inspect duration values inside the first measure (or backup duration if present).
  - Choose mode:
    - Spec mode (per quarter) when values look like 16/32/64/480 etc and measure totals fit expectedMeasureDivisionsSpec
    - Legacy mode (per whole) when values look like 1/2/4/8/16 and measure totals fit legacy expectation
- Implement this as a private enum MusicXmlDivisionsMode { StandardPerQuarter, LegacyPerWhole } and store the resolved mode for the import run.

4) Correct measure parsing with forward/backup
- For each measure:
  - Use int cursor = 0
  - For each child element in order:
    - If localName == "note": parse it
      - startDivisions:
        - if <chord/> exists => lastStartByStaffVoice[(staff,voice)]
        - else => cursor
      - durationDivisions from <duration>
      - Create NoteEvent or RestEvent with:
        - Start = Rational(startDivisions, divisionsPerWhole)
        - Duration = Rational(durationDivisions, divisionsPerWhole)
      - If not chord: cursor += durationDivisions
      - Set BaseDuration/DotCount from Duration (if representable), else choose closest and keep Duration exact
      - Parse ties from <notations><tied type="start|stop"/> and set TieStart/TieStop
    - If localName == "forward": cursor += forwardDuration
    - If localName == "backup": cursor = Math.Max(0, cursor - backupDuration)
    - If localName == "harmony": keep existing behavior (mainText/subText)
  - At the end: ScoreMeasure.Events contains all events as imported.

5) Prevent layout crashes on import
- After building ScoreDocument:
  - Reindex measures
  - Run ReflowEngine.NormalizeFrom(score, 0) to split overflow across measures and add ties
  - Run AutoRestFillEngine.RecomputeAll(score) if AutoRestFillEnabled
- This ensures no event has Start >= measure capacity after normalization.

6) Export updates (standard-compliant output)
- Export should emit:
  - <divisions> = 16 (per quarter note) by default
  - Duration numbers consistent with the standard meaning (quarter note duration = 16 when divisions=16)
- Keep:
  - Partwise structure
  - Harmony per measure (if present)
  - Two staves export for ScoreStaffMode.Grand
  - Consider exporting one staff if score.StaffMode is TrebleOnly/BassOnly (optional but recommended)
- Ensure roundtrip:
  - Export(score) -> Import(xml) produces a non-empty score and preserves chord symbols at least

Acceptance criteria
- Import can parse MusicXML containing DOCTYPE without throwing
- Import correctly maps duration values for divisions-per-quarter files (e.g., divisions=480)
- Import no longer assumes staff=2 on <backup>; it uses forward/backup cursor semantics
- Exported MusicXML opens in third-party tools with correct note lengths
- Legacy exports can still be imported successfully
