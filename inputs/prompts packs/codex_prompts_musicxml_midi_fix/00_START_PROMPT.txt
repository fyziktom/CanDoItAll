Reported failures to fix
1) MusicXML import fails or loads wrong:
   - Many third-party MusicXML files include a DOCTYPE (DTD). XDocument.Parse often throws when DTD processing is prohibited.
   - Current importer ignores <divisions> and assumes a legacy non-standard divisions model, which breaks durations (notes become far too long/short).
   - Current importer is fragile for namespaces and for backup/forward semantics.

2) MIDI recording is inaccurate:
   - Stopping recording finalizes active notes using the timestamp of the last MIDI message, not the actual stop time.
     This truncates the last held note(s) and sustain-pedal notes.
   - Start/duration quantization can collapse sequential notes into the same start (appears as a chord) when tempo/rounding differs.
   - Users need correct note start ordering and more reliable note lengths.
