# Operating model and reality alignment

A process-management system that only draws diagrams will fail in a larger organization.  
This module therefore needs to carry operating-model semantics from the beginning.

## Required operating-model concepts

- process owner
- sponsor
- steward
- primary customer
- value statement
- criticality tier
- strategy link
- upstream and downstream interface contracts
- decision-right rules
- risk-tiered controls
- change acknowledgement and process literacy aids
- conformance observations
- deviation clusters

## Additional orchestration concept from this pass

The process is not only a document of how work *should* move.  
It is also the canonical model of how responsibility is supposed to move between humans and future AI executors.

That is why the bundle now adds:

- process-native work briefs
- baton handoff artifacts
- governed triage decisions
- runtime overlay visibility on the same process canvas

## Reality alignment rule

The module should make it easier to compare:

- modeled path
- executed path
- observed real-world path

without collapsing them into one uncontrolled note system.
