# Normalized requirements

## Canonical model requirements

1. Node stays the universal carrier.
2. Node identity stays stable across note -> richer-block evolution.
3. Node X/Y coordinates remain canonical semantics.
4. Node markers remain canonical semantics.
5. The carrier must become lean and stable; cross-module and plugin-specific payload must move into typed facets/bindings.
6. Workbench canonical storage must not persist read-only projections from other modules.
7. Editable hierarchy must have one canonical containment representation only.
8. Node-kind semantics, capability rules, editor schema, and allowed assignment roles must come from one central registry.
9. Reclassification must write history and facet supersession instead of silent in-place semantic replacement.
10. The connector/plugin platform must be manifest/descriptor-driven, not enum/switch-driven.
11. Repeated architectural blockers must be enforced by tests and hard-gate scripts, not only by review text.
