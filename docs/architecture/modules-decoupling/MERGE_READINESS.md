## What `160616c8` closed

The audit findings were repaired in their owners with regression proof in the same commit (40 files, +1586 / −92, signed with key `96E836FAA8854EE98ABC10903C206549E1D7EAD6`):

1. **Agent chat context scope lifetime** (`AgentFramework.Core`, Workbench, CrmHr, Projects, AgentFramework pages). Scope and publication leases report `IsActive`; a provider whose lease was superseded by a newer scope, or that is disposing, stands down instead of publishing or synchronizing navigation; an execution-completed notification is dispatched only when the lease that admitted it is still the active one at consumption; fire-and-forget reloads log their faults instead of dropping them. Deterministic bUnit proof admits the notification from a foreign thread while the renderer is busy (`ProjectStructureAgentChatContextProviderTests`, `CrmAgentChatContextProviderTests`, `FloatingAgentChatArchitectureTests`). This is the class of race behind the one timing-bound Components failure of the `stable-fix11` gate.
2. **Process pre-dispatch tool inventory versus executable authority** (Workbench). An inventory context composes the declared task and project tools as inert `ProjectStructureInventoryOnlyTool` wrappers that refuse invocation with `403 ProcessToolInventoryNotExecutable`; the inventory access state allows no project, not even `Guid.Empty`, and grants nothing; dispatch still composes its own tools from the saved execution, and a governed path without the inventory flag still fails closed (`409 ProcessExecutionReconciliationRequired`). Proof: `ProjectStructureAgentRuntimeToolProviderTests`, `ProjectStructureAgentRuntimeToolRoundTripIntegrationTests`.
3. **No-effect and denial semantics** (Workbench, `AgentFramework.Maf`). Rejected asset content is a typed `ProjectAssetContentValidationException` mapped to `ProjectAssetContentInvalid` (400, effect `None`) instead of a framework exception; a saved pre-dispatch denial is restored on replay only when its journal outcome is `NotCommitted`, and a tampered checkpoint is refused without consulting the owner or dispatching; effect evidence distinguishes the same target reached by different tools and path spelling variants; the completion contract stays truthful for the eight audited scenarios (`AgentToolFailureEffectEvidenceTests`, `ToolOutcomeCompletionIntegrationTests`, `MafPolicyDenialCheckpointTests`, `ProjectAssetStorageServiceTests`).
4. **Plan truth and costing** (Workbench). One helper, `ProjectTaskExecutionStatePolicy.ResolveExecutionBackedProgress`, is used by the plan summary, the manager forecast and the Gantt task metrics; a recorded `NotStarted` or `Started` state beats the status text and the canvas hint, `Cancelled` is excluded from the progress aggregates, and a zero quote stays distinguishable from a missing one. The person quote summary no longer discloses the hourly rate to the agent (`ProjectPlanSummaryCalculatorTests`, `ProjectStructureGanttProjectionAdapterTests`, `ProjectStructureTaskResourceCostServiceTests`).
5. **Gantt Mermaid export contract** (Workbench). The export is a schedule snapshot: a task line carries the projected UTC start and duration, and is written as `after <ids>` only when the projection synthesized the whole interval, every predecessor precedes it in row order and its start equals the latest predecessor end. The exporter now uses its own filtered predecessor set; multi-predecessor (`after task1 task2`) and pinned-successor cases are covered.
6. **Composition hardening** (Projects, Workbench, CrmHr, AgentFramework). Projects registers its no-op bridge defaults with `TryAddScoped`; the owners install their implementations with `services.Replace`; `OwnerBridgeRegistrationOrderTests` proves the real bridges win in every registration order; `DatabaseCanonicalityArchitectureTests` also refuses any product-module use of the global `AppDbContext` factory.
7. **Documentation.** `docs/architecture/agent-tool-failure-recovery-boundary.md` gained the denial-consistency, typed asset validation, tool inventory and context lifetime sections; `docs/architecture/modules.md` gained the owner contracts and adapters section; one reviewed portability baseline fingerprint was refreshed for the restructured case-policy line.
