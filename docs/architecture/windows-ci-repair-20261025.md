# Windows CI repair after concurrent mutations merge

Status: implementation and validation in progress. Base: `3fa52d707`; repair branch: **codex/windows-ci-repair**.

The supplied CI archive reports failures in unit, component and integration contracts. The merge added original-intent lifecycle commands, owner completion evidence, planning review APIs and schema migrations. Several older fixtures still call the deliberately disabled lifecycle entry points or insert today's entity shape into a historical schema. The repairs retain the legacy rejection tests and use captured, typed submissions for normal setup.

## Implementation boundaries

- Keep lifecycle test setup in the test-support project. Never reopen legacy mutation routes or turn conflicts into success.
- Seed historical schemas with their historical columns. Test upgrade behavior with the current model only after the relevant migration.
- Document public request, response, revision and recovery semantics through the existing typed OpenAPI transformers; preserve documentation enforcement.
- Fix the regular sandbox reservation race at prepublication admission: after another worker publishes the same source, return that source's saved reservation. Re-throw unrelated conflicts and never replay effects.
- Validate required prepared-launch payload members before hashing saved evidence, so malformed historical rows produce an explicit evidence failure instead of a null-reference exception.
- Update UI fixtures to use an interactive renderer and the actual disclosure controls. Preserve pending-operation recovery assertions.

Keep the single physical deletion and empty pending-cleanup assertions in both cases.
- Select the measured definition family in the capacity-test observer while allowing the other registered pools and lifecycle family to run. Keep family eligibility separate from aggregate pool eligibility, and retain explicit failure for malformed identities and incomplete observations. Observe connections from the extracted finite-operation context as well as Projects so terminal backend-exit evidence remains mandatory. Add a short real-child regression before the sustained workload, with bounded type/method diagnostics on child failure.
- Bound pressure observations by their phase and configured cadence. The old shared eight-minute deadline expired after one of two 60-second workers recovered: warning thresholds require a later cycle when timestamps fall just short of two minutes, complete metric frames arrive at the next cycle, and competing workers can need separate empty cycles.
