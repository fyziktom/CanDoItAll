# Process template improvement review

## Software delivery
The release approval lane now explicitly depends on peer review, QA validation, and security review and consumes three artifact inputs.

## Branching code review
A dedicated review-routing template now exists and models explicit review disposition branching, default normalization, and error handling.

## Hotfix rollout
Emergency release approval now consumes explicit blast-radius and validation inputs and remains a separate governed lane rather than a compressed normal release.

## Onboarding and incident response
The baseline forms remain intentionally compact where the current repository uses compact scenarios, but role descriptions, sidecars, prompts, validations, and artifacts were made more detailed and execution-grade.
