# Assumptions And Risks

## Assumptions

- "All forms" means all editable value-entry surfaces reachable in the shipped `CanDoItAll.Web` app plus shared/sandbox form components used to validate the component library. Low-level canvas inline editors and Space3D sandbox-only controls are inventoried, but product module forms take priority for implementation.
- It is acceptable to use representative route screenshots for repeated component patterns when a shared component change affects many forms, as long as the `.xlsx` checklist still lists the source files and marks unchanged or indirectly covered surfaces explicitly.
- Image proposals are low-fidelity layout direction artifacts. They must not be mistaken for exact pixel specs.

## Critical Path Risks

- Shared CSS changes can improve many forms but also affect dense toolbars, floating inspectors, and dialogs. Browser proof must cover both a normal page form and at least one constrained modal/floating form.
- Adding tabs to every dense form could increase interaction cost. Use subtabs only where the current editor has too many semantically different fields to scan in one section.
- Arbitrary Tailwind utility additions inside module Razor may not be generated by the BaseLib Tailwind source pipeline. Prefer existing shared classes or module `.razor.css` when adding layout CSS.

## Validation Risks

- Some forms require seeded data or specific UI actions to appear. If a route cannot expose a form in the current database state, capture the closest available editor state and record the gap in the workbook.
- Browser screenshots must crop or clip to form regions. Whole-page screenshots alone are not sufficient for closure.
- The app may need a local database or runtime services. If a route fails due to environment setup, record it as a blocker and validate reachable forms instead of pretending full coverage exists.

## Reopen Triggers

- Any validation screenshot still shows a textarea smaller than the expected content category.
- Any form region wastes major horizontal space while adjacent content is empty or scrolls unnecessarily.
- A targeted form adds one-off CSS where a shared component parameter or shared class would have solved the same pattern.
- A proposal/checklist row is missing for an implemented visual change.
