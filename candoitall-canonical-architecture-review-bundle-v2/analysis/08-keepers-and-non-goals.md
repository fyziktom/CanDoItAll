
# Keepers and non-goals

## Keepers

These are strengths and should be preserved:

- **mindmap-first authoring**
- **stable node identity for workbench-authored thinking**
- **simple-note brainstorming**
- **future promotion of ideas into richer typed work**
- **semantically meaningful X/Y and marker signals**
- **module-native canonical aggregates where they already make sense**
- **party directory / AI-agent identity as a reusable capability**
- **assembled graph as a projection boundary**

## Non-goals for this stabilization wave

These are explicitly **not** the target:

- turning node into a mere view shell
- a big-bang migration of every module into one mega-table
- destructive delete/recreate as the default note→task/decision evolution model
- keeping party truth duplicated in metadata and assignment rows “just for convenience”
- deducing canonical dependency truth from XY placement alone
- forcing all module-local responsibility fields into one owner before an ownership matrix exists
- rebuilding unrelated runtime/watch/storage tooling during the same wave

## Future derived layers that must stay derived

These can be built later, but must remain derived above the canonical model:

- LLM/knowledge-compiler proposals
- node embeddings / semantic vectors
- cross-project pattern mining
- AI summaries and heuristic recommendations
- similarity retrieval over past project structures

The canonical model must stay simpler and more explicit than any future semantic layer built on top of it.
